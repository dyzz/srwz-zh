# 剧情内心独白的姓名漏色：v0.4.2 修复

2026-10-09。bgcnh 反馈：v0.42 的剧情姓名大部分已恢复蓝色，但每话仍零星出现未调色的姓名。用户转述该反馈并要求全量排查，没有指定角色或台词。

**已确认静态根因：括号独白的实际中文编码是 `8F E8`，姓名样式判定却仍比较原生日文编码 `81 69`。** Original、Best 冻结 v0.4.2 均有 2,361 条记录受影响，分布在 151 个 STAGE 数据块。数据块数量不等于玩家章节数量；该统计包含不同路线及事件副本，不能称为 2,361 句互不重复的台词。

正式修复已同步生产工具、常量合同及测试：Original、Best 将括号判定改为生产编码器实际输出的 `8F E8`；SP 当前产物已是正确值，新增显式应用及独立回读检查。语料不需要改写。既有 V030-047 对普通弯引号的修复仍有效；本项补齐其未覆盖的括号独白。

## 原因

普通对白与 Back Log 共用 `0x220E70` 的姓名样式判定（Original 地址）。该函数通过 `0x221030(text, 1)` 取姓名换行后的正文行，再比较其头两个字节。旧修复只把 `「` 的判定常量由 `81 75` 换成 `“` 的 `91 41`，并刻意保留 `（` 的日文原码 `81 69`。

然而，汉化字库／写入器把可见 `（` 编码为 `8F E8`。两个字节与被保留的常量不同，判定返回 0，不能选择专用姓名样式。Unicode 文本看起来都是 `（`，不能证明运行字节相同。

| 项目 | Original | Best |
| --- | --- | --- |
| 可执行文件 | `SLPS_258.87` | `SLPS_732.70` |
| 16 字节判定常量块文件偏移 | `0x33E258` | `0x33EA48` |
| 冻结版常量块 | `91410000000000008169000000000000` | 同左 |
| 待修正括号常量文件偏移 | `0x33E260` | `0x33EA50` |
| 括号独白正文实际开头 | `8FE8` | `8FE8` |

例如 `story/001/dialogue/02.01/0047`，说话人为卡克利孔，正文为：

> （这个男人就是丹泽尔·哈默上尉……
> 　《荣耀之星》的队长吗……）

原盘姓名换行后的前缀为 `81 69`，冻结汉化成品为 `8F E8`。节子的“（第一次实战……）”、卡缪和丹泽尔的内心独白也在同一漏识别集合中。

## 冻结成品检查

从保留的父子 CHD 提取两版默认、不带 skip 的 v0.4.2 ISO，并核对整盘 SHA-256，结果与发布记录一致：

- Original：`6a72307c36ec6b2f7f0af9e6f31d1a88cdb092af7d1b64377341c2e4b7e0e50c`
- Best：`081b4ce998b9c71ba17f84f5e410e6bfa0b99b9d4582711f2d72d60defa6cc1a`

分别使用对应日文原盘、原生 HB 偏移表和 STAGE 基址解压并解析。Original 基址为 `0x7566F0`，Best 为 `0x756EF0`，没有套用另一版本地址。检查实际 NUL 结尾字节串，按上述函数的第二行／两个字节规则统计：

| 日文原盘识别 | 汉化冻结版识别 | Original 条数 | Best 条数 |
| --- | --- | ---: | ---: |
| 是 | 是 | 77,427 | 77,427 |
| 是 | 否 | **2,361** | **2,361** |
| 否 | 否 | 3,880 | 3,880 |
| 否 | 是 | 0 | 0 |
| 合计 | | 83,668 | 83,668 |

全部 2,361 条差异均为正文以 `8F E8` 开头，且姓名非空；其余 3,880 条是没有姓名的场所／系统卡片等，不应强行着色。范围统计是静态字节模型，不能冒充全路线逐帧运行验收。

可复查的汇总、逐数据块数量和样例见 [静态收据](issue-assets/speaker-color-20261009/static-receipt.json)。完整逐条原始字节清单保留在被忽略的 `work/*-speaker-audit.json`。复跑脚本见 [audit_v042_speaker_colors.py](issue-assets/speaker-color-20261009/audit_v042_speaker_colors.py)，脚本只读输入镜像，结果写入 `work/`。

## 测试缺口与后续修复边界

### 括号调整的历史核对

用户提出可能与此前改用原版括号字符的调整有关。提交核对确认：2026-09-02 的姓名颜色修复 `ecd0a01` 已保留 `81 69` 判定，而当时字库分配就同时存在主码 `8169` 和剧情使用的安全别名 `8FE8`。2026-09-17 的 v0.4.2 冻结成品也已存在本缺陷。

2026-09-28 恢复原版全角括号字形的 `145c3e1` 只修改 `config/fonts/zh-release-font.json`，没有改变上述主码／安全别名分配。因此本项应记录为 9 月 2 日姓名颜色修复未覆盖安全别名的旧漏项，不能归因为 9 月 28 日字形恢复新引入的回归。原版字形与原版编码应分别核对；使用原版外观不意味着剧情字节已回到 `81 69`。

修复前，既有 `test_dialogue_speaker_colors.py` 的 3 项测试仍全部通过。这只能证明旧补丁符合自己的两字节合同。它把“日文括号常量原样保留”作为成功条件，只检查语料的 Unicode 开头，没有将生产编码器输出与判定常量做比对，因而没有检出这 2,361 条。

正式修复在 Original 的原有补丁中同步两类前缀，并沿 Best 自身的已审计地址映射迁移；SP 使用自身文件偏移 `0x3B0ED8`。补丁只接受原生、旧引号单项修复、完整修复三种已知前像；仅允许两个前缀的四个字节位置发生变化，重复应用不改变产物。三版构建及最终 ISO 回读都将完整 16 字节常量块与各自生产编码器输出比较，编码分配漂移时拒绝构建。

本轮未改写历史 V030-047 记录，不把旧样本验收扩展为所有剧情均已着色；PCSX2／人工验收尚未进行。
