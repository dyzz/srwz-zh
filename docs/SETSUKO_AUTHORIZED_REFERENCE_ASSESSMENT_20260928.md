绑定方法中，4,796 条带日文匹配分数；其余 23,468 条为中文兜底、对话框顺序匹配或战斗匹配。日文匹配分数并不等于人工核实；中文相似度高也不等于语义正确，而且会偏向选中两边措辞相近的句子。

覆盖边界：

- 本目录截止第 57 话；第 58–60 话没有对应文件，需要以日文和现译精读。
- 视频走太平洋、直布罗陀及隐藏路线，另一支与其他结局需要单列。第 27 话资料只选中 stage-052，另一 stage 也不能自动算已审。
- 共通章节和公共段仍属于节子线游玩文本；旧规划只列节子专属段，范围偏窄。
- 实况未触发的战前对话、击破顺序、说得、条件分支与缺失字幕必须从游戏全量清单补入。没有 UP 对应不等于无需精读。
- 无说话人的开场旁白可能与解说混在 `note` 中，应重新识别；不能简单丢弃全部 note 后宣布完整覆盖。

## 4. 推荐流程

### 先整理参照和待审队列

1. 当前语料按稳定 ID 读取，绑定 `source_text_sha256`、当前译文哈希、当前 HEAD，以及涉及文件哈希。后续出现源文或现译变化时重新审查该条。
2. 以 `epNN.json` 为证据入口，保留集数、分集、时间段、视频链接、原始 OCR、说话人、轨道、绑定方法及分数。`by-line-id.json` 适合查找，但缺少这些配对字段，不能独立驱动写回。
3. 将既有 `misaligned` 线索通过旧 cue 的分集、时间、文字回连到新记录，标成待重配。新整理稿有去重和合并，不能仅凭 cue 数字或文本相似度回连。
4. 分别记录“配对核实状态”“OCR 核实状态”“译文审定状态”。建议人工修正覆盖层保存原始文本及修正依据，避免重新生成时丢失核查。
5. 解说、攻略和译者吐槽单列，尤其检查混入 `dialog` 正文的括号尾注。轨道名称不能代替人工判断。

### 按场景精读，按影响排序

- 每次取一个完整场景，通常 50–150 句；保留前后文、人物、触发条件。视频顺序用于证据定位，游戏事件顺序用于阅读；互斥分支不能被拼成连续对话。
- 第一遍专查肯否、时态、主客体、条件关系、指代、漏译和增译。参照差异大或未配对的句子也要读，不按中文相似度过滤掉。
- 第二遍处理角色口吻与主题呼应：节子的敬语与成长、托比和丹泽尔的军人口吻、阿萨基姆的嘲讽、雷本前后阶段的表里差异。主题句建立跨话索引，按具体语境保持呼应，不机械套同一个中文词。
- 最后集中排版。把 381 条纯格式候选从实质改译中分开，降低用户确认负担；不设固定“必须改几成”的目标。
- 每条候选同时展示日文、现译、UP 原始 OCR、整理后的参照、建议及理由；明确“吸收 UP”“日文独立修正”“保留现译”“配对待核”四种情况。跨句玩笑、宣言或铺垫成组显示。
- 初审 accept 只表示初审意见，不能当用户确认。沿用已有第 7、32 话本地确认与写回机制；已确认句的修改应明确列出旧决定及新证据。

### 推进顺序

1. **准备批**：修正旧术语说明，整理错配线索、去重同一 ID，补齐 11 条初判缺口，重新检查最终建议的格式。
2. **开场批**：用第 1 话现有候选跑通端到端流程，再推进第 2–6、8–9 话；第 7 话作为既有定稿基准。此批重点确立荣耀之星三人的口吻。
3. **主线人物批**：第 21、31、47 话优先，连同第 9 话与第 32 话已有定稿做跨话呼应检查。第 47 话影响主题的语义错误可以先形成独立修正批。
4. **其余已覆盖章节**：顺剧情推进第 10–30、33–46、48–57 话，包含共通章节，跳过前面已完成内容；战斗台词按人物与触发情境独立整理。
5. **补全批**：未走分支、公共段、缺失字幕，以及第 58–60 话；读完全量游戏条目后才报告路线精读完成。

不把旧规划的“700–800 条”当目标或工期依据。现在的候选范围更大，包含共通章节、战斗及大量排版记录，统计口径不同。

### 写回与验收

- 写回前检查日文哈希、现译冲突、当前术语、变量与控制符、实际显示宽度、引号和换行。剧情与战斗换行存储形式分别处理，保留可见拉丁字母和标识。
- 同源联动沿用现有工具的源文、说话人、主人公与相邻场景判断；不能仅凭日文哈希全局替换，同源已有不同定稿时列冲突。
- 语义修正、人物润色、纯排版分开留回执与提交；构建使用项目当时有效的版本配置，并检查槽位容量和实际回读。
