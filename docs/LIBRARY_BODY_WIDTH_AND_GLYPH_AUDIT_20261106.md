# 图鉴中文字号与正文行宽核查（2026-11-06）

> 排版策略后续已与梗概、滚动字幕合并为同一 `prose_policy`，并增加原有合法行数/固定滚动字段数的保护。最新全量结果见 [三类长文统一核查](UNIFIED_PROSE_LAYOUT_AUDIT_20261106.md)。下文保留该次独立图鉴候选的历史证据。

> 后续根因已进一步确认：GS 帧缓冲中的底横连续，ARMSX2 原生 1× 的 Automatic/FastMAD 显示重建才产生断口；同 ISO、同尺寸切到 Weave 后连续，切回 Automatic 再次复现。此前“最终绘制采样阶段”的描述范围过宽，现明确收敛至去交错重建路径。见 [根因报告](SNOW_STROKE_ROOT_CAUSE_20261106.md)。

> 补充：同字号和同字库不等于最终笔画完整。随后“雪”字检查确认，ARMSX2 SW 1×、Metal 1×的底横出现断笔，而 Metal 4×完整。三种模式的源字格、RAM 图集、GS PSMT4HL 图集逐像素一致，缺口发生在最终绘制采样阶段。本页此前的字体一致性结论只证明源字形/字号未混用，不能排除这种显示问题。见 [对照证据](issue-assets/snow-stroke-20261106/verification.json) 和 [放大对比](issue-assets/snow-stroke-20261106/comparison.png)。本问题尚未修改原生绘制代码或字体修复。

用户反馈新版莉露图鉴部分中文看起来更大，同时同页的行宽不一致。

## 中文字号

使用当前 `build/iso/special-disc/sp-current.iso`，通过 ARMSX2 runner SW 冷启动并自然进入莉露图鉴。逐字追踪显示，首屏 125 个中文字形记录均为宽 21、高 12；没有因 G、Geo、14 的控制符而把部分中文改成另一种字号。

从该 ISO 解出当前字库，核对首屏出现的 96 个不同中文：全部与当前全局 HarmonyOS Sans SC Regular、22px em、统一 24×24 格及固定基线的标准栅格逐字节一致。没有混用另一套字体、漏换字形或单字字号配置。墨迹外框本身有差异，例如“格”的字格墨迹高 22px，“兰”高 20px。这种视觉差异仍存在，本轮没有为单个汉字做拉伸或改字号。

## 行宽修复

图鉴的共享 JS 场景仍使用 balanced_width；其余长文此前采用的非末行统一宽度策略没有应用到图鉴。因此即使都是中文，原先后几行仍会提前结束。

角色、机体、术语正文现在使用共同的非末行宽度目标，继续使用各自的原生宽、高、step 和最大面板宽。保留标点禁则及完整紧缩作用域，不保护词的拆分。最多允许比原生最大宽度最少行数增加一行，避免把整篇缩成很窄的长条。库内没有分段缩进的普通段落通过合法断点图选择最小行宽区间；已更均匀的旧布局保留为回退候选。末行不参与宽度一致性投票。

全量共享语料检查：1,550 个正文场景（角色 820、机体 626、术语 104），1,114 处非末行宽度差缩小，436 处持平，无变差、超宽或文字丢失。包含英数的行仍受 21px 中文、12px 紧缩推进、标点位置和作用域边界约束，不能承诺零余差。
