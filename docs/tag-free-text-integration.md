## 当前状态与边界

## 数据与排版

`config/text-layout/rendering-mode.json` 显式选择 proportional / compact。迁移后的翻译字段不存储 `<z></z>`；旧协议只保留兼容解析及独立测试。

`shared/text-layout/engine.mjs` 是构建端、浏览器预览、格式化、提交校验的共享排版实现。`proportional-metrics.mjs` 是与现有字库绑定的字形度量；`proportional-selection.mjs` 定义英文、数字、上下文空格和斜杠选择。整行测宽保留邻接关系，不能把分别测量的词块相加代替它。

- 对白：483 px，最多 3 行；战斗字幕：462 px，最多 2 行。续行缩进计入总宽，战斗字幕保留原行数约束。
- 梗概：480 px；主篇滚动：528 px，指定窄资源为 504 px；SP 滚动：575 px。
- 图鉴人物：336 px；机体：546 px；关键词：525 px。
- 滚动、梗概、图鉴保留段落和段尾。为了行宽更均匀而缩窄时，每条非段尾行必须仍在原生面板宽度减一个中文步长以内；不满足就使用原生最大宽度方案。这里是排版宽度选择，不是横向拉伸字形。
- 中文标点适度压缩留白，并遵守行首行尾禁则。拉丁标识符保护独立于中文词语保护，过长标识符才允许回退拆分。
- 地点字幕使用实际比例字宽计算居中缩进，零头通过原生间距控制表达，不再生成 `<z>`。

`tools/srwz/build_layout.py` 批量验证已存储正文，不在构建时默默改写普通对白。对白独立检查工具使用同一批量测宽，同时保留缩进、行数和词语跨行检查。资源拥有者继续负责编码、字节预算、时序、原文身份及读回。

## 游戏汇编

`tools/srwz/tag_free_integrated.py` 生成和安装三版本补丁；`proportional_hooks.py` 实现 EE 指令，`proportional_scene_dispatch.py` 在原生入口捕获文本边界并按字号选择场景度量。

每版 9 处 hook：绘制/测宽入口 2 处，绘制/测宽循环 2 处，普通/描边顶点底线修正 2 处，关键词下划线 3 处。有效代码和表为 Original/Best 各 6,036 字节、SP 5,804 字节；Original/Best 预留 10,496 字节，SP 预留 6,400 字节。使用核对过的非加载 ELF 元数据空间，不增长 ELF，不移动堆边界。每处原指令必须匹配才安装。

字母和数字采用各自底线参数；普通字形和描边同步修正。测宽与绘制共用选择规则，游戏原有测宽调用可获得新宽度。自动换行仍在共享 JS 中完成。主篇战斗武器列表的 20×9 与 SP 查看器的 16×9 分别选择对应度量；主篇保留两种尺寸。未知字号走原生路径；这不等于所有 UI 已获得新字号支持。

原生测宽入口只提供宽度，绘制入口按宽、高选择场景。因此同宽不同高的场景必须共享横向度量；新增回归逐项检查三版中这些场景的字母、数字、空格及标点 code/bearing/advance 一致。字体高度和底线参数仍可不同。

## 构建与读回

```sh
RUSTC_WRAPPER= /opt/homebrew/bin/python3 tools/build_editions.py --candidate --editions original,best,sp
```

输出为 `build/iso/test/integrated-{original,best,sp}.iso`；候选收据为各版 `manifests/editions/<edition>/candidate.json`。候选工作空间与生产分开。2026-11-08 用户批准生产接入后，默认构建已启用同一比例策略并更新各版 current；`--candidate` 仍可用于隔离测试。生产与候选均执行相同的汇编安装、逐字节核验和读回绑定。

`tools/srwz/typography_iso.py` 以已完成语义读回的镜像为输入，生成并安装 ELF，再独立重新生成预期补丁逐字节核对。补丁步骤要求成员记录、文件长度、ELF 外所有字节不变。`verify_editions.py` 把语义读回、事件字幕、最终汇编和输出镜像的哈希串起来；不同阶段的哈希不能互换。

## 审阅站

`srwz-community-web/scripts/sync_text_layout.py` 同步 ESM、字体度量、选择规则及 Python 适配器；`--check` 拒绝漂移。浏览器与独立格式化 CLI 共用 `formatReviewText`。Python CLI 只转发到该实现。预览保留原输入，格式化是显式操作；底线残差应用到预览字形位置。

## 性能核对（2026-11-08）

优化前的三版候选构建总耗时 886.959 秒；Original 组件 508.715 秒，其中图鉴 311.168 秒；SP 共享图鉴 313.937 秒，SP 完整文本构建与验证 841.644 秒。并行阶段不能直接相加。

CPU profile 显示排版搜索反复创建不需要的预览字形对象，并对普通汉字重复进行上下文斜杠匹配。优化只让内部候选行搜索跳过字形对象收集、减少稳定字符集的无效正规化和匹配；公开测宽仍返回完整字形数据，未知兼容字符保留既有处理。

最终版本在 1,226 个图鉴正文/场景组合上与优化前完整序列化输出逐字节一致（整体 SHA-256 `0b30532544ae37e8cd65a2009c2d80902a23fb9ca98a58f5a146e364ae51b209`），耗时从 297.941 秒降至 131.689 秒，约 2.26 倍。79,200 个混合字符上下文的度量差分检查也通过。测量时存在并发任务，此数值是本轮排版负载实测，不代表三版 ISO 整体加速比例。

优化后三版候选构建实测 562.529 秒，较前轮 886.959 秒缩短 36.6%；Original 组件阶段 341.213 秒，SP 完整文本构建与验证 519.430 秒。两轮存在不同并发负载，不视为严格独占基准。三版 typography 输入镜像 SHA-256 均与优化前相同；SP 最终镜像也相同，Original/Best 最终 ELF 包含新增 20×9 武器分支。批次收据 `work/editions/11dc66d5eea8a2748aca77d9bd0eff1969b03cc85270fd629bff94ac809b1dcf/original-best-sp-candidate.json` 已通过独立绑定核验。

证据：`work/review/tag-free-promotion-20261108/performance/current-library-performance.json`（绑定该轮测量的算法和度量输入哈希）及同目录 `metric-equivalence.json`。测量后增加的 `weapon_main` 度量是独立新增项，原有 11 个 profile 和字体哈希不变，记录在 `weapon-profile-extension.json`；最终三版构建包含该新增项。不得用放宽行宽或省略语义读回来换取性能。
