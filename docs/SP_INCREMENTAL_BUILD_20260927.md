# SP 组件增量构建与等价验证（2026-09-27）

SP 现在默认按组件输入指纹复用产物。日常入口不变：

```bash
python3 tools/build_editions.py --editions sp
python3 tools/build_editions.py --editions sp --force-rebuild
```

统一入口从上一份已通过独立回读的 SP 回执承接缓存。输入未变且整盘回执可验证时仍走原有
整盘复用；输入摘要变化时，五组组件分别判断是否需要重建，不再一律重新运行五个写入器。
组件模式摘要写入 `manifests/editions/sp/current.json` 的 `component_modes`，完整输入和文件锁
写入 SP 最终报告的 `incremental.components`。具体依赖范围见 [统一构建](BUILD_EDITIONS.md)。

## 实测

同一隔离项目内顺序执行 `build_full_text.py`，全量对照加 `--force-rebuild`：

| 场景 | 重建组件 | 总耗时 | 对应全量 |
| --- | --- | ---: | ---: |
| 组件依赖均不变，继续完整合成及回读 | 无 | 32.534 秒 | — |
| 修改一条 SP 剧情台词 | STAGE | 37.003 秒 | 53.687 秒 |
| 在上一场景上修改一条 SP 战斗字幕 | SRVC | 32.782 秒 | 53.446 秒 |

这是本机已有基线、字体和工具链缓存的测量，不是空缓存机器的冷启动。包含基线还原、
组件处理、ISO 合成、保护区校验及独立回读，不含外层版本调度或 xdelta 发布打包。
前两个场景与单元测试进程有重叠；后续全量和字幕场景没有该并行负载。

随后通过统一入口在新输入批次、新私有工作区中承接上一批次，五组组件全部复用，
包含外层调度、最终合成及回读共 **32.843 秒**，`verify_editions.py` 验证通过。
这不是相同输入直接复用整盘的耗时；相同输入仍可走原有整盘复用分支。

第一条剧情 `sd/story/001/dialogue/01.01/0000` 的句号改成感叹号后，增量只重建 STAGE；
`sd-battle:000` 的感叹号改成问号后，增量只重建 SRVC。两处改动仅发生在
`build/benchmarks/sp-incremental-20260927/project/`，未写回生产语料。

## 等价证据

每个文本修改场景都改变了 ISO 字节，并与相同输入的强制全组件重建比较：

| 场景 | 增量与全量共同的 ISO SHA-256 |
| --- | --- |
| 剧情修改 | `c7037fd4ef9e03e043d077fb92fd6adf6e4ed57d9c13eb4eb6f3a2c87efc6dc1` |
| 剧情＋字幕修改 | `763372cfd5a1dc9e4ee1f66aec37c12d3f007da85b2a30f30d0112a77f745a47` |

两组完整 ISO 的大小、SHA-256 及所有替换成员哈希一致；各次构建均通过最终独立语义回读。
未改文本的 SP 仍为 `892689dba632ed355b885eae42caa3fccd7a78646fccc991bda3f52a889bac61`。
详细分项计时、成员哈希及实现文件身份见
[`sp-incremental-performance-20260927.json`](../manifests/editions/sp-incremental-performance-20260927.json)。

全套 569 项测试通过；最后追加输入在构建中变化的拒绝用例后，7 项增量专项测试通过。
覆盖依赖的新增／修改／删除、system → STAGE 字节依赖、缓存损坏和缺失、强制重建、
失败或未完成独立回读的产物不得承接。统一入口另有 SP 强制重建参数传递测试。

## 当前边界

- 配置、锁定基线／字体和共享构建源码变化保守地使五组组件全部失效。
- STAGE 仍以整个组件为重建单位，尚未实现单 STAGE 块的增量编码。
- ISO 合成和独立回读仍完整执行，当前约 21 秒；没有通过省略校验换取耗时下降。
- 本轮只证明构建、字节等价和静态回读；没有新增 LRPS2 或 PCSX2 运行验收。
