## 2. 脚本的组织

- STAGE 覆盖块是代码加数据，载入到 `0x7566F0`。入口函数在 `0x595278` 装事件分派器，主程序按事件类型调用：2 阶段开始、4 战斗开始、5 战斗结束、6 单位行动结束、7 单位被击破、8 地图事件结束。分派器按回合（`0x5585d0`）、阶段字节（`0x558815`）、关卡标志、被击破单位、敌数等条件，把一段 16 字节一条的脚本交给解释器执行（Original `0x17a960`；SP 解释器 `FUN_001785b0`，扩展指令 `FUN_001c2e30`，两盘同构）。
- 所以同一关里的演出往往是不同回合、不同触发条件的几段脚本。第 24 话就是例子：`0xac00` 段是第 1 回合开场（甲儿驾 ＴＦＯ，铁也撞破百鬼帝国的屏障），`0x9f00` 段是几回合后机体被击破时触发的出击事件。早先把两段拼成一项是错的，现在拆成"大魔神冲破屏障"和"魔神Z出击"两项。
- 分析器：`tools/srwz/stage_events.py`（符号化 MIPS 遍历 + 脚本遍历，给出每个对白段由哪个事件触发）。每项名场面配置里的时间线逐条注明本篇偏移，原脚本窗口的反汇编在 `docs/issue-assets/sp-event-fidelity-20261014/original-windows/`。

## 4. 系统变量

- `0x900b` 主人公（0 节子，1 兰德）；`0x9309(p)` 驾驶员 p 在场；`0x9204(p)` HP%；`0x8020/0x8040` 对白里的说话人引用。
- **SP 的系统变量 `0x901e` 起比本篇后移 5。** SP 在 `0x901d～0x9022` 插了手柄变量（`FUN_001b7f60` 读 `0x62514e/0x625152`）。本篇 `0x901f`（暂停当前特效，置 1 时特效计数冻结）在 SP 是 `0x9024`；本篇 `0x9020`（舞台物件当前帧，`0x525610`）在 SP 是 `0x9025`（`0x5a48d0`）。直接用本篇编号会让场景卡死。魔神Z出击里"对白期间暂停特效""等物件动画到某帧"两类指令就是改成 SP 编号后才能原样执行。

## 5. 编号对照

- BGM：两盘通用（见上）。
- 机体、驾驶员：两盘编号不同。按两盘 COMPDATA 定义表（本篇单位 `0x4CAE4`、驾驶员 `0x2160`；SP 单位 `0x54b90`、驾驶员 `0x2b50`）同名组内按序号对应，再用记录字节相似度核对（`work/analysis/sp-event-fidelity-20261013/names.py` 的 `resolve`，结果 `id-map.json`）。低编号（甲儿、龙马等）两盘相同；之后一般后移，例如加洛德 320→330、阿波罗 602→623。对白里 80 个说话人都按此映射。
- 不在剧场名册里的机体要在空位用原生函数初始化（单位 `FUN_00149710`，驾驶员 `FUN_001492c0`）并建地图精灵（`FUN_00174a80`），否则不显示。

## 6. 对白块格式

本篇与 SP 格式相同：

- 关卡块里有一张段表：`{表地址, 段数}`，表项为 `(段地址, 段号)`，以零结束。每关取段数最多的那张表作为地图对白表。
- 每段：0x20 字节段头，接 32 字节一条的记录。`+0` 类型（1 = 一句对白，0x16 = 段结束，0x7e = 终止），`+4` 表情，`+8` 1，`+12` 说话的驾驶员（决定立绘），`+16` 文字指针，内容为"说话人\n台词"。
- 播放链：`0x0f n` → `FUN_002046e0` → `FUN_00204a50` → `FUN_001e0080(*0x62e380, 关卡, n)`；段表从 `**0x61e1e0` 取。对白播放器由 `FUN_002047c0` 创建在 `0x62e380` 并载入资源，`FUN_002048c0` 拆除；播放器 `+0xc` 是当前记录。对白期间游戏模式 `0x4caab0` 变为 0x13，地图帧 `0x140290` 负责绘制和推进。
- 台词里的 `$c`（部队名）、`$n`（主人公名）由引擎展开，SP 剧情里也在用。实测 `$c` 显示为 ＺＥＵＴＨ。

## 7. 对白怎样搬进 SP

SP 光盘里没有这些关卡的对白，所以从本篇日文光盘读取结构，配上已审校的中文：

1. `tools/special_disc/event_gallery/author_talk.py` 从 `build/iso/sources/original.iso` 读出各项用到的段，保留每条记录的类型、表情、段头和控制记录，把说话人换成 SP 编号，台词取 `corpus/zh/story-dialogue/stage-NNN.json` 的译文、说话人名取 `corpus/zh/story-speakers.json`，写成 `config/products/special-disc/event-gallery-talk.json`（构建只读这个文件）。
2. 构建时按 SP 码表编码文字，生成对白块放在 `0x830000`。每项时间线开头的 `talk_install` 把段表指针写到 `0x61e1e0` 并调用 `FUN_002047c0` 建播放器；时间线在原脚本的位置插入 `0x0f n`。播完或取消时调用 `FUN_002048c0` 拆除，`0x61e1e0` 和游戏模式随状态快照恢复。
3. 自动播放：脚本停在 `0x0f` 时，每条记录停留 60 + 4×（文字字节数）帧（一个汉字约 8 帧），然后模拟按一次○；若还没翻页，45 帧后再按。对白期间只有 START 能取消（避免×、○ 与翻页冲突），其余时间 ×／○／START 都能取消。
4. 为放下 24 KB 对白，名册快照移到 `0x840000`，私有区上限 `0x8C0000`。

## 10. ARMSX2 反馈后的修正（同日）

- **哀·天使剑、格兰维昂合神"只有对话"。** 两项都是最后一段对白一结束就起特效。对白结束时脚本离开 `0x0f`，×／○ 立刻恢复为取消键，翻最后一句时多按的 ○ 会直接结束场景（自动播放不按键，LRPS2 逐句回放没有暴露）。改为：○ 永远不取消（它是翻页键）；对白期间及对白结束后 60 帧内只有 START 取消；其余时间 × 或 START 取消（状态块 +0xcc 记最后一帧对白）。LRPS2 验证：哀·天使剑在最后一句后连按 5 次 ○ 照常播完特效；格兰维昂合神在对白结束后 60 帧内按 × 被忽略，之后按 × 正常取消。
- **中途取消后列表拖影。** 内存差分：特效（257）中途被取消后，`0x4cb080`（后期画面处理开关）仍为 1，而自然播完后为 0、列表时为 0。ARMSX2 硬件渲染下列表因此带残影（LRPS2 软件渲染不显）。已加入状态快照恢复，取消后 LRPS2 读回为 0。
- 爆爱无限光开场的黑色字幕条：LRPS2 截图（4540～5200 帧）没有黑条，需要 ARMSX2 截图定位。
