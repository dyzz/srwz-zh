## 2. 脚本的组织

- STAGE 覆盖块是代码加数据，载入到 `0x7566F0`。入口函数在 `0x595278` 装事件分派器，主程序按事件类型调用：2 阶段开始、4 战斗开始、5 战斗结束、6 单位行动结束、7 单位被击破、8 地图事件结束。分派器按回合（`0x5585d0`）、阶段字节（`0x558815`）、关卡标志、被击破单位、敌数等条件，把一段 16 字节一条的脚本交给解释器执行（Original `0x17a960`；SP 解释器 `FUN_001785b0`，扩展指令 `FUN_001c2e30`，两盘同构）。
- 所以同一关里的演出往往是不同回合、不同触发条件的几段脚本。第 24 话就是例子：`0xac00` 段是第 1 回合开场（甲儿驾 ＴＦＯ，铁也撞破百鬼帝国的屏障），`0x9f00` 段是几回合后机体被击破时触发的出击事件。早先把两段拼成一项是错的，现在拆成"大魔神冲破屏障"和"魔神Z出击"两项。
- 分析器：`tools/srwz/stage_events.py`（符号化 MIPS 遍历 + 脚本遍历，给出每个对白段由哪个事件触发）。每项名场面配置里的时间线逐条注明本篇偏移，原脚本窗口的反汇编在 `docs/issue-assets/sp-event-fidelity-20261014/original-windows/`。

## 4. 系统变量

- `0x900b` 主人公（0 节子，1 兰德）；`0x9309(p)` 驾驶员 p 在场；`0x9204(p)` HP%。
- `0x8020/0x8040` 是脚本的临时变量：移动指令 `0x139e` 第三参数 `0x80000001` 时作偏移，回切急降转向里作光标平移的 x、y。早先记作"对白里的说话人引用"不准确。`0x8000/0x8001` 也是临时变量（叠色、光柱的亮度）。
- `0x9015/0x9016`：战术光标所在格的 x、y（推断）。回切急降转向 `0xe620～0xe690` 每 16 帧把 0x8020/0x8040 写进去，光标从 (15,21) 平移到 (12,21)，镜头跟着光标走。LRPS2 里把锚点放在 (11,21) 才与录像吻合，差一格的原因未查。
- **SP 的系统变量 `0x901e` 起比本篇后移 5。** SP 在 `0x901d～0x9022` 插了手柄变量（`FUN_001b7f60` 读 `0x62514e/0x625152`）。本篇 `0x901f`（暂停当前特效，置 1 时特效计数冻结）在 SP 是 `0x9024`；本篇 `0x9020`（舞台物件当前帧，`0x525610`）在 SP 是 `0x9025`（`0x5a48d0`）。直接用本篇编号会让场景卡死。魔神Z出击里"对白期间暂停特效""等物件动画到某帧"两类指令就是改成 SP 编号后才能原样执行。

## 5. 编号对照

- BGM：两盘通用（见上）。
- 机体、驾驶员：两盘编号不同。按两盘 COMPDATA 定义表（本篇单位 `0x4CAE4`、驾驶员 `0x2160`；SP 单位 `0x54b90`、驾驶员 `0x2b50`）同名组内按序号对应，再用记录字节相似度核对（`work/analysis/sp-event-fidelity-20261013/names.py` 的 `resolve`，结果 `id-map.json`）。低编号（甲儿、龙马等）两盘相同；之后一般后移，例如加洛德 320→330、阿波罗 602→623。对白里 80 个说话人都按此映射。
- 不在剧场名册里的机体要在空位用原生函数初始化（单位 `FUN_00149710`，驾驶员 `FUN_001492c0`）并建地图精灵（`FUN_00174a80`），否则不显示。

## 6. 对白块格式

本篇与 SP 格式相同：

- 关卡块里有一张段表：`{表地址, 段数}`，表项为 `(段地址, 段号)`，以零结束。每关取段数最多的那张表作为地图对白表。
- 每段：0x20 字节段头，接 32 字节一条的记录。`+0` 类型（1 = 一句对白，0x16 = 段结束，0x7e = 终止），`+4` 表情，`+8` 1，`+12` 说话的驾驶员（决定立绘，也决定光标落在哪个单位上），`+16` 文字指针，内容为"说话人\n台词"。记录和段头里都没有光标位置。
- 播放链：`0x0f n` → `FUN_002046e0` → `FUN_00204a50` → `FUN_001e0080(*0x62e380, 关卡, n)`；段表从 `**0x61e1e0` 取。对白播放器由 `FUN_002047c0` 创建在 `0x62e380` 并载入资源，`FUN_002048c0` 拆除；播放器 `+0xc` 是当前记录。对白期间游戏模式 `0x4caab0` 变为 0x13，地图帧 `0x140290` 负责绘制和推进。
- 台词里的 `$c`（部队名）、`$n`（主人公名）由引擎展开，SP 剧情里也在用。实测 `$c` 显示为 ＺＥＵＴＨ。

## 7. 对白怎样搬进 SP

SP 光盘里没有这些关卡的对白，所以从本篇日文光盘读取结构，配上已审校的中文：

1. `tools/special_disc/event_gallery/author_talk.py` 从 `build/iso/sources/original.iso` 读出各项用到的段，保留每条记录的类型、表情、段头和控制记录，把说话人换成 SP 编号，台词取 `corpus/zh/story-dialogue/stage-NNN.json` 的译文、说话人名取 `corpus/zh/story-speakers.json`，写成 `config/products/special-disc/event-gallery-talk.json`（构建只读这个文件）。
2. 构建时按 SP 码表编码文字，生成对白块放在 `0x830000`。每项时间线开头的 `talk_install` 把段表指针写到 `0x61e1e0` 并调用 `FUN_002047c0` 建播放器；时间线在原脚本的位置插入 `0x0f n`。播完或取消时调用 `FUN_002048c0` 拆除，`0x61e1e0` 和游戏模式随状态快照恢复。
3. 自动播放：脚本停在 `0x0f` 时，每条记录停留 60 + 4×（文字字节数）帧（一个汉字约 8 帧），然后模拟按一次○；若还没翻页，45 帧后再按。对白期间只有 START 能取消（避免×、○ 与翻页冲突），其余时间 ×／○／START 都能取消。
4. 为放下 24 KB 对白，名册快照移到 `0x840000`，私有区上限 `0x8C0000`。

## 9. 验证结果

- **`$n` 改为固定名。** 实测 SP 把 `$n` 展开成 SP 存档里的主人公名（测试卡上是"兰德"），而第 0、12 项是节子线、立绘也是节子。`author_talk.py` 的 `PROTAGONIST` 表按项把 `$n` 写成"节子"，遇到未登记的项会报错。`$c` 照常由引擎展开（ＺＥＵＴＨ）。

## 20. MAPMODEL 地图成员与舞台物件（10-29）

**成员与地图号**
- 地图 n 用成员 **n + 1**：`FUN_00143cf0` 载入 `*0x524b00 + 1`，也就是关卡入口写的地图号加一。
- 成员 0 是公共资源，地图系统初始化时由 `FUN_00180b00` 载入一次，里面是 3 个动画模型。
- 81～195 是世界地图地名贴图（[MAPMODEL_WORLD_MAP_TITLES.md](MAPMODEL_WORLD_MAP_TITLES.md)）。女主线第一关选择值 0x50 再加一得到成员 81，也是同一条规则。
- 解析器：`tools/srwz/mapmodel_layout.py`，地图号换成员号用 `member_for_map`。测试：`tests/test_mapmodel_layout.py`。

**成员格式**
- 头部（`u32`）依次是：节数，头部大小（`12 + 8×节数` 向上对齐到 16），0，然后每节一对（大小, 结束偏移），结束偏移从 0 起逐节累加。
- 第 0 节：头部之后是地图宽、高，接着宽×高个 `u16`，逐行排列。
  - 低字节：有符号高度（0、−1…）。
  - 高字节：这一格的地形名记录编号，`FUN_00143cf0` 取该记录 +0x18 作为地形属性。
- 第 1 节：地形名记录，每条 0x1C 字节（`terrain_names.py`）。
- 第 2 节起每节一个模型：开头是变换头（缩放、旋转、位置的浮点数），然后是 Sony HiG 数据。

**HiG 数据**
- 插件目录：`u32` 个数，再接 16 字节一项（`name[8]`、0、偏移），依次是 Frame、Micro、Shape、Hrchy、Tex2d，动画模型多一个 Anime，有的还有 Share。偏移从"个数"那个字往前 0xC 算起。
- 插件块：
  - 16 字节块头：HiG 类型 `1,1,类别,0,u16 编号,0,版本`，然后 0 和行数。
  - 一行插件代码。
  - 若干 16 字节的数据引用（HiG 类型、偏移、0）。
- 数据块：同样的块头，最后一个字是长度（以 16 字节为单位），接一行计数。
  - 类别 1 Micro、2 Tex2d、3 Shape、4 Hrchy、5 Anime、6 Share。
  - **Hrchy（4,1）**：计数行的第 4 个字是节点数；每个节点有位移、旋转、缩放和父子链接。
  - **Anime（5,2）**：一行（类型、0、偏移、键数），接着是全部关键帧时间。
  - **Anime（5,3）**：关键帧数值。
  - **Anime（5,1）**：每个节点对应的通道。

**舞台物件与 `0x46`**
- 成员里的每个模型都是一个舞台物件，第一个也算（通常是大的静态网格）。

## 21. 地图对白的光标落点：说话人光标表（10-30）

地图对白每句换说话人时，SP `0x221b30`（对白记录的方法）调用 `FUN_0017cd20(说话人)` 决定光标去哪，`FUN_0017d3c0` 再按状态把光标移到 `0x61e328` 指向的单位（`FUN_0013d850` 写 `0x4eb1c0`）。

**查找顺序**：
1. `FUN_0017c540` 查关卡的说话人光标表（指针 `0x61e1a8`，由关卡入口装入，原作 `0x5952a8`）。
2. 没找到时，换成内置表 `0x458340` 再查一次。内置表把船员、操作员对应到所在舰艇的驾驶员，例如米莉亚莉亚→玛琉、蒂法→贾米尔、梅江/花江→兵左卫门。
3. 还没找到，`FUN_0017ccb0` 取第一个符合条件的单位。

**表的格式**：每条 8 个半字。
- [0] 说话人驾驶员（−1 结束，−2 任意）。
- [1] 低字节标志：位 0 选第二遍查找，位 1 之后隐藏；高字节为类型。
- [2..3] 32 位目标编号或 x。
- [4] y 或偏移 dx，[5] 偏移 dy。
- [6] 条件关卡标志（`0x5dbc40` 位集，`FUN_0014c7b0`；0/−1 表示无条件）。
- 按顺序取第一条满足的。

**两遍查找**：`FUN_0017cd20` 先用 `FUN_00176f60(2, 说话人)` 在地图上找这名驾驶员。这个函数每次先把 `0x61dde8/0x61ddf0/0x61ddf8` 清零，找到时依次写入单位、机体和机体 +0xb0（驾驶员）。
- 找到（`0x61ddf8` 非 0）时，查位 0 = 1 的条目（第二遍）。
- 没找到时，只查位 0 = 0 的条目。
- 原作给自军角色（节子、丹泽尔等）的条目多是第二遍，因为实际游玩时他们的机体在地图上。鉴赏不部署这些人，第二遍条目永远用不上；第 0 行第 16 段节子那句因此退到第 3 步，出现了红色光标。
- 鉴赏的处理：对鉴赏地图上没有的说话人，在每条第二遍条目后面紧跟一条位 0 = 0 的副本（配置里标 `off_map`，`fix_20261030f.py`）。这样不管说话人在不在地图上，这句的表现都一样。

**类型**：

| 类型 | 含义 |
| ---: | --- |
| 0 | 按编号（种类 0）找单位 |
| 1 | 载着该机体的单位 |
| 2 | 载着该驾驶员的单位 |
| 3 | 固定格子 (x,y)，那里不需要单位 |
| 4 | 某驾驶员所在格加偏移 |
| 5 | 不显示光标 |
| 6 | 按编号（种类 14）找单位 |
| 7 | 槽 45–55 里第一个有效单位 |

**这张表解释了此前用录像反推的隐藏锚点**：

- STAGE030 奎因斯坦 → (17,17)。马林/奥利弗/雷太 → 驾驶员 908/906/907（帕尔萨班三机）。

## 23. 脚本推进与 ○ 模式的对白替身（10-30）

**脚本怎样往下走**：
- 每帧由 `0x17c1c0` 一带的驱动调用 `FUN_001c7740(当前记录)`，它按操作码判断等待是否结束，返回要前进的条数，再调用解释器 `FUN_001785b0`。
- 解释器里多数指令执行完自己调用 `0x177cc0`（记录指针 `0x61deb8` 加 16，并立即执行下一条）。
- `0x14 f,s`：调用 f；s≠0 时解释器不前进，但驱动下一帧照样前进一条，所以 s 只能当作"停一帧"，不能让回调自己控制等待。回调可以直接改 `0x61deb8` 来跳转。
- `0x52 a` 是 gosub（返回地址压入 `0x61ded0[深度]`，深度在 `0x61def0`），`0x54` 是 return。
- 扩展指令 `0x139c` 等待镜头滚动结束，同时等所有静态特效（特效池里类型不是 1/100 的）结束。冲锋演出 `0x13a3` 开着时永远等不完（第 10 行实测卡死）。

**对白模式的光标**：每句由记录方法 `0x221b30` 调 `FUN_0017cd20(说话人)`，再每帧调 `0x221b40` 即 `FUN_0017d3c0`。
- 状态 1：`FUN_0013d850` 设光标。
- 状态 3：滚动镜头（`0x13d940` / `0x13db20`）。镜头只在光标靠近画面边缘时才滚，所以最终镜头取决于整段经过的每个说话人。
- 状态 4：选显示的小队成员，然后报告完成。
- `op 0x0f n,x` 会把 x 写进 `0x61e088`（`FUN_0017cd20` 的分支条件）。

**○ 模式的替身**（runtime.S `gallery_quiet_sub`）：
- 场景开始时，○ 把每条对白指令改成 `0x52 gallery_quiet_sub, 说话人表, 下一句`。说话人表在编译时由 `runtime.py` 按对白记录 +12 生成，放在 `gallery-quiet.inc`（位于全部代码之后，免得把代码挤出分支范围；整体仍受 0x24000 载荷上限约束）。
- 每句先清 `0x61e088`，再调 `FUN_0017cd20`。
  - 不移动光标：立即处理下一句，不占帧。
  - 移动光标：每帧调一次 `FUN_0017d3c0`，直到完成（等待用 `0x01 1` 加跳回实现，不用 `0x139c`）。
- 表读完后跳到 `0x54` 返回。
- 结果：两种模式在每个特效开始时的光标格完全一致，画面只差捕捉时机（第 0 行 e8 的差别来自对白 13 紧跟在特效 8 后面，△ 要等对白框打开才移光标）。
