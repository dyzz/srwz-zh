# 滚动正文的原生空格占位符

问题记录：[GitHub #29：黑泽小皮反馈](https://github.com/dyzz/srwz-zh/issues/29)。

世界观滚动正文的空白分隔行是资源格式的一部分。原版在这些行中存放 U+3000
全角空格，编码为 `0x8140`。清理空白或重排正文时，不得删除整个分隔行，
不得将它变成零长度行，也不得缩短原版的多空格占位行。

## 问题与范围

本篇当前 Original、Best 的 MTV_PROS 曾在四条正文中丢失 14 个占位行：
`summary/00/000`（4）、`01/000`（2）、`05/000`（4）、`07/000`（4）。
本地 Best 单项实验保持程序、字体、正文、物理行数和滚动参数相同，仅恢复第二条
正文的两个占位符，两处整块文字短暂消失随之消除。软件渲染也会复现原问题。
该证据不推定具体绘制函数内部机制，也不覆盖其他正文的运行验收。

SP 的 MTZSPROS 同样丢失八个占位行，位于六条叙述：`narration/000`（2）、
`001`（1）、`002`（1）、`003`（2）、`008`（1）、`009`（1）。
`narration/001` 原版占位行包含 21 个全角空格；审阅源曾缩为一个，当前语料又将它删空。
本篇、SP 的成品语料及对应 SP 审阅源均恢复原生长度，可见正文与物理行数保持。
SP 的同类失字现象仍需独立运行验收。

本篇回归来自 `e7f88dc` 引入的重排函数及 `1a73100` 的批量写回（2026-09-28）。
7 月初稿曾有相同输入，`90506ff` 在 7 月 28 日已修正。
SP 的早期写回代码 `a2d1eed`（2026-09-20）已会输出零长度行，随后 `1a73100`
从语料中直接删掉占位符。日期属于源码追溯，不代替历史镜像运行证据。
反馈者回忆旧录像约使用 9 月 22 日镜像，但缺少该镜像身份，不能绑定上述回归提交。

## 检查契约

`srwz.summary.validate_scroll_placeholders()` 将原生空格行与可见正文分开核对：

- 保留分隔行顺序、数量，以及每行全角空格数量。
- 允许正文重排改变物理行位置。
- 拒绝零长度分隔行、ASCII 空格占位行、整行删除和长度缩减。
- 编码及回读中的占位符必须为 `81 40`。

检查接入本篇组件构建、SP narration 写回、共享 summary 补丁规划、两种滚动
profile 的重排结果、本篇与 SP 成品回读，以及 SP 审阅稿导入。
成品必须对照原盘，而不仅与当前中文语料比较，避免坏语料和坏成品同时通过。

在项目根目录运行：

```sh
python3 tools/text_layout/audit_scroll_placeholders.py
python3 -m unittest discover -s tests
python3 tools/build_editions.py
```

审计器读取原盘，核对本篇 28 条与 SP 10 条记录、源哈希绑定及占位行；另扫描中文
语料中带 `source_text` 的记录。发现差异返回非零状态。
其他仅存源哈希的资源不因这一扫描自动获得原盘字节验收。

固定页、Q&A 与固定文本格使用各自存储规则。VT1 会将未使用字格填为 `0x8140`；
用于比较的 `rstrip('　')` 不等于删除存储填充。不可把所有界面的空行统一当作滚动记录，
也不可因格式看起来相同而自动清理原版空格。

完整 ISO、本地录像、存档和运行捕获不进入 Git。生产 ISO 的静态构建／回读与新镜像
的 LRPS2／PCSX2 人工运行验收独立记账；issue #29 在运行验收完成前保持开放。
