## 当前待验收范围

### `DATA/HSFC.BIN` 流程图标题透明层：静态完成，运行验收待做

流程图左上标题已经按“剧情流程”接入当前生产构建；同页三个动态按钮提示仍为
“确定／返回／加速”。标题来源为 `DATA/HSFC.BIN` chunk 1（原归档范围
`0x2570..0x39B00`）中的 TIM2 record 2，解压偏移 `0x30CC0`，256×256、8bpp
索引图。虽然 TIM2 头标记为 PSMT8，这张图在文件中的有效像素顺序实际是逐行
线性索引。

旧方案的问题已经收敛为精确的像素范围错误：把 `x=14..241, y=8..35` 整段
清成固定索引 `2` 时，同时覆盖了 97 个原本 alpha 为零的透明像素，因而把标题板
边缘直接涂成不透明底板。当前方案只在标题板内部的
`x=30..213, y=7..34` 重建原有逐行蓝色渐变；该矩形内 5,152 个源像素全部原本
不透明，因此不会跨越透明边界。中文字形使用原图既有的深色轮廓索引 `2` 和
高亮索引 `16..30`，CLUT 本身不修改。

当前静态／ISO 回读证据：

- 标题纹理按 `linear_indexed8` 写回，通用 PSMT8 swizzle 不再参与；
- 原版与中文输出的 alpha 平面 SHA-256 都是
  `e77e736a92ee2d6b717f5a49134131c634e44006ae3a3774ffef7be51abe056e`；
- 19,449 个透明像素逐像素保持，标题矩形外所有索引字节保持；
- CLUT、TIM2 元数据、HSFC 归档长度、后续 chunk 与 SLPS 偏移均保持；
- 最终 ISO 中的输出索引 SHA-256 为
  `317180e48d4b08b22502272010536ee1f22ecfc8ad394265f64a7fbe13c9b4a9`，
  独立回读为“剧情流程”。

这仍不是 PCSX2 运行画面验收。需要用当前精确 ISO 重新启动后人工确认：标题只显示
一次、无纵向条纹、标题板边缘仍透明、蓝色渐变无涂抹感，并同时确认三个按钮文字。

### `DATA/NISVDATA.BIN` 音乐选择标题透明层：静态及运行验收完成

音乐选择深层界面的左上标题来自 `DATA/NISVDATA.BIN` chunk 1 中的 TIM2 record 0，
解压偏移 `0x40`，512×256、8bpp PSMT8 索引图。第一次写回把标题区清成透明索引
`0`，运行时形成黑洞。随后 SHA-256 为
`e1ed920d38583af848cebed73106c574dd1d12ae8cef0f1d9ebb7b6d4ad6a9f1`
的候选虽然保持了整张贴图的 alpha 平面，却把 `x=15..203, y=4..32` 整块刷成固定
底色；用户运行复验确认它仍是明显的不透明矩形，而且原日文最右侧仍有残留。该候选
未通过运行验收，`alpha_mask_preserved=true` 只能作为必要的静态约束，不能单独证明
标题板视觉正确。

修正方案沿用剧情流程标题的“先恢复原底板、再绘制中文”原则，但不再覆盖整个矩形。
原日文用到的 CLUT 索引 `14..31` 实际范围是 `x=15..205, y=4..32`；写回在
`x=14..206, y=3..33` 内只选择这些源字形像素并向外扩一像素以包含描边，然后按原板
各行索引恢复。这样覆盖到最右端 `x=205` 的日文，同时保留没有参与原字形的底板像素，
最后再使用同一 CLUT 的 `14..31` 绘制“音乐选择”。

当前候选 ISO 的 SHA-256 是
`91a9c5375da4f85bb916de15491cf09c72d3cb053d2997d2b36e76ff5b21e08e`。
最终 ISO 回读确认：原日文索引边界为 `x=15..205, y=4..32`，3,690 个源字形像素
经 1 像素扩张后只恢复 4,451 个像素；整张贴图 alpha 平面、52,236 个透明像素、
CLUT、TIM2 元数据、NISVDATA 其他 chunk、归档长度及固定 LBA 均保持。完整 170 个
剧情块、93,071 条翻译记录的整盘内容回读通过。

用户随后用上述精确 SHA-256 候选完成 PCSX2 运行复验：标题板不再出现平直矩形
涂抹，左右边框与尖角连续，右侧日文残影完全消失，“音乐选择”的位置和清晰度正常。
因此该项同时具备静态、最终 ISO 回读和运行画面证据。

## 通过标准

一个 surface 只有同时满足以下条件才可标记为通过：

1. 精确 ISO、组件、存档、日志和截图哈希齐全；
2. 从声明路线实际到达目标画面；
3. PINE 状态、DVD、ELF 和零 TLB 检查通过；
4. 所有文本、布局、交互和纹理断言明确通过；
5. hash-only receipt 明确绑定当前 ISO SHA-256 和目标路线。

boot smoke、静态回读、旧截图或单独的 session probe 均不能替代上述闭环。执行
命令见 `BUILD_AND_RUNTIME.md`。
