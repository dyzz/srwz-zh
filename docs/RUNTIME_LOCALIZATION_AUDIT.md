# 运行截图汉化审计

更新时间：2026-07-30

## 1. 证据基线

本页只记录实际运行截图能证明的画面状态，并将其与仓库中尚未进入当前 ISO 的
静态候选分开。当前唯一测试镜像为：

```text
build/iso/ui-p2-default-names-first-five/
  srwz-ui-p2-default-names-first-five.iso
SHA-256:
  026f29e3e77b78a19f000c6781317ebc95aeb672b5b2848ad2a30bf8d2f5c473
```

该镜像包含 P2 UI core、默认主人公中文名和 STAGE 001～005 剧情，不包含
P4～P10 的后续 UI 分层，也不包含五张隔离 atlas。P10 的独立精确 ISO 已通过
启动门，但 P4～P10 的静态／启动证据都不能替代当前画面的 PCSX2 逐屏验收。

## 3. 截图中仍然可见的日文

### 3.1 人物能力与数据库

驾驶员能力页仍显示：

- `見切り`
- `カウンターＬ２`
- `援護防御Ｌ１`
- `直感`
- `クリティカル率＋２０％`

仓库 P10 静态候选已经选择四个可定长写回家族，共 403 条：

| 家族 | 条目数 | 当前状态 |
| --- | ---: | --- |
| 驾驶员技能名称与说明 | 88 | 已写入 P10；精确 P10 ISO 启动通过，页面视觉待验收 |
| 机体特殊能力名称与说明 | 155 | 已写入 P10；精确 P10 ISO 启动通过，页面视觉待验收 |
| 精神指令名称与说明 | 145 | 已写入 P10；“絆”同码位重绘为“绊”；精确 P10 ISO 启动通过，页面视觉待验收 |
| 小队长能力分类与效果 | 15 | 已写入 P10；精确 P10 ISO 启动通过，页面视觉待验收 |

截图中的示例在现有语料中分别为`识破`、`反击`、`援护防御`、`直觉`和
`暴击率＋２０％`。当前 Rust compressor 将完整 P10 COMPDATA 压到
145,191 字节，保持原 71 扇区并在 145,408-byte 硬门内余 217 字节。对应
7-member DVD 的 SHA-256 为
`218de6c432fd0d076cc464b68a8868349ced4f585e31608b8c4b0f49e4dff63b`；
PCSX2 v2.6.3 fresh-process 已确认 DVD、ELF、PINE Running 和零 TLB。
因此容量／启动阻塞已解除，但这不等于四个页面家族已经显示正确。下一步应在
同一精确 P10 候选上，逐页验证名称、等级、说明文字、颜色和截断；只有出现
可归因问题时才按家族拆分。

### 3.2 武器名称与武器数据库

巴尔戈拉武器页仍显示：

- `ヘルブ・ストライク`
- `ストレイターレット`
- `レイ・ピストル`
- `バーレイ・サイズ`

这些名称存在于武器语料草稿，但 P10 有意没有批量晋级零件／武器专名：
当前 1,250 条数据库父集只选择了上述 403 条，另有 847 条延期。现有部分直译
（例如把专名按普通词义拆译）不能直接视为最终译名。武器工作需要先按作品设定、
官方中文资料和同系列社区惯例审校，再处理定长容量、字库和信息页运行验证。

武器页中的攻击力、射程、命中、CRT、弹数、EN 消耗、必要气力、必要技能、
地形适应和特殊效果等框架标签已具备中文语料；仍需用拥有不同武器属性的存档
覆盖 TRI、PLA、全体、移动后、合体和不可用状态。

### 3.3 人物、机体与敌军列表

敌军部队表截图仍可见：

- `【敵部隊表】機体選択`
- `地図`
- `小隊`
- 列头 `小隊`、`機体`
- 机体名 `ネモ`

这说明“页面框架”和“动态数据库名称”是两层工作。不能因为`力克・迪亚斯`
已经出现中文，就认为同一列表的所有机体名都已覆盖。后续需要：

1. 补齐遗漏的人物、机体和武器专名，并锁定官方／人工确认来源；
2. 将列表标题、操作提示和列头归入对应 embedded UI 分组；
3. 用敌军列表、我军部队表、搜索结果和机体信息页交叉验证同一名称。

### 3.4 系统设置

系统页顶部标题已经是中文，但主列表、选项值和底部帮助仍有大量日文，例如：

- `ＢＧＭ設定`
- `クイックコマンド`
- `ソート・サブ情報の記憶`
- `振動機能`
- `グリッド表示`
- `カーソル移動方式`
- `カーソルジャンプ`
- `ピース移動スピード`
- `援護防御の初期設定`

P7 已建立设置页及其子页所需的追加字库和 fixed-span 候选，但仍需合入当前 ISO，
逐页检查左右选项、灰色禁用态、帮助文字和控制器图标。

### 3.5 开场资料与关卡标题

角色选择页的`男主人公`、`女主人公`和`请选择角色。`已经是中文，但路线标题
`ザ・ライトスタッフ`及人物简介仍是日文。第一话标题在过场标题卡、作战目标和
战况报告中也继续显示日文。

这部分需要先确定同一标题在所有 surface 的统一译名和长度预算，再分别处理
动态文本与可能的图片文字。英文装饰标题（如 `Operation End`、
`Tactical Situation`）属于原 UI 设计，默认保留，除非后续决定做全中文美术。

### 3.6 第一关前世界地图地点标题

`月面　地球連邦軍ルテチウム基地`目前仍是日文。运行截图已经证明
`flow.bin`／HSFC 的同名摘要不是显示源；无效补丁已撤销。用户决定暂缓，
该项保持独立未定位 surface，不阻塞第一关正文和数据库汉化。

## 4. 建议的后续顺序

1. **先运行验证 P10 人物／机体能力数据库。**
   它直接覆盖截图中最显眼的技能、精神、特殊能力和小队长效果。403 条已经
   通过 Rust 压缩、71 扇区硬门和 fresh-process 启动；现在需要取得第一幕间
   原生存档，在同一精确候选上完成四个家族的视觉验收。

2. **再做武器与剩余人物／机体专名。**
   先审校名称，尤其避免把片假名专名机械直译；通过后再解决 847 条延期项中的
   定长、字库和压缩预算。

3. **完成系统设置、敌军列表和信息页细项。**
   合并 P4～P9 已有 embedded UI 分层，逐页验证列头、选项、帮助和状态色。

4. **统一关卡标题与开场人物资料。**
   同一个标题必须覆盖标题卡、作战目标、战况报告及其他重复 surface。

5. **最后单独处理图片／未定位渲染资源。**
   包括世界地图地点标题及五张 atlas 的运行时映射，不与普通文本写回混为一项。

## 5. 验收原则

- “已有中文语料”不等于“当前 ISO 已显示中文”。
- “静态候选通过”不等于“同一 PCSX2 页面已验收”。
- 人物、机体和武器专名优先采用官方中文译名；没有共识时登记来源并人工确认。
- 每次只增加一个可归因分层，保持单一 ISO、固定哈希、零意外 LBA 偏移和
  fresh-process boot 证据。
