# 给移植 AI：XAN 在无印版完整战斗动画中缺少左下角头像

日期：2026-10-06。主程序：无印版 `SLPS_258.87`。用户截图已经确认目标是完整战斗动画底部台词栏左侧的黑色头像框。XAN 机体、名称和台词已经出现，任务是补齐这个框里的头像。

本文替代此前版本中“完整战斗动画的路径尚未确定”的说明，补充 [VT1 格式及 Extract 文档](VT1_XAN_RESOURCE_HANDOFF_20261006.md)。压缩处理按接收方已有方案执行，不重复设计。

## 1. 结论：这个框有已确认的 VT1 小头像加载链

无印版战斗模块的头像缓存函数会调用共用 VT1 加载器，再读取 128×128 小头像映射表。这里所说的地址已经从原版和 SP 主程序的调用指令验证，不是根据图片尺寸或网页导出器猜测。

```text
战斗当前发言者的人物视觉 ID V，以及表情 E
  → 战斗头像缓存登记函数 0x2F88C0
  → 战斗头像加载函数 0x2F8710
  → 0x1805E0
  → 共用 VT1 加载函数 0x180090，选择小头像
  → ELF 的人物／表情映射表，得到图片 ID R
  → ELF 的小头像成员偏移表
  → VT1 第 10 组的压缩图片记录
  → 战斗纹理上传 0x2F87C0、绘制 0x2F8970
```

**图片留在 VT1，ELF 负责索引绑定；不把 PNG 直接追加到 ELF。** 已经把图导出或塞进 VT1，还不等于战斗框能找到它。

## 2. 可复查的调用与调试地址

下表的运行时地址适用于原版布局；若接收方搬迁了代码，须按候选 ELF 的程序段重新换算。

| 用途 | Original 运行时地址 | Original ELF 文件偏移 |
| --- | --- | --- |
| 战斗头像缓存登记 | `0x2F88C0` | `0x1FA340` |
| 战斗头像加载函数 | `0x2F8710` | `0x1FA190` |
| 战斗模块调用共用包装函数的指令 | **`0x2F8744`** | **`0x1FA1C4`** |
| 共用包装函数 | `0x1805E0` | `0x082060` |
| 共用 VT1 加载函数 | `0x180090` | `0x081B10` |
| 小头像表引用指令 | `0x1801F8` | `0x081C78` |
| 表情回退帮助函数 | `0x180A20` | `0x0824A0` |
| 战斗头像纹理上传 | `0x2F87C0` | `0x1FA240` |
| 战斗头像绘制 | `0x2F8970` | `0x1FA3F0` |

Original 主加载段的换算为 `RAM = ELF 文件偏移 + 0xFE580`，只适用于该段。

关键指令（省略无关指令，保留延迟槽）：

```asm
; 战斗头像函数 0x2F8710
0x2F873C  lbu   a3,7(a0)       ; 已登记头像个数
0x2F8740  addiu a1,a0,8        ; 人物视觉 ID 缓存数组
0x2F8744  jal   0x1805E0
0x2F8748  lw    a0,0(a0)       ; 输出缓冲区，延迟槽
; a2 此前设为 a0+0x38，即表情数组

; 包装函数 0x1805E0
0x180614  lh    a0,0(a1)       ; 取第一个视觉 ID
0x180628  lh    a1,0(a2)       ; 取第一个表情
0x18062C  move  a3,zero        ; 小头像分支
0x180630  li    t1,-1          ; 按视觉 ID 和表情计算表项
0x180634  jal   0x180090
0x180638  move  a2,zero        ; 延迟槽

; 共用加载器的小头像分支
0x1801F0  lui   v0,0x40
0x1801F4  sll   a0,s6,1        ; s6 = V*16+E（常规计算路径）
0x1801F8  addiu v0,v0,-0x1AD0  ; RAM 0x3FE530
0x1801FC  addu  a0,v0,a0
0x180204  lh    a2,0(a0)       ; 得到 VT1 图片 ID
```

SP 中对应战斗加载函数为 `0x2FE760`，其中 `0x2FE794` 调用 `0x181FD0`；包装函数 `0x182024` 调用 `0x181A80`。SP 也使用同类共用加载链，但表地址、组号及图片 ID 不同。

完整摘录和源程序 SHA-256 见 `issue-assets/vt1-xan-resource-plan-20261006/battle-portrait-binding-proof.json` 及两份 `battle-portrait-*-disassembly.txt`。

## 3. 无印版 ELF 中实际需要绑定的表

以下是 **ELF 文件偏移**。

| 文件偏移 | 用途 | 表项 |
| --- | --- | --- |
| `0x2FA100` | VT1 外层分组偏移表 | 小端 uint32 |
| **`0x2FFFB0`** | **视觉 ID → 小头像的 16 个表情槽** | **小端 uint16；程序用有符号 lh 读取** |
| `0x30E8F0` | VT1 第 10 组小头像成员偏移表 | 小端 uint32，相对该组起点 |
| `0x307450` | 视觉 ID → 512×512 半身像表 | 小端 uint16 |

小头像映射表原有 933 行，每行 32 字节：`[0x2FFFB0, 0x307450)`。原小头像成员为 1742 条，即图片 ID `0…1741`。若接收方沿用末尾新增一张的方案，新图 ID 是 `R=1742=0x06CE`。

```text
XAN 的表情 E 对应表项：0x2FFFB0 + V*0x20 + E*2
写入内容：R 的小端 uint16
例如 R=1742：CE 06
```

当前接收方候选的 V、R 和表搬迁情况未知。必须用对方已有移植的真实 V，而不能把 XAN 的机体 ID、名字索引、SP 视觉 ID 或 VT1 图片 ID 混用。

若 XAN 只需要一个头像，可将 **XAN 自己的** 16 槽都指向 R，保证战斗台词涉及的表情都能命中。程序虽然有“当前槽为 1 时找第一个非 1 槽”的帮助函数，但共用加载器在全局模式值为 2 时跳过视觉重映射和表情回退；因此不能依赖回退修复所有战斗情况。

```python
import struct

# candidate_elf 为接收方修改后的 SLPS_258.87 字节内容。
assert 0 <= V < 933, '原表容量不足；先检查接收方的扩表或搬迁方案'
assert 2 <= R < 32768, '原加载器用有符号 lh 读取图片 ID'
row_offset = 0x2FFFB0 + V * 0x20
before = struct.unpack_from('<16H', candidate_elf, row_offset)
print(hex(row_offset), before)
# 确认该行归 XAN 所有、R 已写入且成员边界正确之后，再修改候选副本：
struct.pack_into('<16H', candidate_elf, row_offset, *([R] * 16))
```

原表只覆盖 `V=0…932`。`V=933` 已落入半身像表；新增 V≥933 时必须检查并采用接收方的表扩展／搬迁方案，不能直接按上式向原表外写。

追加 R=1742 还需要完整更新成员边界：原表中的 `offset[1742]` 原为终点，文件偏移 `0x310428`；新 `offset[1743]` 的位置是 `0x31042C`。后方发现的零字节仅是空间候选，使用前须检查所有权、引用和接收方已有修改。不能只改映射槽却缺少新成员终点。压缩及组边界按既有方案处理，并保持原版固定文件／组边界约束。

## 4. 战斗里传入的 V 从哪里来

已找到的战斗指令准备代码 `0x2EA080` 会根据台词发言者匹配当前机师记录，通过 `0x2E9BF0` 输出视觉 ID，再登记到 `0x6D2C50` 的头像缓存中。

`0x2E9B00`／`0x2E9BF0` 在匹配成功后，从运行时机师条目的 `+0x1C` 读取视觉 ID，向输出参数写入该值。常规台词指令中，`0x2EA0E8` 将指令字节 `+3` 的位 2…5 提取为表情，即 `(byte3 >> 2) & 0x0F`。因此名称能显示并不能证明用于头像的视觉 ID 已经正确。

最直接的候选调试方法：

1. 在缺图的同一战斗片段，于 Original RAM `0x2F8744` 下断点。
2. 记录 a1 指向数组中的视觉 ID、a2 指向数组中的表情，以及 a3 的个数。两数组的元素步长为 4 字节，包装函数以 lh 取有效低 16 位。
3. 跟入 `0x180090`，记录最终 s5（有效视觉 ID）、s4（表情）、s6（表项编号），避免漏掉视觉重映射。
4. 小头像分支在 `0x180204` 从 RAM `0x3FE530 + 2*s6` 读取图片 ID。核对它是否等于实际新增 R。
5. 通过该 R 的成员边界从候选 VT1 解压读回，并在相同战斗界面验证显示。

如果没有模拟器调试，先要求移植 AI 报告候选 XAN 的真实 visual ID 和对应 ELF 行前后值；这些足以制作具体的映射补丁，但仍不能代替战斗实机核验。

## 5. SIPI 和 TICI 的位置及本任务边界

`BTL/SIPI.BIN` 是光盘上的独立成员，**不是一张等待在 ELF 中追加的完整机师头像表**。原版文件大小 14928 字节，共 933 条 16 字节记录；SP 共 969 条。代码 `0x2ECA40` 加载该文件，`0x2EC960` 用索引乘 16 取得记录。

SIPI 的记录内 `+0x06` 是直接 TICI 索引。原版 TICI 有 217 条；但 SP 原生 XAN（视觉 ID 553）的 SIPI 记录为：

```text
<8H = FFFF, 0000, 0000, FFFF, 0103, 0040, 0000, 0000
hex = ffff00000000ffff0301400000000000
```

它的 TCI 与 TICI 直接索引都为 FFFF。**不要为了修复截图中的 VT1 头像框而自动追加 TICI 或改这个字段。** `0040` 的完整语义未由本次证据确定，也不能当作“开启 VT1 头像”的开关照抄。

SP XAN 的 VT1 小头像映射行是 `[1094,1,1,…,1]`，源图为 SP VT1 第 12 组图片 1094。可用附带 Extract 导出完整原生图片记录。图像是否符合用户希望的外观，需要另行视觉确认；来源一致只证明它是原生资源。

SP 的 553 仅用于源图定位。无印版视觉 ID 553 对应已有角色薇拉，其小头像行位于 `0x3044D0`，全 1 不代表人物 ID 空闲。不能把 SP 的 V=553 或 R=1094 原样照搬到原版。
