# 从 DreamQuest 到机战 Z：写在 v0.4.0

这个项目的初心，是想看看“一个人＋AI”能把汉化做到什么程度。
受别人用 ChatGPT 重制老游戏的启发，我先做了 DreamQuest 的分析与重制尝试，
又翻出《SD 高达 G 世纪 DS》，测试 GPT 5.5 能否完成 NDS 汉化。
很快有了初步效果，于是继续尝试各个部分。

以为难的 UI 修改，主要靠 AI 就能推进。我此前不懂 4bpp，更多是在看效果，提醒它调整对齐和大小。
以为直接的字库反而卡了很久：两种字体大小、非标准 Shift-JIS 映射，
需要结合攻略里的已知人物、机体、指令与 OCR 识别，最后搭网页人工识别、补录了一千多字。

字体也试了很多种，8×16 窄字体始终难找，神游 8×11 的个别字效果又不好。
加上太想测试 AI，尝试铺得太开，后来推进越来越困难。

发过几张贴吧测试图后，大约一周内看到了废柴君驾到的开源项目。
他将小字体统一改成大字体，工程规划也给了我启发。
我很高兴有人开源，便把已有成果合并过去，继续修复问题。

这部分包括：补齐四关遗漏的 31 条剧情及章节标题，新增 404 条简介（人物 216、机体 188）；
汉化 54 个 EV 标题、28 个作品名，补齐 30 条回放文本；
补全各层菜单，修正 346 个字形与“逅”覆盖“目”的问题。

还处理了姓名框、长名称、资料首字缺笔，以及 22 个超宽模板、44 条 ID 指令说明的裁切；
修复 Turn A 图标、强夺高达长武器名导致冻结、卡缪和捷利特强化在特定通关分支中被退回，
以及人物形态名、匹配条件和西罗克相关文本。
敌方 HP 不显示由我定位、上游集成修复；永恒号六格背景与边框由我补齐，六格容量本身是上游已有改动。

后来同时验证机战 Z 和 64，恰逢 64 汉化发布、官方宣布《破界篇》重制，便集中做 Z。
工程和审校主要使用 GPT 5.6 Sol Max，近期开始用 Astra High，
也受益于 fortiersteven 的开源研究。

社区常说 Z“加密复杂”。就我处理的资源而言，主要是自定义 LZ 类压缩、归档和编码，无需寻找解密密钥。
压缩会用“向前找多远、复制多长”来表示重复内容，但编码规则和游戏解压限制需要逐项适配，改后的数据还得压回原空间。
编解码、压缩策略和往返校验基本都借助 AI 完成，我负责提出约束、检查结果。

字库还有特殊窄距规则：换了字形，程序仍可能按旧编码把中文压窄，需要按界面处理。
贴图也会出现电脑上正常、游戏里发暗或带黑边的情况，我需要反复比较字形、阴影、间距，再进游戏确认。

翻译初稿全部使用固定版本 deepseek-v4-flash-0731，通过阿里云 DashScope API 分批调用。
提示词先规定忠实、自然、符合人物语气的表达，以及术语、标点、变量和选择项结构；
再附项目词表、已审译例和待译文本。
译例只参考风格，不能套用内容。

剧情按关卡、场景和固定编号组织；
补充上下文的批次还提供说话人的中日文名、身份、所属作品和前后台词，避免混淆角色与分支。
指代不明时保留自然的无代词表达，标记歧义，不擅自补“我、你、他”或性别。
图鉴区分必须采用的译名与语境提示，避免把普通词硬套成游戏术语；硬换行先还原成语义段，战斗资源的相邻记录也不能直接当成连续对白。

模型返回后，脚本检查编号、漏项、变量、术语和标点，再让 AI 审校。
站友在阅读和游玩中向我反馈问题，我会核对原文、排查同类情况，借助 AI 润色，再构建并检查效果。

为了重复复现问题，我搭建了 LRPS2 自动化，按帧操作、截图对比，使用独立存档副本并记录运行条件。
字体、布局和演出仍需要人工看实际画面。

开发、排查和修改主要由我借助 AI 完成。
感谢大家提供的建议、截图和存档，它们经常让我注意到此前遗漏的细节。
审阅站也把建议、处理结果和后续讨论留了下来。
