# 战斗演出 □ 跳段补丁

本文记录 2026-09-13 至 09-14 对战斗演出引擎的逆向结论、□ 键"跳到下一段"的实现与验证，
以及 ○ 快进机制的分析。○ 的增强版只作研究记录，不进入发布。2026-09-16 至 09-17 参照
《第2次Z再世篇》做的早期直接跳转原型见第 7 节；用户已决定采用的独立 native-tail-r5 方案见
第 8 节。现已接入 Original／Best 正式构建，默认开启；开关和当前实现见第 9 节。
第 1–7 节保留旧定格方案与早期原型的历史记录，不代表当前默认实现。

## 1. 旧定格方案结论

- 原版已内置：× 新按下跳过整场演出（先淡出，再回到地图）；○ 按住时逻辑节拍从每两帧
  一拍改为每帧一拍、精灵动画步长 1→2、等语音处直接停语音，实测整场用时约一半。
- 补丁新增：□ 新按下后，当前这条"行动"剩余部分在后台以每帧最多 15 拍执行，机体精灵
  不绘制、音效静音、GS 包增长受限；期间不翻转显示缓冲，画面停在按下时的一帧；行动下标
  变化后恢复翻页，直接切入下一段第一帧。每条脚本命令仍然执行，没有跳过任何状态更新。
- 每按一次 □ 跳过行动表里的一条记录。小队战里队员攻击和队长攻击是两条记录，需要按两次；
  ALL 攻击是一条记录；援护防御在记录内替换防御者，不增加次数；援护攻击是反击之后的独立
  一条；演出末尾按 □ 直接到结算，与 × 相同。

## 2. 引擎结构（Original 地址；BEST 对应地址见 `config/full-story-components.json`）

- 手柄：状态块 0x59C100，0x59C24C 当前按住、0x59C24E 本帧新按下。位定义：L2 0x1、R2 0x2、
  L1 0x4、R1 0x8、△ 0x10、○ 0x20、× 0x40、□ 0x80、SELECT 0x100、START 0x800、
  ↑0x1000 →0x2000 ↓0x4000 ←0x8000。
- 主循环状态 0x36/0x39 每帧调用 FUN_002E37F0：FUN_002F7760(0x6CEE00) 读输入 →
  FUN_003082B0(0x5F9D50) 世界步进 → 提交 GS 包；帧末 FUN_0016D3E8 翻转显示缓冲。
- 输入块 0x6CEE00：[0] 已到最终淡出、[1] 光盘异步读取中、[2] 快进、[3] 跳过请求
  （× 置 1）、[5] 帧计数、[6] 半速节拍。
- 世界步进执行每条行动各自的世界命令表（world+0xE0 起每项 8 字节，PC 在 +0x402），
  再对最多两个场景槽（world+0x3A80，步长 0x1160）执行场景脚本（结束标记命令 0x1F）。
  行动表 0x6D20D0（步长 0x1D4，类型 +0xC：1 队员攻击、2 队长攻击、3 结束），当前下标
  iRam006D2BCC，下标 0 为开场。
- 行动表由 FUN_00307440 从战斗信息块 0x5239B0 生成；战斗信息由地图侧 FUN_00258810
  按阶段（先手攻击、反击、援护攻击）经 FUN_0030AAD0 转换。hit 条目标志 0x8000 表示
  攻击者不是队长（队员攻击，进入类型 1 记录）；0xC0000 表示援护防御。
- 帧 GS 包缓冲从 0x49A6D0 直到 0x5238D0，约 549 KB，没有边界检查；正常一帧 30–110 KB，
  爆炸帧可达 180 KB。

## 3. 旧定格补丁实现（历史）

- 当时源码为 `tools/native/battle-square-skip/skip_hook.s`（旧版可查 Git 历史，现已换为 r5），按版本用 `--defsym` 注入地址后汇编；
  `assemble_hook.py` 只在开发时使用，生产构建只消费配置里的十六进制字节。
- 代码洞 0x3F6000（两版都是全零区）；补丁点四处：FUN_002E37F0 内的世界步进调用、
  FUN_002F7060 内的类型 0 精灵绘制调用、FUN_00180E80 音效入队函数前两条指令、主循环
  0x1438B8 的翻页调用。BEST 的对应位置由指令序列匹配得到，全局变量整体偏移 +0x800。
- 写入器 `tools/srwz/battle_square_skip.py`：要求代码洞前像全零、四处前像等于零售指令、
  或已完整安装（幂等回读）；其他状态失败。Original 在 `build_full_story_components.py`
  应用，BEST 在 `best_build.py` 的 ELF 编译中排除投影后按 BEST 契约应用；最终 ISO 回读在
  `verify_full_story_iso_content.py` 中核对。
- 状态块 CAVE+0x380：+0x14 每帧额外拍数 15、+0x28 包字节上限 0x30000、+0x30 静音开关、
  +0x34 跳过精灵绘制开关。

## 4. 走过的弯路

- 每拍后回卷包游标以节省内存会让 EE 卡在 DMA 等待超时并黑屏，先等 DMA 空闲再回卷也一样。
- 超过包缓冲上界会覆盖主循环状态并崩溃，因此额外拍数受包字节上限约束。
- 额外拍里连贴图上传（绘制类型 1–3）一起跳过会丢字幕字形，只能跳过类型 0。
- 黑屏方案下信息面板的队形图标层级高于淡出四边形，需要清零 0x1099/0x109A 门控；改为
  定格显示后不再需要。
- 代码洞内子程序调用必须用 `bal`，`jal 标签` 会被汇编成绝对地址 0x15C。
- 直接把脚本指针跳到结束标记理论上可把定格期从约 1 秒压到 0.3 秒，但会跳过分配切入、
  特效、语音缓存的命令，泄漏风险需要逐条审计，未采用。按 Z2 思路做的原型见第 7 节。

## 7. Z2 式直接跳转原型（仅记录）

2026-09-16 至 09-17 参照《第2次Z再世篇》（PSP 汉化 2.5，工作区根目录的 `SRWZ2/SRWZ2CHS2.5.iso`，不在仓库内）做了"直接跳到下一段"
的原型，未进入发布，当时生产补丁为第 3 节的定格方案。
本节保留旧 jump 系列的历史经过；当前已选定的实现及人工反馈以第 8 节为准。

### 7.1 Z2 的机制

- □ 在输入块 0x8EEC7B0 的字节 0 上切换跳过标志。等待型命令处理器（FUN_089BCB34 等全部机体空闲、
  FUN_089BCA68 等单个机体、FUN_089BD430 等语音）分别按其分支停语音、启动收尾或直接放行，
  推进世界命令 PC。FUN_089C268C 控制右下角跳过提示图形淡出，不是复位整个演出状态机。
- 每帧只执行一次世界步进，主循环、FUN_089BF5BC、FUN_089C4108 都没有循环，也没有快进。
- 强制收尾 FUN_089B8458 先清 unit+0x440/441/442（命令写索引、参数区索引、读索引），再用
  FUN_089B1EAC 建立 0x15、0x16、0x12 收尾序列。它不是在旧队列后单纯追加；“从不回退、天然幂等”
  的旧解释已由 2026-09-17 原始指令复核撤回。
- Z 的世界命令 0x11（FUN_003053D0）、0x2B、0x2C、0x2E 与 Z2 的正常等待结构相似；但资源等待、
  对象清理、位置恢复和命令编号不能直接照搬。Z 的同构队列追加原语是 FUN_002EBF10，详见 7.6。

### 7.2 原型做法

- 每帧世界步进调用（0x2E3DF4）处检测 □，置跳过标志并记下行动下标；下标变化时清标志。
- 六个等待处理器的序言改为跳到存根：四个"等场景空闲与语音"的命令，另加命令 0x0B（等单个
  场景标签变为 0x0F）与命令 0x03（等单个精灵 +0x450 变为 4）。标志置位时让等待条件当场成立，
  处理器本身照常推进。旧记录的 752/574 帧按队列槽位统计，不能归因于这两个命令，见 7.6。
- 场景收尾在写指针处追加结束标记 0x1F，读指针只前进；当前已是结束标记时不做任何事。
- 开场（行动 0）期间忽略 □，原因见 7.4。
- 文件中 0x3F6000 起有 4776 字节全零，原型用到 0x6A0，状态块在 0x3F6560。文件零区不等于
  运行时空闲区；后续已发现启动时会写入 0x3F6900，r5 的代码和状态均限制在 0x3F6000–0x3F67FF。

### 7.3 版本经过

| 版本 | 改动 | 结果 |
| --- | --- | --- |
| v1 | 四个等待处理器挂存根，标志置位时截断场景队列 | 存根调用子程序前未保存 $ra，处理器返回进存根无限重入，EE 卡死 |
| v2 | 修正 $ra | 攻击段 32 帧；实机：首场有机体残帧，开场与敌方攻击段按 □ 无反应 |
| v3 | 收尾后立即清标志，照抄 Z2 | 一条行动有多个等待点，只解开第一个，退化到 592 帧，放弃 |
| v4 | 收尾限定在按下时的行动 | 与 v2 行为相同 |
| v5 | 补命令 0x0B、0x03；开场每帧最多 8 拍且跳过类型 0 绘制 | 各时机都能响应；头像位置出现未初始化显存噪点 |

### 7.4 结论与教训

- 最初实现覆写队列槽 0 并把读写指针归零；改成向前跳后，读指针从"3→0、1→0"变为"3→5、1→3"，
  已有路线的画面和手感改善。这是实测事实；但 Z2 自身也重置队列，因此“回退本身就是根因”和
  “追加已经完整移植 Z2”都不能作为定论。"拉幕转场可见"和"跨动作截断"两个旧解释仍已撤回。
- v12 禁止开场跳过是已有取舍，不是已经证明开场固定 96 帧不可压缩。实际开场世界队列没有
  命令 0x01；资源加载、sprite 就绪与淡入完成需要分别追踪。用户在本轮重做前以 v8 为最佳体验基准，
  但冷启动前几场仍可能显示异常，具体时序原因待验证。
- 跳过绘制、降低步数和缩短淡入的实验均出现过画面或体验回归。单帧包峰值、跳转耗时和少量截图
  不能代替逐帧画面、加载状态与人工试玩证据；“缓存预热后改善”尚不能定位到某一层加载。

### 7.6 Z / Z2 与 PS2 执行约束复核（2026-09-17）

本轮仅做静态代码、原始指令与历史 RAM 重分析，没有新增模拟器或 PS2 运行。上述修正以
`work/analysis/battle-skip-z2-review-20260917/README.md` 为依据；脚本 `audit_evidence.py`
通过 17 项证据断言，并重读 12 份 RAM 和 v8/v12 观测。

- Z2 的 `0x15 → 0x16 → 0x12` 含相关机体对象的清理标记、位置恢复参数和终态。Z 的
  `0x21 → FUN_002FF3F0 → FUN_002FDCC0` 有对应清理标记；直接把场景 PC 移到 `0x1F` 会越过
  中间命令，未证明与完整收尾等价。
- Z2 `world+0x3E2` 对应 Z 的 `world+0x402`（世界命令 PC），不是 `0x6D2BCC`（战斗行动下标）。
  同一行动中会重建队列，等待统计需按实际 tag/队列代次区分，不能只按 slot 聚合。
- Z 的 0x03 等待资源请求/解析/对象初始化完成到状态 4；0x0B 会建立准备队列并等到 0x0F。
  两个 helper 强写完成状态可能绕过必要工作，但已有 v8/v12 路线的计数均为 0，尚不能据此归因
  用户实际遇到的冷启动异常。
- v8 的开场 8 次世界步进共用一次外层输入/半速节拍采样，且世界步进包含绘制。多步不是正常帧
  的等价重复，必须同时考虑异步资源、对象生命周期、GS 包预算与显示翻页，不能只比较步数。
- 下一实验方向：资源等待保持真实完成条件，跳过请求可保留至安全阶段；按 Z 的对象结构补足
  收尾，并分别比较 v8 与原定格方案。短暂定格只可作为隐藏中间态的候选，不能替代实际就绪条件。

## 8. native-tail-r5 原生收尾方案（2026-09-17，已决定采用）

在上述复核后独立实现 native-tail-r5，编号与旧 jump-v8/v12 无关。用户试玩后明确表示采用当前
方案，未感觉到问题，并认可跳过后仍能看到武器伤害效果和数字。后续正式接入与 Best 适配以
这份成品为基准，保留当前行为，不再为压缩剩余转场时间继续修改算法。

- □ 请求绑定当前行动；资源加载忙时保留请求，等待原生加载完成。每显示帧仅调用一次世界更新。
- 对已识别的场景末尾 `[0x21, 0x1E, 0x1F]`，先执行已有清理命令，再在清理完成后越过动画等待；
  使用队列代次及对象身份约束收尾，未知队列继续原生快进。
- 世界后续结果、分支及转场处理仍执行。伤害效果和数字的保留是用户认可的体验；这份反馈不代表
  所有武器路径、伤害计算字段或平台均已验证。
- 17 项成品机器码测试、4 项写入器测试及 ISO 完整读回通过。有限路线 LRPS2 软件渲染验证中，
  演出入口至返回地图由不跳过的 2517 帧缩短到 1048 帧；两次 r5 运行共 8202 帧不可变代码检查通过。
- 人工试玩已获认可，但平台/渲染器未注明。该原型镜像仅支持 Original；后续正式构建接入与
  Best 适配见第 9 节。

源码、构建器、测试、成品与详细证据位于不入库的 `work/analysis/battle-skip-native-tail-20260917/`，
入口为 `README.md`。选定镜像为 `native-tail-r5.iso`，SHA-256：

## 9. 正式构建与开关（2026-09-17）

`config/full-story-components.json` 的 `battle_square_skip.enabled` 为构建开关，默认 `true`；
省略该字段也默认开启，仅接受 JSON 布尔值。设为 `false` 后构建出的镜像保留零售版的 □ 行为，
不安装跳段 hook，× 整场跳过及 ○ 快进保留。这是构建选项，不是游戏内菜单选项。

```json
"battle_square_skip": {
  "enabled": true
}
```

上例仅展示需要调整的字段，其余契约字段应保留。调整后使用正常构建入口：

