# 真唱 BGM 替换研究（2026-11-05）

结论：已用 `/Users/nate/gba-sound/test.mp3` 的 30–50 秒片段，在 Original 中文候选 ISO 内通过原生音乐选择播放、循环、重播并退出恢复资料库音乐。证据为 ARMSX2 runner 冷启动及实际 SPU2 混音录音。**这证明短片段采样替换可行，不代表整首真唱、战斗中播放或正式发布已完成。**

## 已验证的资源与加载路径

直接核对当前 Original ISO 的 `BGM/BGM.BIN`，大小 174400528 字节，SHA-256 为 `0f277113b854e6730edd27b6d734812744837e3670d7f61eaeda2a48e30da362`。

102 个曲目项是 Sony PS2 的 SQ 演奏序列、HD 乐器定义、BD PS ADPCM 采样库组合，不是每曲一个可直接替换的 MP3/ADX 流。当前静态文件中所有 102 项的 SQ/HD 签名与 ELF 偏移表均已核验，完整偏移见 [bgm-layout.json](issue-assets/vocal-bgm-20261105/bgm-layout.json)。包含空曲/占位项，不等于 102 首非空音乐。

Original ELF 地址：

- `0x411b20`：曲号重映射表。
- `0x411b88`：表头；真正偏移项从 `0x411b90` 开始，每曲三个偏移 SQ/HD/BD，下一项 SQ 为结束位置。
- `FUN_00189b70`：异步 BGM 加载状态机；状态 1/2/3 分别载入序列、定义、采样，状态 4 注册乐器、音量并播放。BD 被上传到 SPU 地址 `0x5010` 起的区域。
- `FUN_00181350`：普通 BGM 请求入口，包含同曲判断、停止旧曲、队列及状态切换；正式扩展应保留这些语义。
- `FUN_00189600`：另一条同步载入路径，同样一次载入 SQ/HD/BD；不能把此处读取分段误认为持续音频流播放。

格式字段参考开源 [VGMTrans SonyPS2Seq.cpp](https://github.com/vgmtrans/vgmtrans/blob/master/src/main/formats/SonyPS2/SonyPS2Seq.cpp) 与 [SonyPS2InstrSet.cpp](https://github.com/vgmtrans/vgmtrans/blob/master/src/main/formats/SonyPS2/SonyPS2InstrSet.cpp)，结论以本地二进制和运行实验为准。

候选 ISO：`build/iso/test/vocal-bgm-sample.iso`，通过 APFS clone 创建。生产镜像未写入；全部 ISO 成员 LBA/大小保持不变，BGM 第 0 首槽以外字节逐字节一致。实验只覆盖 Original；Best/SP 的可移植性尚未当前运行验证。

## 整曲方案选择

整首测试文件转换为 PS ADPCM 的容量估算（不含容器/对齐开销）：

| 音质配置 | 整曲大小 | 持续读取速率 | 第 0 首原 BD 槽可容纳时长 |
| --- | ---: | ---: | ---: |
| 22.05 kHz 单声道 | 2.66 MiB | 12.6 kB/s | 75.91 秒 |
| 32 kHz 单声道 | 3.85 MiB | 18.29 kB/s | 52.31 秒 |
| 32 kHz 双声道 | 7.71 MiB | 36.57 kB/s | 26.15 秒 |
| 44.1 kHz 双声道 | 10.62 MiB | 50.4 kB/s | 18.98 秒 |
| 48 kHz 双声道 | 11.56 MiB | 54.86 kB/s | 17.44 秒 |

声内存总共 2 MiB（本地 runner `pcsx2/SPU2/defs.h` 的 `_spu2mem`），还要容纳音效、语音缓冲等。即使扩大 ISO 槽，整首这些配置也不能作为一个常驻采样装入声内存。所有现有曲目 BD 最大约 1.02 MiB（1064928 字节）；第 0 首槽的时长数字是本槽预算，不是全局硬件上限。

建议分成两种产品能力：

1. **短版副歌/循环真唱：沿用原生采样库。** 已有运行证据，改动面小；下一步做高质量预测编码、双声道 program/split 配置、音乐性循环接缝、原序列循环边界及战斗语音并发测试。必须逐曲计算原槽容量，不强行挤入整曲。
2. **完整歌曲：新增独立 BGM 流式通道。** 离线将 MP3 转成 PS ADPCM，按扇区与 ADPCM 块对齐存储；IOP 分块读盘，SPU 双缓冲/环形缓冲，EE 的原 BGM 请求转交播放、停曲、淡出、恢复、同曲续播和循环位置。44.1 kHz 双声道约 50.4 kB/s，带宽估算不等于并发读盘已通过。缓冲大小与音效/语音资源争用要根据实际驱动分配确认。

游戏已存在 CCC 语音播放路径和声音 RPC/缓冲机制，是流式驱动研究入口，但**本轮未证明可无冲突地借用其通道播放 BGM**。不能直接占用战斗语音通道，否则真唱与台词可能互相打断。新增资源布局需要单独设计 ISO 空间和目录/偏移更新，不能向固定槽末尾越界写入。

模拟器外部播放器同步可做专用客户端实验，但依赖模拟器且另需处理暂停、倍速、即时存档和同曲恢复；当前目标若是可分发 ISO，应优先游戏内通道。未实现或验证外部播放器方案。

## 追加：开源音频实现选型

- [PS2SDK audsrv](https://github.com/ps2dev/ps2sdk/blob/master/iop/sound/audsrv/src/audsrv.c)：提供 PCM 环形缓冲、双缓冲传输；EE 接口另提供 ADPCM 样本播放。可参考流式实现，但初始化调用 sceSdInit(SD_INIT_COLD)，不能未经适配直接并入原游戏声音驱动。
- [PS2SDK libsd](https://github.com/ps2dev/ps2sdk/tree/master/iop/sound/libsd)：底层 SPU2 控制接口，适合参考声部和 DMA 管理；本身不是通用音频解码器。
- [psxavenc/libpsxav](https://github.com/WonderfulToolchain/psxavenc)：离线 SPU-ADPCM 编码器，支持 raw/VAG；编码实现搜索预测滤波器和量化参数来减小误差。仓库已归档，但源码可用。其自定义交错 VAG 头不能默认被《Z》识别，需按原 BD/HD/SQ 格式封装。

建议优先改善离线编码，并保留《Z》原声音驱动；如需长音频再研究与语音、音效及资源读盘共存的流式实现。尚无本项目测量支持“加载现成库即可无损或提升音质”的结论。

## 曲库统一存储与用户网页工具规划（草案，未实现）

目标：用户在本地网页选择自己的歌曲，部分或全部替换游戏 BGM；音乐项目独立于汉化版本保存。此节是后续设计，不表示现有单曲实验已经从音乐容器读盘或已有音乐导入网页。

### 逻辑文件与物理分配

规划镜像内唯一容器为 `BGM/VOCAL.BIN`，由版本化二进制头、曲目索引、2048 字节对齐的 Ogg 数据构成。整库共用空间，不为每首歌划定 2 MB 固定槽，也不将用户歌曲嵌入 ELF。容器名称、格式版本和稳定曲目 ID 是工具与播放器的接口；物理 LBA 由各发行版本的构建配置决定，不能照搬 SP 地址到 Original/Best。

建议首版固定容量 512 MiB（536,870,912 字节），包含头和索引。按 101 首、平均 4 分钟估算，64 kbps 约占 193.92 MB，128 kbps 约占 387.84 MB。网页以实测编码大小核算，64/96/128 是平均码率目标，不保证每首大小固定。默认目标 64 kbps，保留较高质量选项与试听。

第一阶段使用镜像尾部新建的独立音乐区。当前 SP 镜像为 3,918,850,048 字节，增加 512 MiB 后约 4.46 GB，另计小量运行时代码与元数据；正式构建须检查最终容量限制。已有重定位器只能移动已有成员，新增目录记录、UDF file entry 与 VMAP 条目需要在本地构建端实现并验证。全部原有游戏资源 LBA 保持不变。

当前 SP 与 Original 的 DMY 文件均为 122,558,928 字节，单独不够上述全曲库预算。Original 已审计的大块前部填充可作为未来分配候选，但不能把其运行时结论直接视作 SP/Best 的证据。各版完成专门审计后，可以把同名容器分配到合适的留白区而不改变网页或音乐包接口；本草案不固定或占用未验证的留白 LBA。

### 基础补丁与用户定制分层

提供带播放器、完整目录记录和空容器的“支持自定义音乐”基础镜像/补丁。容器长度与分配区固定，空索引意味着全部播放原曲。补丁可用重复/零填充编码表达空空间，不要求下载等体积的零数据；实际补丁大小以生成结果为准。浏览器只在已声明的音乐容器范围内重建索引和 Ogg 数据，不修改文件长度、资源 LBA、ELF 或 ISO/UDF/VMAP 目录。

保留原始 BGM.BIN 内容。必须先把当前实验中永久清零第 19 首 SQ 力度的做法改为运行时选择：有有效替换项才转入 PCM 播放；未配置、停用、打开失败或验证失败时按原生路径播放原曲。播放器与 web 工具共享格式版本、边界检查、编解码约束和曲目 ID；Z/SP 使用各自的游戏曲目映射配置。

二进制索引至少包含稳定曲目 ID、有效标志、相对文件偏移、有效字节长度、采样率/声道/编码标识、解码总帧数、循环起止帧、音量增益、内容校验。名称与编辑项目使用外部 JSON，EE 不解析用户 JSON。实际字段宽度、表容量和 ABI 编号在实现容器读写器与一致性测试后再冻结。

### 网页与便携音乐项目

复用 `srwz-patch-web` 的本地流式 ISO 处理与输出方式，新增独立音乐编辑入口（路径待实现，不代表已上线）。流程为识别支持的基础版本、列出游戏曲名、用户分配本地音频、编码/试听/调节音量及循环、显示总容量、生成新的自定义 ISO。无需上传 ISO 或音乐。编码按单曲在后台任务中完成；大文件输出继续分块，不能沿用把整份 4 GB 以上 ISO 拼成 Blob 的方式作为主路径。不支持流式写出的环境至少能导出音乐项目包；浏览器与编码器兼容性需要实际测试。

可导出独立音乐项目包（工作扩展名 `.srwzmusic.zip`）：版本化 `manifest.json` + `tracks/<stable-id>.ogg`。包含用户分配、循环和音量设置，不包含整个 ISO；原始 MP3 可由用户自行保留，不强制打包两份。输入文件名用于显示，不充当曲目识别主键。汉化升级后将同一音乐项目重新导入新版支持音乐的基础镜像；兼容性依据曲目目录和播放器 ABI，而非旧版物理偏移。

现有网页补丁器用完整目标 SHA-256 验证官方成品。个性化 ISO 不能继续声称匹配官方完整哈希：首次导入先验证官方基础镜像；再次编辑时验证对应版本的不变区域、容器位置/容量以及音乐索引和内容校验，再生成用户自己的结果 SHA-256 与可导出收据。只信容器中自报的 base-version 字段不够。

### 实施顺序与验收

1. 将 SP 单曲从 ELF 移到 `VOCAL.BIN`，以路径/容器相对偏移读取；保留现有 EE 解码与 DMA 1 输出成果。
2. 实现有效曲目选择、原曲回退与多曲切换，并验证一首、部分曲库、空容器、坏索引、越界、失败回退、重入和播放停止。
3. 初期可在受验证的单曲内存上限内预载当前曲；网页按发行配置限制单曲输入。随后改为压缩输入预取/循环缓冲，实测与战斗读盘、台词流同时工作。不能把容器总容量当成当前单曲可用 RAM，也不能声称当前已支持任意时长。
4. 实现本地打包器与浏览器共用格式/测试向量，验证容器外逐字节不变；建立空音乐基础镜像后再接网页导入与导出。共享格式不要求第一步就移植整个 ISO 文件系统写入器到浏览器。
5. SP 验收后分别接 Original/Best；每版都要单独识别、边界验证和 ARMSX2 运行证据。

本轮仅规划存储及工具边界，未改动现有测试 ISO、播放器、网页站点或线上部署。
