## 1. 先分清三种“标签”

| 层 | 例子 | 处理责任 |
| --- | --- | --- |
| 资源字段标签 | `DSCR`、`DSC2`、`PRDC`、`CHFN` | 决定文本属于哪个面板、使用哪个基准；不是直接发给绘制器的内联指令 |
| 工具的无损文本记法 | `<width:0E>`、`<35:0E>`、`{12}`、`<-<height:3E>` | 把原始字节表达成可编辑字符串；记法名字不能替代语法上下文判断 |
| 原生／上层运行协议 | `32 0E`、`<-3>`、`%02d`、`$n`、`@N` | 原始字节先由所属消费者解释；有些在上层展开，有些直接影响绘制 |

所有 `<...:XX>` 参数均为十六进制。例如 `15` 是十进制21，`16` 是22；`0E` 是14。`<space:XX>` 表示横向推进，并不是插入一个空格；`<color:XX>` 的原生直接作用是纹理／调色选择字段，不等于直接设置RGBA。

`CONTROL_NOTATION` 的正则命中只表示工具把它保护成一个片段；不等于已经证明其运行语义、能独立写盘或可以任意生成。编码器允许两位十六进制标签名作为原始操作码出口，也不等于这些组合已经获准用于普通正文。

## 2. 全部现行控制记法的处理方案

### 2.1 工具层控制符与结构标记

权威实现：[text.py](../tools/srwz/text.py)。`control_notation_tokens()` 按 `raw_byte`、`runtime_format`、`runtime_substitution`、`text_tag` 分类；`encode_text` 在普通字形覆盖之前处理完整运行控制片段。

| 家族 | 例子 | 当前处理 | 限制／后续规则 |
| --- | --- | --- | --- |
| 四个命名尺寸／样式记法 | `<color:03>`、`<width:0E>`、`<height:8C>`、`<space:0C>` | 分别写出 `31/32/33/34 + 参数`；原始码表只有这四个命名别名 | 先识别是否嵌在复合协议中；不能对全文盲目替换height/space |
| 未命名双字节操作记法 | `<35:0E>`，以及编码器接受的 `<HH:XX>` | `35`是纵推进；数值标签由编码器写出对应两字节 | 默认保留原生顺序；其他opcode需按消费者审计，不能凭可编码就新增 |
| 原始字节 | `{12}`、`{00}` | **优先**解析成一个原始字节；`{12}`是0x12，不是“参数12” | NUL／LF可能触发上游截断／拆行；不自动当可见字形，也不自动批准未知字节 |
| 内联数值选择器 | `<0>`、`<8>`、`<10>`、`<-3>` | 整段恢复为原始ASCII协议字节，绕开字形覆盖 | 不把所有选择器叫作按钮；保留正负号和编号，不按英文数字收窄 |
| 选择器的无损混合记法 | `<-<height:3E>`、`<<color:30>>` | 分别恢复 `<-3>`、`<10>` | 内部的height/color在这里表示ASCII字节对，不能作为真实字号／颜色指令改写 |
| 数值花括号复合协议 | `{4.4.0}`、`{<space:2E><space:2E>0}` | 整段保留原生ASCII字节；后者恢复为前者 | 具体每个数的完整样式语义仍不能只凭标签名认定；两位纯十六进制形式优先属于原始字节 |
| 数值方括号协议 | `[4]`、`[<space:5D>` | 整段恢复为原生ASCII字节；不再将内部space误当推进93 | 不对全部参数臆定含义；静态排版要求所有者专用合同，不与可见全角方括号混用 |
| printf格式串 | `%s`、`%2d`、`%02d`、带位置／精度／标志的格式 | 整体保护并写出原生字节，包括 `%0<width:64>` 等混合记法 | 不收窄内部数字、百分号或格式空格；动态结果宽度按调用者约束，不按源字符串长度 |
| 美元变量 | `$c`、`$f`、`$l`、`$n`、`$F` | 共享编码器识别这五种大小写敏感形式并保持原始字节 | 普通布局通常保守预留六格；不是所有变量真实长度已证明为六格；其他`$X`不能凭布局识别推定编码支持 |
| `@`前缀／重复符号 | `@N`；解码可能出现`@<height:XX>`等 | 已发现专用包装：以`@`开头时读取十进制计数并走缓存重复符号路径 | 不是通用内联字号语法；当前编码器整段恢复原始字节（包括解码器吸收的末尾NUL），静态排版明确分流。保留所属资源路径，动态几何仍逐消费者核对 |
| 动态模板外壳 | `＜ｔｍ＞…＜／ｔｍ＞`；工具也保护ASCII `<tm>…</tm>` | 图鉴排版边界识别完整块，已有SP模板保持原样 | 不是普通正文HTML；当前语料扫描有全角形式，不能强行转换两种形式。模板展开宽度／编码合同未全部闭合 |
| 双尖括号片段 | `<<…>>` | 图鉴编译器将其作为边界保护 | 不与`<<color:30>>`等复合协议混淆；未知内容按所属格式处理，不宣称通用编码器支持任意双尖括号 |
| 关键词括号 | `《…》` | 只有显式启用`stage_keyword_links`的路径按关键词标记计宽 | 其他文本面仍可能是可见书名号，不能全局删除或当零宽 |
| 实际换行／字面转义 | 实际LF、字面`\n`、`\r`、`\t`、`\uXXXX` | 实际LF由共享编码器写0A；图鉴编译器保护这些字面转义边界；战斗等格式有独立转义规则 | 字面反斜杠+n不等于通用编码器的实际换行；不能统一`replace`后写全部资源 |
| 普通可见空格／空白占位行 | 词间空格、U+3000、原生多空格行 | 双字节文本面用`two_byte_visible_spaces()`在存储边界转为8140；控制协议内格式空格保留ASCII | 滚动占位行必须保留原生顺序、数量和每行空格数，不能`strip()`清空或压缩 |

完整控制字节保护使用 `runtime_control_bytes()` 与 `verify_runtime_control_bytes()`：不仅比较解码文字，还比较**有序控制片段实际字节**。独立校验目前明确接入SP相关系统文本／模板／ticker回读；不能把这些局部接入泛称为所有资源均已覆盖。历史修复及反例见[控制编码审计](CONTROL_SEQUENCE_ENCODING_AUDIT_20261006.md)。

两个必须保留的反例：

```text
原生 <-3>          = 3C 2D 33 3E
无损记法           = <-<height:3E>
错误改写负号后      = 3C 98 68 33 3E  （解码文字仍可能一样，协议已坏）

可见 99% 的恢复顺序 = 99%<space:15><width:15>...
不要生成            = 99%<width:15>... （可能被识别成格式串的混合记法）
```

当前单元格和像素路径共用`control_layout.py`：数值角括号按一个图标格预留，美元／格式替换按六格，样式花括号／原始字节／尺寸标签不计普通可见格。这是工具预算；实际动态结果与不明原始字节仍要由资源所有者验收。tm、@与数值方括号明确禁止误入普通静态重排。

### 2.2 当前原生绘制器的完整控制分派

以下为已还原的主解析器直接动作。不是对所有上层格式的完整说明。`F`为字体状态：Original `46E330`、Best `46EB30`、SP `4ED5B0`。显式W/H/DX/DY为`F+14/16/18/1A`；数字专用W/H/DX为`F+2C/2E/30`。

| 原始字节／内部码 | 原生直接动作 | 工具／排版使用原则 |
| --- | --- | --- |
| `00`→内部`2F` | 替换期间返回原串，否则终止 | 不在C串正文中随意嵌入00参数；上游strlen可能提前截断 |
| `0A`→内部`2E`；分派槽`2E` | x回到行初始值，y加临时DY | 图鉴上游还按字节找0A；原始ASCII点不能直接作为普通字形写入 |
| 分派槽`2F` | 结束／返回替换串 | 裸ASCII斜杠不能作为普通双字节正文写入 |
| `30` | 调原生初始化，额外消费一字节 | 不等于完整恢复所有临时scratch；不能用它替代闭合作用域 |
| `31 xx` | 写`F+1C`，影响主字形纹理选择高字段 | 标签别名color；RGBA／描边另有状态及样式函数 |
| `32 xx` | 写显式W和临时W，分类开关清零 | 同时处理字形右边缘；恢复W不代表恢复DX/H |
| `33 xx` | 写显式H和临时H，分类开关清零 | 现行补丁还解码8A..8E并设置光学标志，见第4节 |
| `34 xx` | 写显式DX和临时DX，分类开关清零 | 控制游标推进，不是增加空格 |
| `35 xx` | 写显式DY和临时DY，分类开关清零 | 不作为普通段落的空行替代，不自动注入 |
| `36 xx` | 写`F+32`，数字／符号纹理选择 | 属于专用数字／符号状态，不把它当正文color的同义词 |
| `37 xx` | 写数字字宽`F+2C` | 不替代正文width |
| `38 xx` | 写数字／符号字高`F+2E` | 不替代正文height；正文中存储的可见数字也未必走专用数字生成器 |
| `39 xx` | 写数字横推进`F+30` | 供数字布局及右对齐，不替代正文space |
| `3A`、`3B`、`3C`、`3D` | 保存返回指针并进入各自替换缓冲区 | 原生裸`<`会进入3C槽；`<编号>`的完整语义还涉及上层处理，不将`$n`等强行对应某个槽 |

替换返回指针是单层状态，不是任意嵌套栈；替换串首字节的处理也有特殊路径。专用十进制、负数占位符、`@N`缓存绘制可以绕开正文解析器，分别读取不同尺寸组。样式表函数主要写palette、RGBA、outline，不等于改字号。完整细节和执行域保留在持续反编译记录第4–10阶段。

### 3.2 编译、作用域与混合标识符

实现：[library_typography.py](../tools/srwz/library_typography.py)。当前处理顺序：

1. 规范化可见全角英数的逻辑身份，保留大小写、数值、标识符；生成旧作用域先还原为逻辑文字再编译，保持幂等。
2. 在图鉴正文中将旧`16/16`基准／恢复迁移为`15/15`；仅在正文把原始字高0A转换为安全8A。
3. 保护复合控制片段、模板、双尖括号和字面转义，识别可收窄英数／符号段。
4. 图鉴允许G、14等短段收窄；这区别于通用`compact_visible_runs()`的至少3个可见字符门槛。
5. 一个混合型号只开闭一次W/DX作用域，内部按字母／数字切换H，防止布局器将型号拆开；标点继承前一段，括号及希腊／罗马符号按段内默认类别处理，不声称每个符号均已光学校准。
6. 可见百分号后的恢复顺序为space→width；最后恢复本域H，关闭光学标志。
7. 校验去掉工具控制记法后可见文字不变；生产仍需检查最终编码字节、槽容量、指针和压缩边界。

当前角色例子（由快照脚本直接调用生产函数生成）：

```text
中文<width:0E><space:0C><height:8C>RX-<height:0B>78<height:8C>F<height:0B>14 99.9%<space:15><width:15><height:0C>中文
```

`8C`与`0C`的实际H都为12，但前者还要求record Y−1，后者关闭该光学效果。两者不可因为“高度相同”而合并。正文中的字母／数字来自双字节字形码，并不因内容是数字而自动转入`37..39`的专用数字队列。

## 4. 原来代码究竟改了什么

### 4.1 原问题与分工

原生行初始化主要更新分类尺寸，未同步所有显式尺寸。先显示作品字段，再由正文width/space切到显式模式时，可能继承前一字段H。旧工具又把正文恢复到22而非原生21。因此根因有两部分：**原生每行初始状态不完整、工具恢复参数和域不一致**，不能只删几个控制符解决。

现行方案分为两个原生patch owner和一个工具owner：

| owner | 修改位置／行为 | 范围 |
| --- | --- | --- |

### 4.3 安全字高与光学Y契约

| 33的参数 | 解码H | 光学标志 | 用途 |
| --- | ---: | ---: | --- |
| `8A` | 10 | 0 | 避免正文出现原始LF值参数0A，供机体中文／数字恢复 |
| `8B` | 11 | 1 | 当前机体字母 |
| `8C` | 12 | 1 | 当前角色字母 |
| `8D` | 13 | 1 | 保留支持；上一轮角色字母 |
| `8E` | 14 | 1 | 保留支持；较早候选角色字母 |
| 其余251值 | 原值 | 0 | 保留原H参数语义；例如0B是当前角色数字、0C是角色中文恢复 |

光学标志在每次解析入口清零，在height控制时重新设置；仅改变最终record Y，不改pen、DX或DY。**width/space的恢复不能替代height恢复来关闭光学效果**。`30`重置的缓存／scratch语义也不等于重新开始一行，不能当作通用作用域关闭符。

原生图鉴按字节找LF，并经strlen等上游层处理；它不知道0A是某个height的参数。因此`33 0A`即使低层能设置H10，也会被上游拆成行。这就是8A存在的原因。类似地，NUL参数可能被更上层截断，不能认为低层接受就能安全穿过整条资源链。

历史的[library_height_restore.py](../tools/srwz/library_height_restore.py)保留8A单值方案和旧证明；**当前生产只组合body metrics＋optical metrics**。两个height patch占用相同处理器及尾区，不能把旧safe-height补丁先后再叠加到现行optical补丁上。

## 5. 后续排版方案与实施顺序

### 5.1 继续使用的生产流程

```mermaid
flowchart LR
 A[审定逻辑文本与资源归属] --> B[保护运行控制与模板]
 B --> C[按字段及域生成闭合作用域]
 C --> D[按profile计宽与断行]
 D --> E[双字节编码与槽容量检查]
 E --> F[版本独立原像补丁及构建]
 F --> G[ISO文本与控制字节回读]
 G --> H[LRPS2指定页面验证]
```

具体要求：

1. 先绑定原盘资源、字段、显示面、调用者和版本；后续不要从作品名猜正文基准。
2. 保留逻辑英文、数字、标点用途和控制顺序；可见英数写原生双字节字形码，可见空格写8140，协议ASCII保持原字节。
3. 图鉴继续由编译器生成尺寸段，不手工向大量译文填8A/8C。原有手工控制保留来源，改旧段时只剥离工具自己拥有的作用域。
4. 按实际推进累加，整行再换算格预算，同时检查最后字形右边缘；H和Y不参与水平长度，但它们的控制字节参与存储容量和原生解析。
5. `RX-78F14`等闭合混合段保持原子性；保词、禁则、变量预留、续行缩进和行数约束同时成立。超长不可拆段不能靠删字符或静默截断解决。
6. 滚动正文分段／原生空格占位行单独保存；实际空行、8140占位行和未使用字格填充不能互相替代。见[占位符合同](SCROLLING_TEXT_PLACEHOLDERS.md)。
7. 编码结束独立检查实际控制字节、NUL、LF、双字节槽、指针、共享引用、压缩长度及后续LBA；文字回读一致不能替代控制协议字节一致。
8. 三版分别读回、分别运行。LRPS2页面样本、隔离RAM实验、整数／Unicorn模型及静态检查各自记账，不用一种证据代替另一种。
