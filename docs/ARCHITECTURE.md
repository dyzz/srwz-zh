# 工程架构

## 数据边界

工程将数据分为三层：

1. `rom/` 和 `work/`：用户本地的原版及解包数据，永不提交。
2. `corpus/`、`config/`、`patches/`：中文工程的可审查源数据。
3. `font/generated/` 和 `build/`：从源数据生成的产物，永不作为唯一来源。

## 构建流水线

```text
原版校验
  -> 提取与 round-trip 校验
  -> 日文语料基准
  -> 中文译文与术语检查
  -> 字符集和字形生成
  -> 中文断行与空间检查
  -> 文本、字库和 ASM 回插
  -> ISO 重建
  -> PCSX2 运行验证
  -> 补丁打包
```

每个阶段都应产生清单或测试结果。任何缺字、无法编码字符、文本池溢出、超过最大行数或来源哈希变化都必须令构建失败。

## 上游集成

上游仓库只作为固定版本的逆向参考。中文工程应通过适配器调用或逐步重写所需能力，避免依赖上游工作树中的未提交状态。

未来若确认授权并需要同步上游，可将其作为只读 submodule 放在 `vendor/upstream/`，并同步更新 `config/upstream.lock.json`。
