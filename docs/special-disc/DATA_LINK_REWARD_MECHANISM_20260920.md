# SP Data Link 奖励机制与默认双路线策略

2026-09-20。依据原版 `SLPS_259.20` 的静态控制流、原始奖励表、原版 COMPDATA
零件名称，以及 Unicorn 执行原始指令片段的结果。

## 当前中文版本策略

按用户要求，当前 SP 默认启用 Z 男、女两条路线的通关奖励，不检查 Z 存档。
进入剧情模式时，两个 SP 状态副本的低两位执行 `|= 3`，并启用两个奖励开关；
其他位保持原值。新 SP 状态与已有 SP 状态均经过同一入口。

- 新开始一组剧情时仍由玩家选择是否领取，奖励数值沿用下表“双路线”列。
- SP 自身五组剧情的通关判断、对应奖励表和发放代码保持原样。
- “数据链接”入口改成说明页，确认后返回剧情选择，不进入 Z 记忆卡读取流程。
- 已经进行中的关卡不自动补发；奖励仍在原生的新剧情开始分支发放。

## 原版机制结论

Data Link 将 Z 系统数据中的男女主角通关标志合并到 SP 状态；新开始一组剧情、
选择领取奖励时，按该组剧情的固定表发放奖励。它不按 Z 的资金余额、PP 总量、
改造程度、等级或周目次数计算继承比例。

以下均为 **Z 联动追加量**，不含该剧情的初始资源及 SP 自身通关奖励。
PP 是逐条加到驾驶员记录上的数值，不是全员共同分配的总额。

| 开始的剧情组 | 每条 Z 通关路线：资金 | BS | 每名驾驶员 PP | 男女两条都通关时：资金 / BS / 每名 PP |
| --- | ---: | ---: | ---: | --- |
| 另一面记录 | 1,000,000 | 1,000 | 1,000 | 2,000,000 / 2,000 / 2,000 |
| 幕后回忆 | 1,000,000 | 500 | 1,000 | 2,000,000 / 1,000 / 2,000 |
| 荣耀之星报告 | 1,000,000 | 1,000 | 1,000 | 2,000,000 / 2,000 / 2,000 |
| 比特维修公司业务日志 | 1,000,000 | 1,000 | 1,000 | 2,000,000 / 2,000 / 2,000 |
| 秘密后日谈 | 2,000,000 | 2,000 | 1,000 | 4,000,000 / 4,000 / 2,000 |

每组剧情的零件奖励相同：

- 男主角路线：超级干扰器 `ハイパージャマー`，ID 17，1 个。
- 女主角路线：防护力场 `バリア・フィールド`，ID 16，1 个。
- 两条均有：各 1 个。没有第三条“双路线额外奖励”记录。

重复链接同一记录不会增加奖励次数；先链接男线、后链接女线可以合并为双路线。
已经记录双路线后，再链接只有一条路线的系统数据，不会把另一条清除。
这里证明的是内存状态的合并规则；实际系统存档落盘与重启恢复未做本次整机验证。

## 输入与通关标志

原版 ELF SHA-256：
`9c345c4a19e7abd791b00af707fe1f44086da6b1b21b8a4344a5872b307c5101`。
下文地址均为 EE 虚拟地址；此文件对应区段 `VA = file offset + 0xFF680`。

- `0x4409B0`：Data Link 记忆卡读取状态机。
- `0x440B3C–0x440B88`：组合 `/BISLPS-25887Q/Z.BIN` 路径并打开。
- `0x440C7C–0x440CDC`：另一分支组合 `/BISLPS-25887Q/BISLPS-25887Q`。
- `0x440D68–0x440D7C`：读取 `0x1D8` 字节到 `0x763FC0`。
- `0x31B8F0–0x31B900`：读取 `0x764185`，即输入文件相对偏移 `0x1C5`，
  取低四位，再分别用 `& 1`、`& 2` 生成男女路线确认界面。
- `0x438010` 的界面使用男／女路线文案；奖励说明列表的原版标签表在 `0x4A43F0`，
  第 0、1 项分别为男、女主角路线。

确认应用后，`0x31B970–0x31B9D4` 等价于：

```c
incoming = loaded_z_system[0x1C5] & 0x0F;
if (incoming != 0) {
    byte_at_0x5DC546 |= incoming;  // 保留原高四位
    byte_at_0x612A06 |= incoming;  // 保留原高四位
    rebuild_reward_flags();      // 0x319DD0
}
```

`0x319DD0` 将 `0x612A06` 的 bit 0、bit 1 转成 `0x488DA0`、`0x488DA1`
两个布尔值。其余五个奖励开关通过 `0x155040` 查询 SP 自身剧情完成标志，
表 `0x488DA8` 为 `5, 11, 16, 21, 29`，查询参数各减 1。
因此 Z 反复通同一路线不会在这个奖励计算中增加一档。

## 奖励表与实际发放

原版奖励表从 `0x4A09F0`（文件偏移 `0x3A1370`）开始。
五组剧情，每组 `0x60` 字节，每项 `0x0C` 字节：

```c
struct Reward {
    uint32_t money;       // +0
    int16_t bs;           // +4
    int16_t pp;           // +6
    int16_t part_id;      // +8；实际发放以 lbu 读取低字节
    uint16_t padding;     // +10
};
Reward rewards[5][8];
```

每组索引 0、1 是 Z 男／女路线，2–6 是 SP 五组剧情的通关奖励，7 是奖励界面的
初始数值行。**实际奖励循环仅遍历 0–6，不能把第 7 行再算作联动奖励。**
显示路径 `0x437CB0` 起分别从第 7 行读取初始资金、BS、PP，与已启用奖励行求和。

新剧情入口中的顺序：

1. `0x31BBE0–0x31BC94`：按剧情索引处理初始资金、BS、零件表。
2. `0x31BC98–0x31BD38`：将驾驶员记录的额外 PP 字段清零。
3. `0x31BD40`：仅状态值为 8（选择领取）时执行追加；状态 9 跳过追加。
4. `0x31BD60–0x31BF38`：遍历七个布尔开关；开关为真才应用对应记录。

发放调用和目标：

- `0x31BD8C → 0x155130`：增加资金，当前资金位于 `0x5DBB20`。
- `0x31BDB8 → 0x1551F0`：增加 BS，当前 BS 位于 `0x5DBB68`。
- `0x31BDE8 → 0x27D040`：给表中指定零件增加 1 个。
- `0x31BDF0–0x31BF20`：遍历 `0x61E3E8` 指定数量的驾驶员记录，
  每条基址为 `0x5A5080 + index * 0xB0`，向 `+0x9C` 加上该行 PP。

零件名称独立从原版 COMPDATA 核实：`0x437ADC–0x437B08` 使用
`0x767270 + part_id * 32` 的名称指针；对应解压文件偏移 `0x22F0 + part_id * 32`。
因此零件名称不是根据本篇列表顺序猜测。

Data Link 的确认合并路径本身没有调用资金、BS、零件发放函数；发放发生在上述
剧情开始分支。这里的奖励不随每个普通关卡再次自动发放。
