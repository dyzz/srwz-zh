# 《超级机器人大战 Z Special Disc》汉化规划

2026-09-17。本文综合 2026-09-12 的四份只读评估与本次补充分析，给出 Special Disc（下称 SD）的汉化范围、复用程度、技术路线和实施顺序。

本文最初为只读分析，随后追加了 9/17–9/18 的实际迁移、图片与初稿工作记录。补充分析的明细、脚本与预览图见 `work/analysis/sp-localization-plan-20260917/`（Git 忽略目录）。

**当前进度入口：[全量文本候选](FULL_TEXT_CANDIDATE.md)（2026-09-19）。** 当前 8,629 条既有译稿已全部写入新镜像。本文其余内容保留早期估算与中间版本记录，不能作为最新完成状态。

## 结论

- **可行，建议在本仓库内作为第三个产品来做，而不是 Original／BEST 之外的第三个“版本”。**
  - SD 与本篇同引擎，压缩器、文本编码、字库、STAGE／SRVC／图鉴解析与写回器都能复用。
  - 剧情块、主程序、COMPDATA 的布局都与本篇不同，BEST 那种“把 Original 组件映射到另一套地址”的后端不适用。
  - 做法是“共享中文前端（语料、码表、字形）＋ SD 原生后端（按原文哈希绑定译文、SD 地址契约、SD 写回器）”。
- **新译文约 23.7 万日文字符（上限估计），其中剧情对白 18.1 万（6,579 句），约占四分之三。**
  - 这相当于本篇剧情对白与战斗字幕总量（约 202 万字）的一成出头。
  - 战斗字幕（99.5%）、图鉴（98%）、中断消息（100%）、攻略 Q&A（96.5%）、演示人名（100%）基本现成。
- **字库不需要重新识别。**
  - SD 的字库块与本篇原版逐字节相同，0x989F 以上的扩展字表（229 项）也相同。
  - 2026-09-12 的实测中，现有中文码表和字形不改主程序就能在 SD 中正确显示。
  - 要解决的是 VT1 布局：中文字库压缩后多 29,760 字节。本篇借用的前一块零填充，在 SD 中被一个新增的 66.8 MB 音频块隔开了。
- **主要风险有四类：**
  - VT1 布局迁移需要运行验证；
  - COMPDATA 与 STAGE 的容量；
  - 若干 SD 功能要重新逆向：图鉴与声音选择解锁、姓名格式、VT1 固定格文本的索引、对白回看；
  - 换上中文字库后，未翻译的汉字必然显示错字，所以发布前必须 100% 覆盖。

**标题副标题条（2026-09-18 追加，脚本 `ai-image-kit/retitle_logo.py`）**

VT1 第 28 块一张 TIM2 里有 3 张 512×256 的 4bpp 图，共用一组 64 色调色板（4 组 16 色，第几张用第几组）：第 0 张是画面（带框的副标题条、右上角的同一行文字、旁边的斜纹），第 1 张是它下面那层橙色光晕，第 2 张是火焰零件（与本篇相同，不动）。

- 第 0 组调色板本身就是一条渐变：0 透明，1–7 橙色描边（透明度 120–255），8–10 黄色字面，所以一个字就是一张“浓淡图”。描边和光晕都是从日文原图上拟合出来的，不是另画的：
  - 描边：按到字芯的有向距离查表，距离要先按拟合出的位移和纵向比例修正（原图下方和右侧的描边更宽）。拟合后重画日文，平均误差 0.5 个索引，65.8% 完全一致。
  - 光晕：等于画面墨迹外扩 3 像素再按 σ=6 高斯模糊查表，平均误差 0.72 个索引、91.6% 在 1 个索引内。写回时只写差值，条内当作整条发亮，所以中文比日文短也不会让条内忽明忽暗。
- 右上角那块不是另一处用途：它是条内文字本身的拷贝，被切成两半分别平移（左半 +304/−16，右半 +160/+16），游戏把两半又画回条上，等于副标题画了两遍。日文用这个规则可以 99.999% 还原，中文同样切开写回；最初只改条内不改拷贝时，实机会看到中文重影。
- 中文用项目字体 HarmonyOS Sans SC，按 logo 的斜切（每行 0.5 像素）排，字高 17 像素与假名一致。汉字在这个尺寸上字内空隙只有 1 像素，2 像素的原始描边会糊死，所以中文这条把距离压缩 1.6 倍，描边收到约 1 像素。
- 描边查表按距离分桶拟合，假名笔画细，字心较深的桶没有样本；这些桶原本默认成 0（透明），汉字笔画交叠处就漏出背景，实机看到黑点。现在空桶按有样本的桶补齐，另外把 1–3 像素的透明小孔用周围最亮的墨色补上（本次补了 5 个），真正的字腔不动，脚本里有断言守住。

## 4. 技术路线

### 4.1 产品结构

在 `srwz-zh` 内新建独立产品 `special-disc`：

| 位置 | 内容 |
| --- | --- |
| `config/products/special-disc/` | 原盘与主程序身份；地址契约（档案表、STAGE、COMPDATA、SRVC、VT1、补丁点）；ISO 与发布配置 |
| `corpus/zh/special-disc/` | 只存 SD 独有的译文，ID 用 `sd/…` 前缀。与本篇相同的日文一律按原文哈希引用共享语料，避免两份译文分叉 |
| `manifests/special-disc/` | 只记录哈希、计数与回读结论 |
| `work/build/zh-special-disc/`、`build/iso/zh-special-disc/current-special-disc.iso` | 工作目录与产物 |

**与现有代码的衔接**
- 现有 `EditionProfile` 只接受 Original／BEST，并假定两者内容相同，所以 SD 不塞进这个类，而是另建产品契约。
- 然后逐步把本篇构建器里的硬编码改为从契约读取，例如：HB 表范围 30320／31144、205 块、784 个图鉴条目、2,609 条 Q&A 记录、104 个小队名、145,408 字节上限。
- 每一步改造都用 `build_editions.py --require-legacy-equivalence` 证明本篇两版逐字节不变。

**维护**：共享语料的润色会同时进入 SD，所以 SD 构建也要纳入常规回归，以免本篇改稿后 SD 的覆盖率悄悄失效。

### 4.2 字库与 VT1 布局

**码表共用**：数据链接会读取本篇存档。中文版本篇存档里的名字如果含中文字，SD 必须用同一套码位才能正确显示。

**布局迁移**

SD 的 VT1 前四块依次是：

| 块 | 内容 | 块末零填充 |
| --- | --- | --- |
| 0 | 压缩块 | — |
| 1 | 音频，与本篇第 1 块相同 | 356,850 字节 |
| 2 | 新增音频，66.8 MB | 仅 1,031 字节 |
| 3 | 字库 | — |

- **推荐做法**：把第 2 块整体前移 29,760 字节，占用第 1 块的零尾，再让字库向前扩展。
  - 只需改主程序表中 `0x353798`、`0x35379C` 两项，VT1 总长和后续偏移都不变。
  - 这两个偏移值在主程序里只出现在该表中。
  - 需要实测：用到第 2 块音频的场景（还需定位）能正常播放。
- **不采用的做法**：Rust maximum 策略只能压到 619,484 字节，仍超 20,144 字节，且单次要 5 分钟以上。
- **备选**：重压第 3 块之后的各块，把它们整体后移；需要改约 105 个偏移。

**容量**
- 共享码表现有主映射 3,476 个。
- 常规宽度的可用候选还有 75 个。
- 条件宽度 `0x8492–0x889E` 另有 183 个空位。按现行政策，它们只能用于剧情、战斗、系统对白和图鉴，不能用于人名、机体名、部件名，并且要逐个审核（其中夹有框线字符）。
- SD 实际新增多少字，等初稿完成后由字库构建按实际写回闭包计算。

**覆盖要求**
- 换上中文字库后，未翻译日文里的大部分汉字会显示成别的字（假名不受影响）。
- 所以 SD 发布前，所有可见文字面都必须 100% 覆盖。
- 存档里可能残留的日文默认名（如小队名），按本篇 `source_compatibility` 的做法单独保护。

### 4.3 各领域写回要点

- **STAGE**
  - 沿用整关重排。
  - 本篇中文重压后，压缩比中位数 0.912，单块最小余量 24 字节。SD 日文原文用 Rust 重压，每块只省 9–227 字节，所以容量取决于中文是否比日文短。
  - 先用占位中文对 `stg_017`、`stg_020`、`stg_213` 试排；不够时再平衡 HB 偏移（STAGE 总长 527,552 字节，另有 832 字节扇区余量）。
  - 解压大小保持不变（SD overlay 窗口为 `0x804600–0x81C600`）。
  - 同值地址的归属审计要在 68 块上重做，本篇的 9 条地址契约不能照搬。
- **中断消息**：位于主程序数据段 `0x38CB00–0x39AC7F`。用系统对白解析（基址 `0xFF680`）绑定已有译文；写回属于主程序文本池，不属于 STAGE。
- **SRVC**：25,403 句按哈希复用，另新译 123 句。要用 SD 实际编码重算每块余量（估算需要 1,659,935／2,174,142 字节，无块溢出）。
- **COMPDATA**
  - 按 SD 描述符重建；关卡名等可用本篇的 `repack_menu_texts_in_block` 整块重排。
  - 解压大小不能变，因为其后紧接 STAGE overlay；压缩后必须 ≤178,176 字节。
- **VT1 第 40／50 块**：需要新写回器，把中文按 28 列固定格重新换行。动手前先找到程序读取这些行的方式，并确认码表在这里同样适用。
- **主程序新文字**
  - 新增 SD 专用表：特别剧场、战斗鉴赏、剧情与挑战模式、背景名。
  - 本篇的菜单描述可以用脚本迁移过来：934 条原文中 916 条在 SD 中原样存在，28 张指针表中 25 张可按固定偏移定位。
  - 战斗鉴赏有大量定宽栏位，翻译前先测容量，必要时用 `<width>`／`<space>` 标签。
- **对白回看**：SD 新增了回看功能，剧情排版要在对话框和回看界面各验一次。
