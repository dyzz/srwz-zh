# 全角存储与字宽控制：代码分析及 LRPS2 实测

2026-09-28。结论：**全角双字节字形码可以与独立的字形宽度、字符推进距离控制同时使用。**
本轮验证了当前 SP 普通对白窗口的可行性，并复验本篇当前 Original 的英文标题显示。

## 确定的规则

1. 普通双字节文本面的可见英文、数字使用原版全角字形码；可见空格使用 `0x8140`。
   中文标点使用发布码表。语料的 `MAX` 与 `ＭＡＸ` 经生产编码后相同。
2. `<width:XX>` 编码为 `32 XX`，调整字形宽度；`<space:XX>` 编码为 `34 XX`，
   调整字符推进距离。参数为十六进制。这些是控制码，不是可见英文／数字。
3. 要紧凑排英文，必须同时考虑字形宽度和推进距离。只收窄字形会留下大间距。
4. 收窄英文段后显式恢复当前文本面的宽度和推进距离，再继续中文及标点。
   恢复值按界面确定。本轮 SP 普通对白是 `16/16`，即名义 22 px；本篇读档详情
   既有标题契约是 `12/12`，即 18 px。不能给所有界面套同一恢复值。
5. 宽度控制不减少存储字节。每个可见字形仍占两字节；前后四个标签共增加 8 字节。
   槽容量、压缩预算、居中测宽和换行均须继续验证。

可复核示例：

```text
<width:0C><space:0C>ＭＡＸ　５６０００<width:16><space:16>
```

上述全角 Unicode 写法与逻辑文本 `MAX 56000` 的最终载荷完全相同：

```text
32 0C 34 0C 82 6C 82 60 82 77 81 40 82 54 82 55 82 4F 82 4F 82 4F 32 16 34 16
```

## 当前 ISO 的代码证据

从三版最终 ISO 独立读取 ELF。两个控制处理块均为 28 字节，逐字节一致：

| 版本 | `width` 文件偏移 | `space` 文件偏移 |
| --- | --- | --- |
| Original `SLPS_258.87` | `0x3BEF0` | `0x3BF30` |
| BEST `SLPS_732.70` | `0x3BEF0` | `0x3BF30` |
| SP `SLPS_259.20` | `0x3B890` | `0x3B8D0` |

SP 渲染入口 `0x13AD30` 的分发表将 `0x32` 路由到 `0x13AF10`，`0x34` 路由到
`0x13AF50`。处理块读取后续一个参数字节，再推进字符串指针；分别写入字型状态
`s1 + 0x14`（宽度）、`s1 + 0x18`（推进距离）及对应绘制状态。
当前 SP 的两处测宽范围指令 `0x3B0E0`、`0x168A1C` 均为 `9F820134`，
保留既有测宽／绘制范围修正。

生产编码路径见 `tools/srwz/text.py` 的 `original_fullwidth_ascii_overrides`、
`two_byte_visible_spaces`、`encode_text`；已有标题作者规则见 `wrap_trailing_latin_run`。
对照历史标题实测见 [STAGE_TITLE_LAYOUT_20260912.md](../STAGE_TITLE_LAYOUT_20260912.md)。

## 验证边界与采用范围

- 8 项 SP 格式／编码测试与 3 项既有标题宽度测试通过。
- 测试前后当前 SP ISO 和输入记忆卡 SHA-256 一致；标准运行器另确认本篇和 SP
  挑战源卡未改变。
- 本轮没有运行 BEST 的 LRPS2 流程；其两个控制处理块已与另两版静态比较。
- `Black Gale`、`BLOCK WORD`、`The Big`、`MAX/56000` 是普通对白渲染器的 RAM 探针，
  尚未自然完成各自源场景；17 条动态 `tm` 模板仍待独立运行时确认。
- 首轮测试时普通对白排版器仅按固定字格计宽。后续已接入 `width/space` 参数、
  字形边界和跨行状态，并实测超过 21 个可见字符的收窄对白。
  最新实现与名称验证见 [TEXT_WIDTH_LAYOUT_POLICY_20260928.md](../TEXT_WIDTH_LAYOUT_POLICY_20260928.md)。
  默认普通对白保留既有 21 格、最多 3 行预算；含标签的文本按实际推进距离计算。
- 以上是 LRPS2 证据，没有新增 PCSX2／用户人工验收。
