## 决策

用户后续范围约束：**数字相关不改动**。数字字形、UV、图元、调色板和数字选择／绘制代码均为保护对象；分析登记仅用于防止跨页标题改动误伤，不迁移、不重排、不重写数字。

建立 Special Disc 独立的“字块—取样区域—图元引用—场景调用”登记表，优先跨页复用冻结的
中文双字块。标题像素放第 6 页，原生颜色／阴影的调色板继续从第 2／4 页取得。
普通字库改接尚未通过运行验证，不作为本轮标题改动的依赖。

先处理 DATA HELP 与 OTHERS COMMAND 的技术阻塞；模式标题、图鉴标题及字母缩写先登记、
保护，不把清单当作批量翻译授权。文案、样式和已有英文保留范围在接入条目中显式表达。

**接入前先对齐现有配置与当前 ISO。** 当前回读中，`command-headings.json` 的 51 条记录
均未达到配置的 `after_hex`：41 条匹配 `before_hex`，10 条匹配 `native_hex|before_hex`。
仅在内存中调用现有 `apply_command_headings()` 能通过前像检查，得到之前单行指令候选的
两份成员哈希。此轮没有把这份结果写回镜像。
因此“第 4 页已有指令／菜单／阵型新布局”是配置目标状态，不能当作当前 ISO 的既成事实。

## 代码与资源结构

以下均是 Special Disc `SLPS_259.20` 的 EE 虚拟地址，不能套用本篇。

| 入口／数据 | 已核实的作用 | 对规划的影响 |
| --- | --- | --- |
| `0x390BE0` | 普通 KVP 图元绘制；局部 ID 范围 0–1467 | 标题、标签、单字母及数字图元都可能通过它 |
| `0x390D70` → `0x38F2E0` | 186 个面板；每块先读 16 字节布局头再走图元链 | 不能从面板块首扫描 type 5/7；边框也可能包含文字或子标题 |
| `0x390E00` | 58 个子图元块，沿相同长度表遍历 | UI 外层传入局部 ID，要换算为全局块号 |
| `0x49ABC0` | 三组基址／末尾索引：`0,1468,1654,1712` | 全局块号分别为普通 ID、1468＋面板 ID、1654＋子图元 ID |
| `0x49C770` | 图元绘制分派表 | type 5/6/7/8 是带纹理图元，均须登记 UV |
| `0x49C7D0` | 图元长度函数表 | 按真实记录边界遍历，不能依赖字节特征误命中 |
| `0x38FC70` | 普通组中的 type 12 动画容器 | 还要登记关键帧指向的子图元，不能只看直接调用 |
| `0x38A000` | 材质选择与 TEX0 构造 | 像素页、CLUT 页及 bank 是不同字段 |
| `0x3C1B40` | 逻辑图集页按需上传到共享显存槽 | 分配必须验证槽位兼容，且评估频繁换页成本 |
| `0x13D050` → `0x13AD30` | 普通编码文本绘制包装／核心 | 帮助正文等已走字库，不需搬图集 |

type 1/2/5/6/7/8/9/10/11 的长度依次为 16/28/22/34/34/50/10/14/10 字节；
type 3、4 分别是 `14 + 4*n`、`14 + 8*n`，n 来自记录 byte 4 的有符号值。
末条记录 byte 0 的 bit 7 是结束标记。type 12 是独立容器，不用普通步长遍历。

类型 9/10/11 分别引用普通／面板／子图元组，目标 ID 均在 byte 4 的半字中。
type 9 还经过 `0x762530` 的运行期替换表；静态父子关系是原始引用，不能据此保证运行期
永远指向同一块。其余动态索引和分派表仍要在指定场景核实。

## 数字：代码选择图元的另一类字库

此次直接追到 `0x3DDEA0`：根据样式选择数字图元基础 ID，在 `0x3DE104` 取十进制余数，
`0x3DE130` 以“基础 ID＋数字”调用 `0x390BE0`，随后除以 10 继续。

| 基础 ID 与范围 | 实际纹理来源 | 处理 |
| --- | --- | --- |
| 232–241、253–262、268–277、295–304 | 第 4 页同一排数字，单字 UV 宽 24，高 32，y=120–152 | 四种图元／样式复用同一排像素，整排保护 |
| 438–447 | 第 4 页较小数字，单字 UV 宽 16，高 24，y=152–176 | 保护该排，不能视为标题空位 |

另有 `0x3D9490`、`0x3D9D10`、`0x3DD6C0` 通过类似方式选图元。
这修正了早期“数字完全由代码算 UV、KVP 中看不到”的过宽说法：**已追到的这些数字是
代码选 ID、KVP 给 UV**，因此完整图元解析可覆盖它们的取样区域；代码中的动态选择仍需
登记，以免删除“没有固定标题引用”的数字图元。

这不构成所有运行期 UV 都已解决的证明。`0x3C1B40` 还有绕过 `0x38A000` 的直接调用，
独立图像渲染、顶点／UV 修改、滤波和运行期替换表仍是后续审计边界。

## 普通字库和独立整图不属于这次搬页

- 帮助正文、机体／人物名称、武器名、说明文等编码文本：继续走普通字库、文本码表和布局。
- 世界地图标题、关卡开场标题、主菜单大图：分别由 MAPMODEL、独立图片／特效资源和现有
  冻结图片写回器负责。不能因为它们含文字，就假设能用 KVMDATA 前 10 页的同一页号机制。
- AIDDATA／TRICMN 的战斗提示：另有容器、索引／调色板和动画规则；可借鉴登记方式，
  不能套用 KVP 的记录长度与页槽表。

## 跨页空间与第一批分配草案

空间筛选以本轮当前 ISO 成员为输入，保留全部非零索引、全部结构化 type 5/6/7/8 UV，
包括面板与子图元；仍不宣称动态取样和采样边缘已全排除。

| 页 | 46×20 紧排候选 | 48×22 含一圈空白的候选 | 用途 |
| --- | ---: | ---: | --- |
| 2 | 0 | 0 | 原字母／整词继续保护 |
| 4 | 0 | 0 | 原字母、数字及已登记中文块继续保护 |
| 6 | 4 | 3 | 第一批中文存放页 |
| 8 | 1 | 1 | 备用，不立即占用 |

两种尺寸不能相加，数量是按扫描顺序贪心放置，不是最大装箱容量。
第 6 页 46×20 起点为 `(104,184)`、`(104,204)`、`(104,224)`、`(184,232)`；
48×22 起点为 `(104,184)`、`(104,206)`、`(184,232)`。
第 8 页 48×22 起点为 `(128,223)`。

建议第一批按以下**草案**分配，非生产锁定：

| 字块 | 分配区域 | 实际取样区域 | CLUT | 证据／依赖 |
| --- | --- | --- | --- | --- |
| 项目 | 第 6 页 `(104,184,46,20)` | 同左 | 原第 4 页 | 此坐标及冻结字块已在上一轮 LRPS2 验证；仍需目标武器详情与生产基线验收 |
| 其他 | 第 6 页 `(104,206,48,22)` | 内部 `(105,207,46,20)` | 原第 4 页 | 本次静态候选；保留一圈空白，接入后跑 OTHERS COMMAND |
| 指令（若需要保留旧斜体样式） | 第 6 页 `(184,232,48,22)` | 内部 `(185,233,46,20)` | 原第 4 页 | 本次静态候选；若决定共用现有直体“指令”，此槽可继续保留 |
| 说明 | 现有第 4 页 `(0,100,46,20)` | 同左 | 原第 4 页 | 复用已冻结字块，不新增占地 |

不同字高、字重、斜体、描边的同字不强行合并。“指令”是否复用现有 38×20 直体版本属于
样式决策，不能自动替换旧 46×20 斜体快照而声称外观完全一致。

显存槽映射为 `[0,1,2,3,4,5,5,5,5,3]`：

- 单个图元的纹理页和 CLUT 页若不同，须占不同槽；第 6 页纹理＋第 4 页 CLUT 合法。
- 不同图元可以先后取第 6 页和第 8 页，二者各配第 4 页 CLUT；这不是禁止组合，但会换入
  同一槽，可能增加上传次数。不要把此约束误写为“同一画面不能用第 6／8 页”。
- 尽量让同一标题的新字块集中一页，保持原始层次顺序；不能为少换页而任意调整阴影和前景。
- 10 张逻辑页载入 RAM 不等于 10 张同时驻留显存，文档和构建约束都应使用此区分。

## 登记表和构建器需要承担的职责

规划的 `config/assets/special-disc/title-atlas.json` 应登记以下对象，此轮不建立会被生产误读的配置：

1. **字块**：稳定 ID、文本、样式 ID、宽高、冻结索引及哈希；保留透明／描边／填充索引角色。
2. **分配**：像素页、外框、实际 UV、保护边缘、前像与目标像素哈希、确认状态。
3. **引用**：组、局部 ID、全局块、真实记录偏移、类型与前像；纹理页、CLUT 页、bank、
   颜色、屏幕几何、层次和结束标记分别表达。34 字节图元不能直接套到 22／50 字节图元。
4. **保护对象**：共享拉丁字母／汉字片段、动态数字 ID 范围、按键符号、未解动态引用、
   其他写回器已占用矩形及原始消费者。
5. **使用者与验证**：标题语义、父容器／动画、静态调用候选、实测场景；区分已在 ISO、
   仅在配置、隔离 LRPS2 验证、PCSX2／人工验收。

生产构建应在各图片组件合成后按最终成员执行一次统一校验；同时安装 KVM 像素和 KVP
引用，阻止后续旧整成员覆盖。为 `command_headings`、继承标题迁移、结算标签等已有写回器
导入占地和引用，不立刻把所有作者工具重写。

静态门禁至少包括：版本／成员身份、记录结构边界、外框与 UV 越界、声明区域重叠、共享字母
前像保护、图元预算、结束标记与颜色不变、纹理／CLUT 槽兼容、未声明像素及字节不变。
省下的原字母记录可以清为零面积，但仍保留记录拓扑与终止标记。容量不足明确失败；不静默
把待接入标题回退成英文。明确保留英文的条目则不属于错误。
