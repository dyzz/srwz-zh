## 1. 流程

| 步骤 | 实现 | 产物 |
| --- | --- | --- |
| 1. 繁体派生 | `tools/zh_hant/derive_corpus.py`：简体语料 → OpenCC `s2tw`（只换字形）→ 术语表 → 逐条稿。<br>只改译文字段，日文原文、备注、哈希、id 原样保留。<br>逐条稿绑定简体原文的 sha256，简体变了就判为过期：退回自动派生，并列入报告。 | `build/zh-hant/corpus` 和 `derive-report.json` |
| 2. 码位空间语料 | `tools/zh_hant/codespace_corpus.py`：繁体字库是“同码换字形”，所以繁体构建可以继续用简体码表，只需要繁体的**措辞**。<br>每行以简体原文为底，只在繁体文本和逐字转换不一致的片段换成 `t2s` 结果（如「联系」→「联络」、「屏幕」→「萤幕」）。没改措辞的行和简体逐字节相同。 | `build/zh-hant/codespace`：84 个文件、289 处 |
| 3. 两次构建 | `build/zh-hant/project` 和 `project-tc` 是构建输入的 APFS 克隆：六个源码目录，加上 `rom`、`work/font-source`、`work/disc`、`work/toolchain`、`work/writeback`。<br>两边都运行**未改动的** `tools/build_editions.py --editions original --candidate`。繁体那份把 `corpus/zh` 换成码位空间语料；简体码表缺字时，用构建自带的 `update_zh_release_font_snapshot.py --apply` 分配（本次 1 个：「萤」= `97FC`）。 | 两张完整的单语言盘 |
| 4. 组盘 | `tools/zh_hant/assemble_dual.py`，详见 §2 | 双语盘和回执 |

**仓库里的输入**：
- `corpus/zh-hant/config.json`：底稿用 `s2tw`；排除 `special-disc`、`ui-atlas`。
- `corpus/zh-hant/glossary.json`：5 个全语料安全的台湾用词：感測器、螢幕、訊號、資料、遠距攻擊。共命中 295 处。
- `corpus/zh-hant/overrides/`：样稿 780 条，由 `tools/zh_hant/make_sample_drafts.py` 生成。内容是派生文本加上审定的改写，本次只有 1 处：「聯繫我們」→「聯絡我們」。

**为什么不用 `s2twp`**：OpenCC 的台湾词汇表偏电脑术语，会把文章改错，例如「無能的士兵」→「無能計程車兵」、「命令行動」→「命令列動」、「支持你」→「支援你」、「戰鬥對象」→「戰鬥物件」。地区用词只能走术语表和逐条稿。

## 2. 组盘器（assemble_dual.py）

先逐成员比较两张单语言盘，再按差异类型处理，任何没覆盖到的差异都会报错停下：

| 差异 | 处理 |
| --- | --- |
| 可执行文件 | 先把繁体可执行文件里的 VT1 偏移表换回简体的，因为盘上保留的是简体 VT1。<br>再改字库读取的 5 条指令，指向 DMY 里的繁体字库，并打开线性取字回落。然后求两份可执行文件的差，生成补丁。<br>本次 11 条记录、55 字节：UI 文字改动（「资料」等）加字库读取指令。 |
| VT1 第 2 块（字库） | `tools/zh_hant/tc_font.py`：解压繁体构建的字库，把每个经过光栅化的格子换成该字的繁体主形（简体语料里 `s2tw` 出现最多的写法；语料里没有的字按单字转换，共 28 个，包括「萤」→「螢」），用构建提案里记录的同一套光栅参数重画，压缩后放进 DMY。<br>重画前先抽 200 个不换形的字重新光栅化，必须和构建出的字形、提案记录的哈希都一致（200/200）。<br>“保留原盘字形”的格子不动。本次 1,218 格换形。 |
| VT1 其他块 | 只允许第 8 组（进关标题）不同，处理方式同 M1：整组复制、表项平移。其他块不同就报错，那是 M4 的贴图工作。<br>比较时忽略块末尾补零：繁体字库块小了 80 字节，构建器把它放在槽位末尾，前一块因此多了一段补零。 |
| 其他成员 | 必须有文件对照表行，否则报错。整份复制进 DMY，对照表行改指过去。本次有 6 个：STAGE、SRVC、COMPDATA、NISVDATA、MTVZKNPT、MTVZKNRT。 |

钩子源码在 `tools/zh_hant/lang_hook.S`，和 M2 是同一份。

组盘时的检查（方案 §9.5）：
- 按钩子的逻辑重放补丁，结果必须等于繁体可执行文件；
- 补丁记录不能落在禁区（钩子本身和入口、字库缓冲大小字、字幕缓冲、音乐钩子、堆起点字）；
- DMY 里每一项都要回读核对；
- 写入范围之外，输出盘必须和简体盘逐字节相同。

## 5. 方案里的问题，现在的结论

- **构建工具不需要“语言”参数。** 每个构建工具都只读自己工作区里的副本，所以在一份克隆工程里替换输入就能得到繁体构建，构建代码一行没改。代价是每次要复制输入目录（APFS 克隆，不占空间，几秒）。
- **构建的排版阶段会读工程根目录下的 `work/writeback/zh-release-codebook-proposal.json`**，这是上次构建留下的文件，不在冻结输入里。克隆时要带上它。这个隐藏依赖值得在构建里修掉。
- **贴图冻结快照**（进关标题、界面标题、世界地图标题）要求对应语料和快照一致。码位空间方案下，这些语料没有措辞改动，所以没碰到。真正的繁体贴图要等 M4 的繁体快照。
- **剧情字幕不走码表**，是用字体文件直接画进 VEFF2DX 的，文字在 `config/event-subtitles/`。繁体字幕要在 M4 单独做。

## 6. 还没做的（A 步时；B 步见 §9）

1. **次要写法要进线性区（B 步）。** 繁体文本里有 86 个字既不是某个简体字的繁体主形，也不在码表里（傢、託、迴、係、瞭、製、乾、複、髮 等），共出现 9,315 次。
   - 码表只剩 7 个空位；同一繁体形对应多个码位，最多还能腾出 36 个码位。都不够。
   - 要做的改动：构建工具支持 0x99xx 线性码位，字形序号 4608 起；`tools/srwz/font.py` 里的字库容量要可配置，默认仍是 4,480，保证简体不变。字库扩容后 VT1 第 2 块会变大，组盘器已经把字库放进 DMY，但繁体构建自己的 ISO 那一步能否接受 VT1 变大，还要试。
2. **样稿是机器底稿加 1 处审定改写**，还不是人工繁体稿。术语表只有 5 条。
3. **字形规范**：字库仍用 HarmonyOS Sans SC，是大陆字形规范。
4. **M4**：贴图和剧情字幕的繁体版。**M5**：BEST。

## 9. B 步：线性区码位（2026-11-17）

用户选择按方案 §7 做：构建工具支持字库扩容，新字进线性区；不走“复用本篇用不到的码位”那条捷径。

### 9.1 构建工具的改动（简体产物不变）

| 文件 | 改动 |
| --- | --- |
| `tools/srwz/font.py` | 新增 `FontCapacity` / `font_capacity(config)`。字库配置里的 `font_capacity` 缺省时，就是原来的 4,480 格、没有线性区。<br>`glyph_index_for_code(..., linear=True)`：扩展表查不到的码位按线性公式解析。只认首字节 `0x99` 起、字形 4608 起，和可执行文件里的线性回落补丁一致。<br>`linear_area_codes()`：列出没被扩展表占用的线性格子，本篇有 173 个。 |
| `tools/update_zh_release_font_snapshot.py` | 新字分配先用原有候选池；候选池用完、且配置开了线性区时，按顺序取线性格子，分配方式记为 `linear_area_allocation`。 |
| `tools/prepare_zh_release_font.py`、`build_zh_font_component.py`、`verify_zh_release_font.py`、`verify_full_story_iso_content.py`、`srwz/release_font.py` | 码位解析和字库大小改为读配置里的容量；原版字库在 4,480 格之后视为全零格。 |
| `tools/verify_full_story_iso_content.py` | 新增可选的“回读折叠表”`config/zh-hant/readback-fold.json`，只有繁体克隆里有。<br>写死的简体字面量检查（ISSUE-020 跑马灯、兰德那句对白、可执行文件文字的偏移契约 10 组）比较前，先把次要写法折回它对应的简体字。<br>和语料比对的检查不受影响。 |
| `tests/test_font_linear_area.py` | 线性区函数的单元测试。现有字库相关测试 30 个照常通过。 |

用改过的工具重跑简体构建，产物仍是 `c6754f75…`，逐字节不变。

### 9.2 繁体这一侧

- **主形规则**：`tc_font.primary_forms` 改为“能保留原字就取原字”。
  - 逐字转换在某处会原样保留的简体字（家、里、后、准、干 等），它的码位就显示它自己；其他写法（傢、裡、後、準、幹）作为次要写法另给码位。
  - 原来按“出现最多”定主形会出错：「家」的主形会变成「傢」，因为「那家伙」很常见。改成新规则后没有任何冲突。
- **码位空间语料**：次要写法按繁体字原样写入（31,721 处）；主形位置仍写简体原字。
- **繁体构建分配新字**：一共 109 个。8 个用掉原有的空位，其余进入线性区 `9940`–`99B2`，例如「傑」=`9940`、「後」=`9959`、「裡」=`998C`、「髮」=`99A9`。
- **字库**：4,800 格，压缩后 673,743 字节。借用前一块末尾的零填充原地放进 VT1，VT1 大小不变。
- **繁体构建里补上的转换**（不改就过不了构建自身的门槛）：
  - `corpus/runtime/stage-keywords-v1.json`：剧情关键词区间要和正文一致，做同样转换。日文原词字段 `source_term` 不转换。
  - `config/text-layout/` 的三个词表：排版门槛不切开的专名和常用词，补上码位空间写法（84 个），原词保留。
  - 贴图绑定的语料（`menu/stage-names.json`、`chapter-intertitles.json`）保持简体，等 M4 做繁体贴图。这两处的次要写法暂时显示为主写法。

## 10. 平行方案：繁体语料、术语表、字库各自独立（2026-11-17）

用户决定：繁体是**平行独立**的一套，语料、术语表、字库都单独维护，不再从简体派生。本节取代 §1–§9 的“派生层 + 码位空间语料 + 同码换字形”做法：`derive_corpus.py`、`codespace_corpus.py`、`make_sample_drafts.py`、`tc_font.py` 和回读折叠表都已删除。

测试盘：`build/iso/test/zh-hant-dual-original.iso`，装了音乐播放器的版本是 `zh-hant-dual-music-original.iso`。`zh-hant-m3a/m3b-*.iso` 已被取代。

一条命令复现（要有装了 opencc 的 Python；两次构建本身用普通 `python3`）：

```bash
python3 tools/zh_hant/build_dual.py
```

### 10.1 仓库里的繁体输入

### 10.2 工具

| 工具 | 作用 |
| --- | --- |
| `tools/zh_hant/sync_corpus.py [--check]` | 让平行语料跟上简体。规则按条：繁体缺这条 → 起草；对照哈希没变 → 保留；变了且是 `draft` → 重新起草；变了且是 `edited`/`reviewed` → 保留原文，列为过期待审，不覆盖。报告写到 `build/zh-hant/sync-report.json`。`--check` 只检查，有缺漏、过期或孤儿文件就返回 1。 |
| `tools/zh_hant/build_codebook.py [--force]` | 只在最初建一次繁体码表（之后只靠构建自带的分配器增长）。从简体码表出发：<br>1. 结构性的行不动：标点别名、源码兼容行、所有 `*compatibility*` 重定位的目标码位、小队名连字、阵型冻结字，还有三项兼容审计（旧存档阵型名、运行时生成字形、音乐选择标题）保护的码位，以及基础码表里的行（测、试）。<br>2. 繁体也用到的字保留码位。<br>3. 只有简体用的字（发）把码位让给平行语料里最常顶替它的繁体字（發）。共 1,063 行。所以绝大多数字在两种语言里码位相同，存档里的名字读出来是对应的字。<br>4. 繁体还缺的字留给分配器：先用 8 个原有空位，其余进线性区。 |
| `tools/zh_hant/build_dual.py [--skip-sc] [--update-codebook]` | 1. 先跑 `sync_corpus --check`，不同步就停。<br>2. 简体克隆构建。<br>3. 繁体克隆：用平行文件（去掉元字段）覆盖 `corpus/zh`、`glossary`、`runtime`；换上繁体码表、字库配置、排版词表；生成回读字面量表；处理贴图相关配置（§10.3）。<br>4. 跑分配器：繁体缺字时停下，加 `--update-codebook` 才分配并写回 `config/zh-hant/`。<br>5. 生成繁体的发行菜单码表（简体的非汉字行 + 繁体全部汉字主行）。<br>6. 繁体构建，组盘。 |
| `tools/zh_hant/assemble_dual.py` | 同 §2，改动：繁体字库直接用繁体构建的产物（不再换字形）；标题确认框的文字按语言分开，各用自己的码表编码（钩子里 `pick_msg` 按 `lang*16 + 序号*4` 取）。 |

### 10.3 公用构建工具的改动（简体产物不变）

构建里有不少门槛拿写死的简体字面量比对（第 38 话标题「被操纵的决战」、跑马灯、默认名「卡缪」、按钮提示「：确定」等）。新模块 `tools/srwz/build_language.py` 统一处理：

- `expected_characters(text)`：给“字形是否存在”这类检查用，整串查不到时按字对照。
