# SP 简繁一张碟：方案

2026-11-17。目标：特别篇（SP，`SLPS_259.20`）也做成一张碟同时有简体和繁体，体验和本篇双语盘相同：
- 开机读卡上的语言设定，开机按住 SELECT 强制进繁体；
- 标题画面按 SELECT 打开设定面板，可设游戏语言、数字样式、对话引号。

本篇的做法见 [技术方案](ZH_HANT_SINGLE_DISC_TECH_DESIGN_20261116.md) 和 M1/M3/M4 记录。本文只写 SP 和本篇不同的地方。依据是两份调查（构建流程、可执行文件地址），要点收在 §1、§2。

## 1. SP 构建和本篇的根本差别

本篇从日文原盘出发，整条管线按语料重建，所以繁体只要换语料、码表和字库，再跑一遍。

SP 不是这样：
- **起点是冻结的中文基线盘。** SP 的起点是 `work/build/special-disc/baselines/text-canary.xdelta`（由 `build_full_text.py` 的 `BASE_SHA` 锁定）。它是 9 月用当时的本篇构建结果转换出来的已汉化盘，再加 17 张插图。
- **基线里一部分简体文本之后不再重写：** OP/ST 演示名、COMPDATA/NISV/MTVZKN 的部分内容，以及 17 张插图。
- **当时的转换器跑不了了：** 它们读的本篇工作区已经删除。
- **其余文本照常重写：** 现在的构建（`build_editions.py::build_sp`）在基线上跑约 30 个写入器，重写剧情、系统文本、SRVC、名场面集等。
- **很多检查拿简体做比对：**
  - 名场面集对白快照（`author_talk.snapshot_drift`）、进关标题、图片标签快照；
  - `instruction_overrides` 拿基线字节和简体 `baseline_translation` 比；
  - `config/editions/sp/inputs.json` 的 32 个哈希锁。
- **字库：** 固定 4,480 字（`install_font.FONT_DECODED_SIZE`），和本篇共用码表。繁体需要 4,992 字，还要用线性区。

**结论：** 繁体 SP 不能照搬“换语料再跑一遍”。建议用**混合做法**：
1. **繁体基线**：把简体基线盘里“之后不再重写”的文本按码表转换。
   - 简体码表解码，按平行语料逐串对应到繁体（对不上的用 OpenCC 加繁体术语表），再用繁体码表编码。
   - 插图另行绘制。
   - 这一步只在基线上做一次，结果冻结成繁体基线。
2. **重写部分走平行语料**：
   - `corpus/zh-hant/special-disc/` 扩到平行语料同步；
   - SP 配置里的译文做成繁体 `sections`；
   - 写死在代码里的简体字串改为读配置。
   - 在繁体克隆里照常跑 SP 管线。
3. **按简体比对的检查**在繁体克隆里改为按繁体基线比对。比对规则不放松，只换比对对象。

## 2. 可执行文件（地址已查到）

- **钩子位置：**
  - 开机钩子：`0x141B28`（本篇 `0x141010`）。
  - VMAP 载入：`0x141AB8`；表在 LBA 450，格式和本篇相同；按名查找 `0x1394A0`。
  - libmc、CD 读取等函数都能一一对应。
- **代码空间：** `0x81C600–0x81E000`（6,656 字节）。原生内存到 `0x81C600` 为止，名场面集把堆起点挪到了 `0x8C0000`，这一段没人用。放得下钩子（约 3.7 KB）和选项标记。要用 `storewatch` 实测确认没人写。
- **标题画面没有单独的处理函数。**
  - 主循环在 `0x14214C` 调用分派函数 `0x156740`。模式字 `0x6163C8 == 100` 时是标题菜单在等输入，就绪标志在 `0x6163D8`。
  - 钩子改为包住 `0x14214C` 这次调用：模式 100、就绪、按下 SELECT 时打开面板。
- **标题按钮贴图是一组 VT1 块（16–29），一次读入。** 不能像本篇那样只改第 6 块的读取立即数，要整组平移偏移表（和本篇进关标题的做法相同）。
- **信息框和按键图标：**
  - 信息框函数：`0x3914C0` 创建、`0x391500` 选择、`0x391510` 输入、`0x3915D0` 绘制、`0x391660` 销毁。
  - KVP 绘制：`0x390BE0`；按键样式小号 ○/× 是 45/37（本篇 47/39）。
  - 消息 id 21/22 和本篇相同，可以照旧轮换。
- **字库：**
  - 读取指令：`0x13AC14` 等五处；缺字回退：`0x13B3FC`。字库在 VT1 第 3–4 块（本篇第 2–3 块）。
  - 字库缓冲大小字：`0x4524E8`。
  - 繁体字库要用本篇那套线性区扩容，地址都已对应上。
- **显示选项：** SP 目前没有选项字（`tag_free_integrated` 只给本篇和 BEST 加了 `SRWZOPT1`），要先给 SP 加上。
- **存档卡：** SP 存在 `/BISLPS-25920*`，存档图标 13,038 字节（本篇 11,664），见 §5 第 2 条。
- **简体 SP 已经挂了钩子的位置：** 行宽、字形库、KVP 绘制内部、名场面集、无 BGM 等。新钩子用的位置都不冲突。

## 3. 光盘空间

- **DMY：** 122.6 MB，全零。
- **繁体副本：** 上限约 240 MB。
  - 整份成员约 170 MB，大头是 AIDDATA 79.5 MB、MAPMODEL 39.6 MB、VEFF2DX 38.2 MB。
  - VT1 里改过的块最多约 70 MB。
- **放不下 DMY 的部分接在盘尾**：沿用 SP 现有的 `iso_relocation` 加 VMAP 重指向，DVD-5 还有约 780 MB 余量。
- **能少存的：** AIDDATA 和 VT1 只存繁体不同的块，可以少很多。要看读取方式是否支持按块重定向；VT1 支持（偏移表），AIDDATA 待查。

### S5 图片（2026-11-18，进行中）

**组盘改为整份重定向 VT1**：
- SP 的 VT1 按组读取，每组的长度等于下一组的起始减本组起始，都取自同一张偏移表。改动任何一块的表项，都会让前一组的长度出错。S4 的做法是平移第 37 块以后的表项，结果第 30–36 组（额外关卡菜单）读错长度，繁体模式进额外关卡黑屏。
- 现在的做法：繁体模式下，`DATA/VT1.BIN` 的 VMAP 行指向追加在盘尾的一整份繁体 VT1（205 MB）。繁体可执行文件用它自己的 VT1 偏移表，不再需要读字库的立即数补丁、进关标题平移或表项平移。仍然要做的两处：只在繁体模式下加大字库缓冲；启用线性区回退（不启用的话，「級」「體」「連」等线性区汉字显示为空白）。
- 盘的大小：
  - 双语盘约 4.13 GB，DMY 用 86 MB。
  - 加音乐包后约 4.67 GB，单层 DVD 只剩约 30 MB。
  - 插图如果改动 AIDDATA（79.5 MB），DMY 放不下，就要接在盘尾，会超过单层 DVD。到时再定，模拟器和 OPL 不受盘大小限制。
