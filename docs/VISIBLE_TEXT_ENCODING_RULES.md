# 可见英文、数字、标点与空格的编码规则

2026-09-28 核对当前 Original、本篇 BEST 和 SP 的生产写入器与最终 ISO。

**普通双字节文本面中的可见英文、数字、标点必须使用双字节字形码。**
直接写入单字节 ASCII 可能改变后续字节配对，使文字显示为乱码；原始 ASCII 数字
`1`～`5` 的字节还与文字控制码 `0x31`～`0x35` 重合，不能作为普通字形直接写入。

## 语料、写盘与显示

| 对象 | 语料规则 | 写盘规则 | 默认版式 |
| --- | --- | --- | --- |
| 可见英文字母、阿拉伯数字 | 保留字母大小写、缩写、标识符和数值；现行逻辑身份使用 `A`、`MAX`、`56000`，输入的全角形式可以归一到该身份 | 使用原版全角双字节字形码；62 个英文字母和数字由 `original_fullwidth_ascii_overrides` 固定映射 | 普通对白每个可见字母／数字计 1 格，与汉字相同 |
| 中文正文标点 | 使用中文全角标点 `，。！？；：“”（）` 等；省略号使用 `……`；已审定波浪号、来源绑定的沉默按具体表现保留 | 使用中文发布字库／码表的双字节码，不能直接写 ASCII 标点字节 | 按对应排版档计格，并检查行首闭合标点和行末开括号 |
| 时间、数值、标识符中的符号 | 保留 `18:00`、`0.5%`、`MC.00` 等逻辑文本；不以中文替换或删除英文、数字和符号来解决布局 | `:`、`.`、`%` 等经过发布码表写为双字节；不得用通用编码器默认的单字节分支 | 保护时间、数字和标识符完整性，按实际字格断行 |
| 可见单词间空格、续行缩进 | 语料中的普通空格是逻辑分隔；普通对白续行使用 1 个全角缩进 | 双字节文本面使用全角空格 `0x8140`；不能写原始 `0x20` | 使用对应文本面固定格宽 |
| 变量、格式串和控制符 | `$n`、`$c`、`%s`、`<color:XX>`、`<width:XX>`、原始字节标记等保留完整语法 | 使用其规定的原始字节／操作码；不做全角字符替换 | 按控制符契约计算，不能当普通可见标点或英文计格 |

语料中的 `MAX` 与 `ＭＡＸ` 经生产编码后都为 `82 6C 82 60 82 77`。
语料中的 `56000` 与 `５６０００` 经生产编码后都为 `82 54 82 55 82 4F 82 4F 82 4F`。
因此“把语料归一为 ASCII 身份”没有将最终盘改成单字节文字，也没有让普通对白字格变窄。

中文字体复用了日文字形槽，标点必须使用发布码表。不要自行调用 Unicode 全角转换后
再用系统 CP932 编码来代替生产编码器。仅调用通用 `encode_text` 而遗漏生产 overrides，
仍可能写出危险的 ASCII；必须使用对应文本面的完整编码路径。

## 已有显示例外

全角双字节存储与字形推进宽度分别由编码和渲染契约决定。
普通对白采用 21 格 × 最多 3 行。标题贴图的英文已采用独立的墨迹宽度布局；
部分 COMPDATA 标题文本通过已验证的 `<width>`／`<space>` 控制码收窄英文。
这些是明确的文本面规则，不能推广为普通对白允许单字节 ASCII。
具体历史证据见 [`STAGE_TITLE_LAYOUT_20260912.md`](STAGE_TITLE_LAYOUT_20260912.md)。

SP 的 17 条 `＜ｔｍ＞…＜／ｔｍ＞` 动态数值模板需要独立确认运行时模板宽度与编码契约，
本轮保留原有语料和最终盘输出，不将其按普通文字重排或记为已验收。

## 当前验证证据

逐项结果见 [`visible-text-storage-20260928.json`](../config/editorial/visible-text-storage-20260928.json)。

- 本篇当前 ISO 全量内容回读证明剧情、SRVC、世界史、技能／武器效果等已检查文本面的危险原始可见 ASCII 为 0；可见空格检查亦为 0。62 个英文字母／数字字形与原版逐字节一致。
- 从 Original 和 BEST 最终 ISO 独立读取 STAGE 002／032，核对 `PLANT` 和 `FAITH` 的实际全角双字节码。BEST 的既有构建门禁另核对 84,338 个 STAGE 所有者的共享编码载荷。
- 从 SP 最终 ISO 独立读取 42 个 STAGE 块，扫描 7,895 个唯一文本载荷；排除合法控制码后，危险原始 ASCII 和单字节可见空格均为 0。
- 本轮归一字符身份的 6 条 SP 挑战对白全部核对原生位置与实际字节，包括 `MAX`、`MS`、`40000`、`56000`、`4`、`150`。
- 格式专项 8 项测试通过，其中 2 项新增用例覆盖全部 62 个字母／数字的全角等价存储，以及可见英文和运行时变量的不同编码契约。此前完整回归 578 项通过。

这些是编码、字库身份与静态回读证据；本轮未增加 PCSX2 人工画面验收。

## 本轮发现并修复的 SP 空格遗漏

首次检查字母／数字字形码时未将空格纳入同一个检查。继续按本规则扫描后，
发现前一张 SP 当前盘有 25 个唯一 STAGE 载荷包含原始 `0x20`，例如
`Black Gale`、`BLOCK WORD`、`The Big`；对应 29 个绑定（20 个普通对白、6 个显式标签、3 个地点标签）。
本篇当前盘已有可见空格为 0 的门禁结果。

SP 写入器现在对所有原生 STAGE 字段在存储边界调用 `two_byte_visible_spaces`，
将可见分隔符写为 `0x8140`，保留语料中的逻辑空格。17 项 STAGE 写回测试通过，
新增用例直接检查重新打包后的 `Ｂｌａｃｋ　Ｇａｌｅ` 字节，并核对未归属区域不变。
SP 独立重建 62.657 秒、批次及最终盘回读通过。原文和社区审阅状态没有改动。
