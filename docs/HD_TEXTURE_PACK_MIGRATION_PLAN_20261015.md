# 旧高清材质包向 PCSX2 2.x 的迁移方案（本体 + BEST）

2026-10-15。依据是同日的研究记录 [HD_TEXTURE_PACK_PCSX2_2X_PORT_20261015.md](HD_TEXTURE_PACK_PCSX2_2X_PORT_20261015.md)（命名规则、归档格式、静态部件表、验证数据都在那里），本文只回答“旧包的每个文件夹怎么迁、产出多少、先做什么”。范围：本体 SLPS-25887 与 BEST SLPS-73270；`XAN-斩` 文件夹不处理。

## 0. 两版通用，一套产物

- 本体和 BEST 的贴图归档逐字节相同；BEST 只改了 TWP 的 13 个动作块，用静态部件表比对，13 块的部件矩形只比本体多 1 个（块 857 的一个 8×8），其余 1,456 个完全一致。所以转换结果一份即可。
- PCSX2 按序列号找目录：`textures/SLPS-25887/replacements/` 与 `textures/SLPS-73270/replacements/`。发布时放同一份内容（macOS/Linux 用符号链接，Windows 用目录联接或复制）。用 SP 盘（SLPS-25920）采集 dump 时，dump 会落在 SP 的序列号目录，要搬回来。
- 旧包里 `face` 的 1,295 张已经在 09-14 转成 `-r513x513`（中场 PILOT 画面）；本文的新工作不覆盖它，只补其他画面的变体。

## 2. 路线取舍（2026-10-15 用户决定：A 必须最终做到纯静态全量产出；B 只用少量实测把剩余两类矩形的生成规则找出来，写回 A；D 不做，目标是官方 PCSX2 2.x 直接可用）

| 路线 | 做什么 | 覆盖 | 适用对象 | 成本 |
| --- | --- | --- | --- | --- |
| A 静态转换 | 从归档解析部件/瓦片矩形，重算 2.x 文件名，在旧 4 倍图上裁剪 | BA、BAC、addition 全量；maps 的整瓦片 | 所有 PCSX2 2.x / ARMSX2 用户 | 转换器 2–3 天；瓦片表解析 1 天 |
| B 游戏内矩形日志 | 在 `FUN_002ef830` 贴图分支和 `FUN_002f5bc0` 每格循环挂钩，把 CLAMP 四值、贴图组、picture、调色板槽、CSA 写入 RAM 环形缓冲；LRPS2 无头快进跑 SP 战斗鉴赏，驱动脚本读走日志并记录机体/武器（经 siWp 表映射到块号）；命名交给 A 的流水线 | 验证 A 的覆盖率；补动态 UV 窗口、裁切瓦片等 A 枚举不到的矩形 | 同上 | 挂钩半天到一天，驱动自动化一到两天，换算半天 |

顺序：A 先按现有规则出全量（已覆盖 dump 样本的 91% 精灵矩形和 64% 背景矩形）；B 只跑小样本，目的不是采集文件，而是找出 A 还枚举不到的两类矩形是怎么算出来的，把公式写进 A 的静态枚举，让 A 达到 100%。这两类是：

1. 背景和图层的裁切零头：区域 = 瓦片矩形被图层可见区边缘按滚动量裁掉一截。滚动量来自镜头流和图层参数的关键帧插值，是确定性的，可以静态模拟；B 的日志用来核对模拟出的滚动值与实际一致。
2. 61 张精灵矩形（dump 样本的 8.8%）：u、v、w、h 沿时间平滑变化，不在任何关键帧里，疑为引擎按时间推进的 UV 窗口或关键帧间插值。B 的钩子要连对象种类、流位置、帧时间、插值标志一起记，才能定位生成函数并还原公式。

face 其他画面与 ui 的形态也由同一轮小样本确定。路线 D（自家分支关闭 region）已排除。

## 3. 工作分解

### 第 1 步：（已取消）路线 D

### 第 2 步：静态转换器 `textures/tools/convert_static.py`（首版已完成，见 [产出与回归](HD_TEXTURE_PACK_STATIC_CONVERT_20261015.md)：283,925 个文件 21.4 GB；精灵 dump 名 678/696、背景整瓦片 500/684 有源者全部命中）

输入：四个归档 + 旧包目录；输出：`textures/SLPS-25887/replacements/<folder>-regions/` 下的 PNG 与一份 manifest（TSV：新名、来源归档/块/组/picture、矩形、旧包文件、是否有源）。

核心规则（都已在研究文档里验证过）：

1. 部件枚举：`twp_parts.block_parts()` 对 twp/trb/tci 全部块；(组, picture) → TIM2 picture；按贴图哈希去重。
2. 区域：默认 `[u, u+w) × [v, v+h)`；模式 1（454 次引用）按内缩/镜像公式，镜像时 WMS=REGION_REPEAT，region 按 PCSX2 规则取 `[MAXU, (MINU|MAXU)+1)`。
3. 名字：`TEX0Hash` = 子矩形索引字节逐行 XXH3（PSMT4 先展开成每像素一字节）；`CLUTHash` = PSMT8 两组 256 色各一名；PSMT4 取调色板槽窗口按 CSM1 重排后 `CSA*16` 起的 16 项；`bits` 按 PSM/TW/TH。超出图集边界的 3,036 次引用按头像 513 的页回绕方式取相邻 VRAM 页字节。
4. 裁剪：旧包 PNG 是 4 倍整图，裁 `(4u, 4v, 4w, 4h)`；镜像/内缩变体裁 region 对应的矩形。
5. 回归：生成的名字集合必须包含 `verified_dump_rects.tsv` 里 602 张静态可复现的 dump 名（精确字符串相等），作为单元测试。

未决项要先处理：604 条部件引用了 TIM2 包里不存在的 picture 序号（twp 525、trb 46、tci 33），需要确认是组字段的别的含义（例如指向对手机体的贴图组）还是无效记录。

### 第 3 步：路线 B 小样本实测，提取剩余规则（服务于 A）

- 挂钩：`FUN_002ef830` 贴图分支算完 CLAMP 后、`FUN_002f5bc0` 每格写 CLAMP 处，各插一个 cave 调用，记录 {帧计数, 对象指针/种类, 当前流记录偏移, 插值标志(+0x1c), unit 槽, 贴图组, picture, 调色板槽, CSA, WMS/WMT, MINU, MAXU, MINV, MAXV, 图层序号与滚动值} 到 RAM 环形缓冲；类型 0 绘制必须执行到挂钩点，只跳过 present（沿用 □ 跳过原型的冻结 present 思路，cave 与 `assemble_hook.py` 工具链现成）。
- 样本：LRPS2 无头，SP 战斗鉴赏普通模式挑十几场：包含 dump 样本里未复现矩形所属的机体（块 329、199、658、296、732、690）、几张典型背景、命中/回避/防御/反击各一；主篇一段剧情和菜单各一次给 face/ui。
- 分析：日志 → (块, 组, picture, 矩形) 与 A 的清单比较；对 A 没有的矩形，用日志里的帧时间、流位置和插值标志回到静态数据里找生成函数（关键帧插值 `FUN_002ecfb0`、图层滚动 `FUN_002f5bc0`），推出公式并在 `twp_parts.py` / `tbg_tiles.py` 里静态模拟（含浮点插值与取整细节），再用日志逐帧核对。
- 验收：A 的静态产出覆盖全部 696 + 1,070 张 dump 名和小样本日志里的全部矩形；之后不再需要跑 B。
- 兜底：若某类矩形被证明依赖运行时随机或输入，才退回"用日志采集的实际值"产出，并在报告里说明数量。

### 第 4 步：tbg 整瓦片产出（并入第 2 步）

瓦片表解析已完成（`textures/tools/tbg_tiles.py`、`tbg_tiles_manifest.json`，147 块、17,060 个整瓦片矩形，1,070 张 dump 哈希全部一致）。转换器把整瓦片当作普通部件产出；裁切零头交给第 3 步。

### 第 5 步：face 其他画面变体（0.5 天）

用第 3 步的剧情 dump 确认形态，若是固定矩形就按 `face_region_hash.py` 的方式批量生成 1,296 张；若是整图则旧名直接可用。

### 第 6 步：打包与发布

- 目录：`replacements/BA/`、`BAC/`、`maps/`、`face/`、`ui/`（按来源归档分目录，便于增量），两个序列号目录。
- 规模：约 9 万个小 PNG；PCSX2 用异步加载即可，`PrecacheTextureReplacements` 关闭。
- 验收：PCSX2 2.8 与 ARMSX2 各跑一场战斗、一段剧情、一次中场，OSD 替换计数与第 1 步对照；抽查部件边缘无接缝。

## 4. 风险与边界

- 旧包作者在整图上作画，部件边界处越界的高清笔触会被裁掉；原版部件在图集里不重叠，所以只影响越界笔触。
- 裁切瓦片随滚动量变化，理论上每个瓦片可派生出几十种零头，静态枚举不划算，只能靠采集覆盖常见位置；没覆盖的零头以原生分辨率显示一两帧。dump 里零头占背景绘制的 36%。
- 精灵里还有约 9% 的 dump 矩形来源动态（运行时推进的 UV 窗口），同样只能靠采集。
- 19 张未定位的 ui 图若是渲染目标，2.x 会按 PSMCT32/24 形态处理，旧包对应文件可能永远用不上。
- 旧包不含的图集（上表“没有高清源”）与 XAN 文件夹不在产出里。
