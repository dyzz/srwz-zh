# 本篇／BEST／SP 译名一致性审计（2026-10-16）

只读审计，未修改语料、构建脚本或 ISO。后续处理：第 1 节 BEST bug 已于 2026-10-17 修复；第 2–4.1 节按用户逐条决定统一，见 [译名统一记录](NAME_UNIFICATION_20261017.md)。比较对象为 2026-10-16 21:45 的三张当前产物：`build/iso/zh-release-original/current-original.iso`、`build/iso/zh-release-best/current-best.iso`、`build/iso/special-disc/sp-current.iso`，以及各自日文原盘。

## 结论

1. **本篇与 BEST 的译文一致**。两版 COMPDATA 中约 9,500 个字符串指针、2,452 个机师名字段逐槽配对，中文全部相同。唯一的问题是 BEST 构建器写坏了一条能力说明（见第 1 节），属于构建 bug，不是译名分歧。
2. **SP 落后于本篇**。SP 的机体、武器、说明文字是从两份冻结的本篇快照迁移来的：COMPDATA 文本取自 2026-09-17 的本篇构建，名称校验参考取自 2026-09-29。之后本篇的改名都没有同步到 SP，约 20 个机体名、武器名仍是旧译。
3. **SP 自译的部分另有一批分歧**：战斗鉴赏的士兵标签、个别人名音译、图鉴里的旧术语。仅限 SP 的名称在 SP 内部是一致的（105 个名称，163 处引用，无矛盾）。
4. **本篇内部也有不一致**。最主要的是机师名表的“姓／名”字段，约 25 名角色的姓与本篇剧情、战斗字幕、图鉴的写法不同。SP 原样继承了这张名表。

## 1. BEST 专有：盾牌防御说明被清空（构建 bug）

`tools/srwz/best_build.py:355` 的 COMPDATA 固定槽声明为 `(0x6C550, 0x6C5E0)`。但在 BEST 和 Original 的日文原盘里，`0x6C5C0` 处都已经是另一条字符串的开头：「防御」選択時、「シールド防御」……（盾牌防御能力说明）。写入器在 `0x6C550` 写完“使伤害减轻1000……”后，会把剩余空间一直清零到 `0x6C5E0`，盾牌防御说明的前 32 字节因此被抹成 0。

| 产物 | `0x6C5C0` 处内容 |
| --- | --- |
| Original 中文 | 选择“防御”时，装备盾牌可通过“盾牌防御”将伤害进一步减轻…… |
| BEST 中文 | 32 个 0 字节，后面残留“盾牌防御”将伤害进一步减轻……；指针仍指向 `0x6C5C0`，所以显示为空 |

建议把槽上界改为 `0x6C5C0`，然后重建 BEST。复现脚本：`best_check2.py`。

## 5. 为什么会漏掉，以及建议的修订顺序

- SP 写回链没有接入全局术语门禁（`tools/srwz/glossary.py` 只在本篇构建中执行），SP 名称校验器又以冻结快照为准，所以本篇的改名传不过去，还会被校验器挡下。
- 本篇的术语门禁只检查带 `glossary_refs` 的条目；机师名表、默认小队名、零件说明等表格类语料不在门禁内。

建议顺序：

1. 修 BEST 固定槽上界（`best_build.py:355`），重建 BEST。
2. 确定第 4.1 节的方向，然后修本篇名表和第 4.2 节的零散旧译，重建本篇。
3. 以新的本篇构建为基础，刷新 SP 的 `OG_CHINESE` 答案表和 `shared-name-reference.json`，重新迁移 SP 的 COMPDATA；同时改第 3 节的 SP 自有语料（`system-text.json`、`native-text.json`、`instructions-overrides.json`、`sp-reviewed-supplement.json`、`squad-names.json`、剧情／挑战对白各条）。`reviewed-non-stage-text.json` 是审阅台账，也有旧名，可一并刷新。
4. 把第 2–4 节的检查固化为 SP 和本篇的构建检查：按日文原文配对三盘 COMPDATA，并用全局术语表扫描 SP 全部语料。

## 方法与复现

脚本与结果：`work/review/main-best-sp-consistency-20261016/`。在该目录下运行（在 `srwz-zh/` 下执行亦可，脚本使用绝对路径读取 ISO）：

```sh
python3 compdata_pairs.py compdata.json   # 三盘 COMPDATA 日中逐槽配对（约 1 秒）
python3 analyze1.py                        # 同一日文在 Original／BEST／SP 的中文差异
python3 analyze3.py                        # SP 全部语料对照全局术语表与本篇名表
python3 analyze4.py                        # SP 独有名称的内部一致性
python3 fullname.py                        # 本篇机师全名 vs 正文写法
python3 best_check2.py                     # BEST 0x6C4C0–0x6C640 字符串回读
```

- COMPDATA 按指针配对：同一指针槽位的日文原串与中文串组成一对，机师名按记录字段配对。中文统一用 SP 字库读回表解码（本篇与 SP 字库映射一致）。
- SP 语料的术语核对使用 `relevant_glossary_terms`（最长匹配优先），再加上本篇 COMPDATA 中唯一译名的片假名机体、武器、机师名。比较时忽略宽度标签、空格和引号。
- 本篇语料只保存日文哈希，第 4 节因此改用中文侧比对：以机师名表的“名·姓”组合反查正文。
- 局限：剧情对白中的漏译、意译（如“未知目标／不明机体”）没有逐条判定；图鉴正文只核对了专名。没有在模拟器中查看画面。
