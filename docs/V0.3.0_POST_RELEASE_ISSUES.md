### 漏扫原因

- 修复前 `corpus/zh/story-z-reports.json` 的范围明确限定为
  “符合 PP 奖励模式的非对话 Z Report”，只有上述两条 PP 正文。
- 修复前 `tools/build_story_component.py` 的 `_discover_z_reports()` 虽然会扫描所有
  STAGE 块，但筛选正则固定为
  `^.+チームはＰＰ＋[０-９]+$`；`config/story-component.json` 又把期望值
  锁为 2 条唯一正文、2 个目标、1 个 archive index。因此 4 个结构相同的
  武装追加记录从选择阶段就被排除，后续固定槽写回、重读和 ISO 验证都看不到它们。
- SLPS 中 `menu/SLPS/00/0286`“获得换装部件”及
  `menu/SLPS/00/0287`“获得某物”是另一套可执行文件格式串，并非这些
  STAGE 字面量的共享模板；它们已经汉化也不能覆盖本次弹窗。
- 根因是 Report 类型枚举／覆盖合同过窄，不是武器术语缺失、中文编码失败、
  STAGE 解压失败或 PCSX2 渲染异常。
