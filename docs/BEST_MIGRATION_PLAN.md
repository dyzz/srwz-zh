## 5. 后续迁移顺序

1. **补齐候选运行覆盖。** 已核验一个既有存档承接到下一关；接着核验男主新游戏、保存后重载、战斗字幕和音频索引，再按已知 Best 改动覆盖图鉴、变形/分离、弹数、预览及模式菜单。输出绑定当前 ISO 的证据。
2. **建立正式版本配置。** 将盘号、原盘哈希、成员名、各基址、指令签名、归档表和补丁原字节放入独立 Best 配置。运行 runner 也需要 Best 自己的输出大小/哈希契约；本次已在实验目录提供，原版契约保持原样。
3. **从源语料构建 Best。** alpha1 是冻结中文组件与 Best 原文之间的迁移桥梁。正式链应共享中文翻译，并明确维护 Original/Best 的不同日文来源与哈希映射；新变体、新增 SRVC 记录、声优更正及动态姓名条目要有固定归属。不能一直靠二进制对齐推断。
4. **纳入现有构建和验证入口。** 为 Best 生成自己的组件锁、ISO 配置和验证清单，确保一次文字润色能分别构建两个版本；通过一次干净重建与复现。
5. **决定默认底盘。** 完成以上回归、保存重载和 PCSX2 手工验收后，再把 Best 设为默认。普通记忆卡已有初步兼容证据；跨版即时存档不作为迁移方式。公开补丁的原盘外部来源和 xdelta 还原另行核验。

当前不需要重做整套翻译、字库或已审核图片。后续主要工程工作是正式化版本配置和验证覆盖，随后中文编辑工作仍可集中在现有语料润色上。

## 6. 复现与证据

实验构建入口：`tools/build_best_candidate.py`。固定输入只在第一次准备时创建；再次运行逐文件检查锁，不会静默接收其他任务后来修改的语料或组件。

```sh
python3 tools/build_best_candidate.py --components
python3 tools/build_best_candidate.py --iso-only
python3 -m unittest discover -s tests -p test_build_best_candidate.py
```

本地首轮生成输入依赖此前完成的原版/Best 分析资料。此脚本和忽略目录内的冻结快照共同构成 alpha1 的复现材料；它尚不是只凭干净 checkout 就能直接重建的正式生产入口。
