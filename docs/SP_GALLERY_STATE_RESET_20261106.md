# 鉴赏中途退出后的镜头残留调试记录（2026-11-06）

用户回报：格兰维昂合神刚起飞时退出，之后魔神Z出击的镜头不对。

## 结论

中途退出跳过了原生的镜头收尾。自然播完不影响后面的演出（用户的判断）：修复前的版本，第 1 行自然播完后第 10 行只有几百像素的时序差，退出后差上万像素。

特效启动时开始一段镜头运动，运动走完后，每帧更新调用 `FUN_0019d850` 收尾。退出后每帧更新不再运行，收尾走不到；鉴赏退出时调用的 `FUN_001ac8e0` 只清特效本身，不管镜头。

## 修复

`gallery_reset_camera`，在每个演出保存快照前和结束时各调用一次：

1. 清 `0x4caf58`，调用 `FUN_0018f9a0`：特效指令 8 的收尾，结束震动。
2. `0x6296d8` 非 0 时调用 `FUN_0019d850`：原生镜头收尾。

中途加过的 10 个恢复区块和手写清零都已删除，只靠这两步验证结果相同。

## 反编译说明

### 收尾相关

| 函数 | 作用 |
|---|---|
| `FUN_0019e1b0` | 开始镜头运动。按 `0x628de0` 的类型设置 `0x629690`、`0x6296d0`、`0x6296d8` 等，并关掉图层。由特效启动调用（经 `0x19e260`）。 |
| `FUN_0019d9d0` | 每帧推进镜头运动，走完时调用 `FUN_0019d850`。 |
| `FUN_0019d850` | 镜头收尾，见下。 |
| `FUN_0015e870` | 把镜头角度 `0x61bdd8/dc/e0` 换算成弧度，写 `0x61bc80～88`，算出视角 `0x61bdd0`（0～3）。 |
| `FUN_00136ea0` | 按光标格 `0x4eb1c0/c1` 重算镜头目标 `0x4eb1d0～f8`，含地形高度。 |
| `FUN_0018f800` / `FUN_0018f9a0` | 震动开始 / 结束。写手柄震动参数 `0x625308` 起，结束时清 `0x625140/41`。 |

`FUN_0019d850` 依次：

1. 清运动标记 `0x6296d8`。
2. 清 `0x457740/44`、`0x457780/84/88`（偏移和旋转），`0x61bdd8` 设为 -384（默认俯角）。
3. 由镜头目标反算光标格 `0x4eb1c0/c1`，调用 `FUN_0015e870` 更新角度。
4. 清 `0x629690`，恢复屏幕图层（`0x5a3ea4` 等）。`0x628db8` 非 0 时跳过图层，清 `0x628db8`。
5. 调用 `FUN_00136ea0` 重算镜头目标，清 `0x629718`。

### `FUN_001ac8e0` 清除的地方

| 地址 | 内容 |
|---|---|
| `gp-0x780c`（`0x4cb064`）、`gp-0x77e4`（`0x4cb08c`） | 特效状态，清 0 |
| `gp-0x77e8`（`0x4cb088`） | 设 0xffff |
| `0x62aa58`、`0x62aa70` | 特效块状态 |
| `0x629690`、`0x6296a8`、`0x6296c8`、`0x6299f0` | 特效子系统的标记 |
| `0x629bb0` 起，40 项，每项 0x50 | 特效池：资源和状态指针、+0x3c、+0x3f 清 0，+0x2c 设 0xffff |
| `0x62a860` 起 | 动态特效资源表：释放（`FUN_0013a390`），项清空 |
| `FUN_001a93f0(0,0)` → `FUN_001a9d50(0x629770)` | 特效贴图对象清零 |
| `FUN_001d7eb0(*0x630900)` | 条件满足时停掉一个子系统（`FUN_001d7160`），未细查 |

### 它遗漏的地方（中途退出后实测留下）

| 地址 | 内容 | 现在由谁收尾 |
|---|---|---|
| `0x6296d8` | 镜头运动标记 | `FUN_0019d850` |
| `0x629708` | 旋转运动的起始值（实测 2.56），`FUN_0019d9d0` 用它算 `0x457784` | 没有直接清；标记清除后不再读取，验证无影响 |
| `0x457740/44`、`0x457780～88` | 偏移和旋转 | `FUN_0019d850` |
| `0x61bdd8` | 镜头俯角 | `FUN_0019d850` |
| 屏幕图层 `0x5a3ea4` 等 | 图层状态 | `FUN_0019d850` |
| 震动标记 `0x4caf58` | 震动 | `gallery_reset_camera` |

还有几段非镜头差异（`0x6205f1`、`0x620608`、`0x6206ce`、`0x62516c`、`0x4cae54`、`0x61e8cd`、`0x61f8e0`、`0x5a1e84`）没有处理，看起来和声音、手柄有关，未逐个确认。

## 验证

第 1 行 ○ 退出后进第 10 行，和干净运行比，每 60 帧比一次，到第 1200 帧：

| 版本 | 170、230、300、360 帧退出 |
|---|---|
| 修复前 | 差 8,700～133,000 像素 |
| 修复后 | 0 |

- 260 帧退出（中途那版测试）：错开 1 帧后差异从 1.4 万降到约 1,600，是特效晚开始 1 帧。
- 第 18 行：170、300 帧退出后差异为 0。
- 全部 22 行：第 1 行退出后比到第 270 帧，20 行差异为 0。第 15、19 行从第 210 帧起有差异，错开 1 帧后降到 85～705 像素，是时序差，不是残留。之前记成亮度差是误判。
- 全部 22 行、○ 和 △、250 与 420 帧退出，共 88 次：缩放、旋转、编队、单位表逐字节恢复。
