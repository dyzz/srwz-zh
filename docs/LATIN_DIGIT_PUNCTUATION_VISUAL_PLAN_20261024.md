# 剧情与图鉴英文／数字／标点视觉修正计划

2026-10-24。目标：在**接受内联标签**的前提下，解决剧情对白和图鉴正文里英文、数字、标点"看起来太大""底边和中文不齐"的视觉问题。只处理剧情和图鉴两类显示面，可以对它们单独定参数；不追求所有界面共用一套英数字号。

本文是计划，尚未改动源码、语料或 ISO。用户审阅后再开始阶段 1。

| 纳入 | 不纳入 |

| 紧缩段内的英文、数字和 `. - / % : ' ~ ( ) +` 等表达式标点 | 无标签自动窄化（分类 B 路线，已放弃） |
| | 挪动现有码位（码表保持只追加） |

不再做的 10-21～10-23 工作（原生测宽接入、分类 B 窄化、标点挪入 ASCII 格、SP 去冻结）已经整体退回，留存在 `refs/backup/uncommitted-20261024`，本计划只把其中核对过的事实当参考。

## 2. 现状

### 2.1 剧情对白

- 语料里共有 2,385 段紧缩作用域，形状几乎全是 `<width:0E><space:0C>…<width:16><space:16>`：字宽 14、推进 12，段尾恢复为 22。**没有任何字高标签**，字高沿用当时的显式字高。
- 2026-10-24 从当前 ISO 的可执行文件直接读出的描述符（+0E..+15，A／B 相同）：

  | 描述符 | Original | SP | 宽／高／推进／行距 |
  | --- | --- | --- | --- |
  | 消息窗口（10-22 认定为对白正文） | `0x41E770` | `0x479F60` | 21／12／21／14 |
  | 前一个相邻描述符（10-21 认定为"默认剧情对白"） | `0x41E730` | `0x479F20` | 22／11／22／15 |
  | 全屏叙述窗口 | `0x41E200` | `0x4799F0` | 21／12／21／14 |

  两轮调查对"对白正文用哪一个"的绑定不一致。10-22 的 LRPS2 字形记录支持 21×12：SP 对白里没有标签的中文是 21×12（备份 ref 中 `docs/CLASSIFIED_LATIN_METRICS_PLAN_20261022.md` §1）。阶段 1 要用"带标签行 vs 无标签行"重新确认。
- **2026-10-24 已改**：剧情语料 146 个文件里的 2,375 段紧缩作用域，加上 5 个"一万两千"前的孤立恢复标签，段尾都由 `<width:16><space:16>` 改为 `<width:15><space:15>`。`story_dialogue` 排版档的默认推进也由 22 改为 21。脚本和报告在 `docs/issue-assets/story-restore-21-20261024/`。字高仍未恢复，见下一条。
- 改之前的恢复值 22 与原生 21 不一致。按当时的 LRPS2 观察，带标签的行在恢复之后，余下的中文按显式 **22×11** 绘制，而同一窗口里没有标签的行是 21×12。也就是说，**一行里出现英数段后，它后面的中文也会变样**。这条需要在阶段 1 重新确认。
- 段尾只恢复宽和推进，不恢复字高，所以段后中文的字高仍是进入段之前的显式值（10-22 观察到的是 11），不是原生 12。补上 `<height:0C>` 放到阶段 3，和段内字高一起由编译器生成。
- 图鉴的上层按字节找 `0A` 拆行，所以字高 10 不能写成 `33 0A`。剧情绘制入口 `0x2212B0` 也会拆行，是否同样按字节拆还没确认，先按同样处理：剧情里也不写 `33 0A`，改用 `8A`。

### 2.2 图鉴正文

已经在生产中，来自 10-21 的提交（`54f98351` 等）：

- 逐行同步补丁 `library_body_metrics.py`：每行开始前把描述表尺寸同步到显式状态，中文每行回到原生尺寸。
- 光学字高补丁 `library_optical_metrics.py`：字高控制 `33` 的参数 `8A` = 字高 10，`8B`–`8E` = 字高 11–14 并把字形上移 1。**这个补丁位于剧情和图鉴共用的正文解析器里**，所以剧情同样能用这些参数。
- 紧缩数字自动减高 `compact_digit_metrics.py`：宽 14、推进 12、字高 9–12、本次解析没有显式字高时，原版数字字高自动减 1。
- 图鉴字号由 `library_typography.py` 在构建时生成，语料不存高度标签：
  - 角色：中文 21/12，字母 14/12（Y−1），数字 14/11。
  - 机体：中文 21/10，字母 11（Y−1），数字 10。
  - 术语：不套用英数字高规则。
- 结果：LRPS2 上莉露、亚历克斯的英数墨迹约 18px，邻近中文约 19–21px，Geo 下缘基本齐，仍有约 1px 墨迹差。**机体页在最新批次之后没有做运行验证**，术语页英数没有调过。

### 2.3 标点

- 紧缩段的字符集（`renderer_metrics.COMPACT_SCOPE_CHARACTERS`）已包含 `. , : _ ' / + % ~ = ( ) [ ] -` 等，这些标点跟着英数一起被压窄。但它们用的是全角字形，是按 24 格居中设计的，压到 14 宽以后的形状和位置都没有单独校过。
- 句子里的中文标点 `。，！？：；` 不在紧缩段内，本计划默认不动它们（见 §6 待决定项）。

### 2.4 底边不齐的来源

24×24 源字格里的墨迹范围（`docs/issue-assets/library-font-fix-20261021/glyph-ink-metrics.json`、`docs/issue-assets/automatic-digits-20261021/glyph-metrics.json`）：

| 字类 | 墨迹 Y 范围 | 墨迹高 |
| --- | --- | --- |
| 中文（地、统、特、中…） | 1..21 或 2..21 | 19–21 |
| 大写字母（A、E、G） | 3..20 | 18 |
| 数字（0、1、3、4） | 2..21 | 20 |
| 小写 x 高字母（e、o） | 8..20 | 13 |

字高缩小时，字是以顶部为基准缩的，底边会跟着上移。原生的光学修正只有"上移 1"一种。所以要让各类字的底边都和中文对齐，需要按字类分别配"字高 + Y 偏移"，不能只调一个字高。

## 3. 手段

### 3.1 内联标签（主要手段）

在紧缩段里补上字高，并在段尾完整恢复为该窗口的原生值：

```text
<width:0E><space:0C><height:XX>GEO 013<width:15><space:15><height:0C>
```

- 段内字高用 `0B`（11）、`0C`（12）这类普通参数，或者用 `8A`–`8E`（10，或 11–14 加上移 1）。
- 段尾恢复为 21/21/12（剧情、角色、术语），机体恢复为 21/21/`8A`。
- 字母、数字、标点如果需要不同参数，就在段内再切一次字高。图鉴现在已经这样做。

### 3.2 光学补丁扩展（按需）

如果阶段 1 测出现有"上移 1"不够，就给 `library_optical_metrics.py` 再加几个参数值，例如上移 2、下移 1。约束沿用现有补丁：

- 只用现有补丁区和已核对的解析栈帧字节，不新增 ELF 段、BSS、堆或持久全局量。
- 三版独立前像校验，地址或原始字节漂移就拒绝。
- 每次解析入口清零光学标志，只改字形记录的 Y，不改游标、推进和行距。

### 3.3 不改测宽的前提

原生测宽只认识 `31`/`32`/`34`，会把 `33 xx`、`35 xx` 当成一个双字节字来计宽。只要带字高标签的文本不进原生测宽（居中、右对齐、截断），就不会出问题：

- 图鉴正文是逐行直接从左边画的，已经验证过。
- 剧情对白是否完全不经过测宽，**需要在阶段 3 核对**，包括 Back Log、姓名框、自动换页这几条路径。如果发现有测宽消费者，就回到"剧情只用 width/space"，仅调整恢复值。

### 3.4 标点字形（按需）

如果标点单靠缩放和偏移仍然不好看，就为窄标点**追加新码位**，配专门为 14 宽设计的字形，只在剧情和图鉴的紧缩段里使用。旧码位一个不动，SP 和菜单码本不受影响。只在阶段 2 证明有必要时才做。

## 5. 风险

| 风险 | 处理 |
| --- | --- |
| 剧情某条路径会测宽 | 阶段 3 核对；有的话那条路径退回只用 width/space |
| 字节增长超出槽位 | 构建门禁会报错；必要时缩短作用域，比如合并相邻段 |
| 光学补丁位于共用解析器 | 新参数值只在作用域里由编译器生成；其他文本不带这些参数就不受影响 |
| 不同模拟器的上采样会影响像素读数 | 以 LRPS2 原生分辨率截图为准，比较相对差，不比绝对像素 |
| 同一字高下各字形留白不同 | 按字类分别验收，不按单个样本推广到全部字符 |

## 7. `<z>` 作者标签（2026-10-24 已实施，未提交）

- **写法**：剧情语料里写 `<z>PLANT</z>`。构建时展开成原生控制码（[compact_scopes.py](../tools/srwz/compact_scopes.py)），例如 `<width:0E><space:0C><height:0B>PLANT<width:15><space:15><height:0C>`。段内按字母、数字显式设字高（字母 `0B`=11，数字 `8A`=10），段尾把宽、推进、字高三项都恢复为原生 21/21/12。`《…》` 关键词正文里不插字高切换，保证和关键词表逐字一致。

### 7.1 标点与图鉴复测（2026-10-24）

用户确认剧情里的字母不上移，沿用 `<z>` 默认写法（字母 11、数字 10）。剧情加测 5 句带标点的样本，图鉴角色页（亚历克斯）和机体页（魔神 Z）各测 2 句，都在 `sp-current.iso` 上用 RAM 注入。结果见 [results.json](issue-assets/z-scope-20261024/lrps2/results.json)、[剧情对比图](issue-assets/z-scope-20261024/lrps2/story-punctuation.png)、[图鉴对比图](issue-assets/z-scope-20261024/lrps2/library-punctuation.png)。

- **剧情 `<z>`**：`- . % / : ' ～ （ ） + ,` 和空格都是 14 宽，字高跟着前一个字的字类走（字母段 11，数字段 10）。段后的中文和中文标点（`、。！，：`）都是 21×12，和无标签的行一致。
- **图鉴角色**：字母 14×12 上移 1，数字 14×11，段内标点跟着字类，段后中文 21×12。
- **图鉴机体**：字母 14×11 上移 1，数字 14×10，段后中文 21×10。
- **半角括号**：`(` `)` 会被编成单字节 `28`/`29`，游戏按双字节读就错位，整段不显示，后面的字也乱。所以 `<z>` 只允许全角 `（）`，半角括号直接报错。生产构建的 ISO 回读本来就会拒绝裸 ASCII。

### 7.2 按用户意见调整参数（2026-10-24）

用户看过 7.1 的截图后的意见：剧情英文已经合适，数字要下移 1 或者改成 11；图鉴数字合适，英文要下移 1。

- **剧情数字改为 11**：原生光学补丁只能上移，不能下移，所以选"改成 11"。现在剧情字母和数字都是 `0B`，段内不再切换字高，每段少 2 字节。"记忆卡（PS2）！！！"（`017DA0`）因此又放得下了（正好 48 字节），已恢复 `<z>`；"Present arms！"（`01EBC0`）仍需 49 字节，还是没有紧缩段。
