# 英文、数字和表达式标点收窄：补充统计与验证

2026-09-28，承接 [英文首轮统计](COMPACT_LATIN_COUNT_20260928.md)。
本轮将纯数字、时间、小数、百分比、分数、范围和上下文中的表达式符号纳入规则。
仅修改作者工具、算法支持和规则，尚未批量改语料或重建 ISO。

## 统一规则

- 仍以全角双字节字形存储；逻辑字母、数值及表达式身份不变。
- 连续英文／英数名称、纯数字和数值表达式至少 3 个可见字符时可生成窄距范围。
  例如 `40000`、`606`、`23:00`、`0.8`、`99%`、`1/10`、`1～3`。
- 型号内的连字符／斜杠，以及数值中的点、冒号、正负号、百分号、范围号和乘号
  随表达式处理。ASCII 逗号只在 `1,000` 这样的千位分组中纳入；
  中文 `，。！？、“”` 和其他正文标点保持原宽及既有断行禁则。
- 1～2 字符短段如 `1`、`20`、`Z`、`MS` 保持默认尺寸。
- 默认紧凑值仍为 `width:0E / space:0C`；恢复值按显示面声明。
  可见 `%` 之后先恢复 `space` 再恢复 `width`，避免被编码器当成
  `%<width:XX>` 格式串语法。百分号仍编码为原有可见双字节字形，没有插入空格。
- `÷` 在 14 px 宽的对照中辨识度下降，含除号的完整表达式暂时保持默认尺寸。
  布局器仍能测量显式指定的符号宽度，新增自动作者规则不将除号压窄。
- 控制码、变量和动态 `tm` 模板继续按自身契约处理。

实现入口为 `compact_visible_runs`，旧名称 `compact_latin_runs` 与其共用同一规则。
闭合表达式作为不可拆开的布局单元，算法兼容两种恢复标签顺序。

## 本轮 LRPS2 选样

数值对照当轮输入 SP ISO SHA-256：
`dcc04fb9aa5ef9555597f0e2dd5083e6c05e9c2d1f16c1d088b4f2bcc390e700`。
启动初始化后使用同 ISO 隔离状态，生产编码后检查 RAM 槽容量再注入。

- 真实对白 7 组：`40000`、`56000`、`23:00`、`0.8`、`99%`、`1/10`、`1～3`。
  默认／收窄对照均可读；中文尾部、下一物理行及正文标点正常。
- 真实名称 2 组：`塔米纳斯606`／`200毫米连装炮`，
  `塔米纳斯909`／`12.5毫米CIWS`。机体名、武器列表和详情可读，恢复尺寸正常。
- 合成符号对照：`-10`、`+10`、`3×4`、`3÷4`，以及全角输入的
  `１８：００`、`０．５％`。前述常用符号收窄可读；除号作为辨识度不足的对照保留。
- 加入除号保护后再次运行：其余表达式收窄，`3÷4` 保持原宽，除号可辨识。

共审看 23 张截图。上述真实源文字通过 RAM 对照验证，未到达其原生场景；
本篇源对白借 SP 窗口测试，不构成本篇 Original／BEST 的新运行证据。
`±`、千位逗号等另有静态编码／布局覆盖，未宣称新增对应 LRPS2 场景验收。
源存档保持不变，使用隔离卡副本；未执行 PCSX2 人工验收。

## 测试和实施边界

宽度专项 21 项、对白词语布局 10 项、SP STAGE 写入 17 项通过。
新增覆盖数值表达式、全角输入、正文标点边界、百分号生产编码冲突、除号可读性保护。

候选数量仍不是批量写入验收：长武器名的固定栏目覆盖问题延续首轮未通过项，
名称还需校验源槽容量、全部引用和缓存消费者。固定数值不能替代动态模板最大宽度测试。
